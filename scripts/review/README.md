# Reviewer evidence contract

Citation contract: use repository-relative path:N[-M][,N[-M]...] or path#LN-LM, optionally as Markdown links. En-dash ranges are accepted. Absolute file:// links must be beneath the exact checkout or verified archive root. Tracked paths define filenames regardless of extension, including dotfiles and extensionless files. Exact repository-relative paths take precedence over basename lookup. Other bare basenames must be unique among active files and cannot implicitly select legacy/. Basename labels resolve through their exact link target; a separate parenthesized basename citation can precede or follow its adjacent full link. Their numeric starting lines must agree. A a named Markdown link (label `name`, target `path#LN-LM`) link asserts that the final name component occurs inside those lines and namespace components occur in that file. Every citation must resolve; invented citations make the output invalid. Backticked dotted, underscore or camelCase identifiers must resolve component by component in the reviewed tree, removed side of the reviewed diff, or the pinned external-name list. Identifier authority excludes legacy/, ISSUES.tsv, scripts/review/fixtures/, scripts/review/test_*.py the external-name registry itself, and review-export helpers REVIEW.diff, DELTA.diff, PROMPT.md, RANGE.txt and _review/. Identifier authority comes only from the reviewed SHA, never helper exports or untracked working files. Report a missing identifier with a standalone ABSENT: name line. For proposed fixes in FINDINGS/REJECT use `proposed:newName`. Plain words and hash ranges are not identifiers. Positive CLEAN/clean/ACCEPT requires READ: paths actually read and at least one resolving file:line citation supporting the conclusion. ALWAYS do the best long term thing rather than cutting corners. A bare `proposed:` is grammar documentation, not a proposal; any nonempty proposed suffix remains forbidden for positive verdicts. To cite a name only as quoted text, use a named Markdown link (label `text:name`, target `path#LN-LM`); the exact name must occur within that range. Every text label occurrence requires its own resolving line target; bare `text:` fails closed. Text links never establish identifier authority or support a positive verdict. Bare names still claim tree authority even near fixture citations. Declared harness files may be READ but are never evidence. Links outside the reviewed roots are invalid.

Identifier lexicon: ASCII initial letter or underscore, then Unicode word characters, optional Lean !/?/apostrophe suffix; dotted sequences of these components. Only tokens with a dot, underscore, or lowercase-to-uppercase transition are identifier citations. Code containing spaces, plain words, filenames and commit ranges are outside that lexicon. `ABSENT:` resolves the reported name, not other names. All unresolved citations are listed in the invalid reason. Invalid is not a verdict; unknown statuses fail closed. READ directives retain their separate repository-access checks.

External names require a reviewed external-names.tsv entry with the exact lean-toolchain pin and upstream provenance. Host installations never authorize names.

Fixture provenance is in fixtures/iss0040/provenance.json. Source archives contain original git blobs from those commits, not reconstructed snippets. Raw reviewer outputs retain original trailers and are tested directly at the citation layer; final-message framing is tested separately.

N2 law-to-witness pairing is a distinct semantic obligation: the generic citation contract checks existence and anchors, not that a cited witness proves a law. A future opt-in N2 contract must specify law, Instance and Planted fields in the same location grammar and check exact source tags. The owning workstream is N2 (law classification and closed Instance/Planted evidence); [R-0691](../../ROADMAP.md) owns the structured schema, exact source-tag validation, law-to-witness pairing and planted missing/mismatched-witness controls. It cannot be inferred safely from arbitrary prose tables.

Validation ordering: known repository failures, timeouts and process errors take precedence. After a recognized verdict (case insensitive, returned in the caller’s canonical spelling), citation invalidity is reported before final-message framing errors. This makes a raw uncited CLEAN invalid even when it also omits READ/REPOSITORY directives. Valid citation evidence still cannot compensate for missing directives. Sign-off collection accepts --base (default origin/main); verification uses the sign-off check’s merge base.

Python repository fixtures use scripts/checks/lib/git_sandbox.py, which obtains the environment from the canonical git_sandbox.sh helper before repository creation and citation lookups. This clears hook-local repository variables and isolates caller configuration, hooks and signing. The structural sandbox scan covers Python makers as well as shell makers. In a linked-worktree hook, the original citation fixture committed repeatedly into the caller: the failing commit reported “nothing to commit, working tree clean” rather than recording the requested original blobs.

Review pieces are split from a commit-to-commit git diff. Readiness fixtures copy tracked tooling paths only, so ignored Python caches cannot become tracked fixture inputs; planted untracked and ignored files must stay out of reviewer prompts. The stand-in reviewer reads a file in its supplied piece and cites its first line; an uncited positive verdict must block readiness with the shared contract diagnostic.

Identifier authority excludes the declared IDENTIFIER_EXCLUSIONS in output_contract.py: frozen legacy/, ISSUES.tsv, archived review fixtures, contract test_*.py files, the external-name registry itself and coordinator export helpers (REVIEW.diff, DELTA.diff, PROMPT.md, RANGE.txt and _review/). Tracked excluded files remain explicitly citable locations; declared harness files are READ-only context and never evidence. Removed-side identifiers use the same exclusions. This prevents committed fabricated evidence from authorizing itself.

Exact tracked paths, including root files, take precedence over basename lookup. Other bare basenames must be unique among active files; frozen legacy/ copies do not shadow active paths. A basename link label resolves through its target; a separate parenthesized basename citation can immediately precede or follow its full link. Starting lines must agree, including en-dash and comma ranges. Filenames come from the tracked tree, with no extension allowlist. Extensionless prose such as UTC-5:30 is ignored unless the tree names that file; explicit Markdown location targets are always checked.

Absolute file:// locations must be beneath the exact checkout root or the caller-supplied --review-root of the verified archive. The collector supplies that archive root after verifying its manifest. No suffix guessing or basename fallback is allowed. Historical evidence tests supply their recorded archive roots explicitly.

Dotted named anchors check the final declaration component inside the selected lines and every namespace component in the cited file. This supports Lean namespace blocks without requiring a fully qualified spelling at the declaration. Wrong ranges and missing namespace components remain invalid.

Harness ownership: collect_output.sh:prepare_review_context creates the supplied PROMPT.md,
REVIEW.diff (the full base-to-head diff), DELTA.diff (the supplied piece), and RANGE.txt.
It writes an explicit sidecar declaration beside the integrity manifest. Validation passes
only those declarations through repeatable --harness-file arguments. No root scan or checker
filename allowlist grants READ access. Tracked-path collisions stop archive construction.
Harness citations report “harness file 'PATH' is not evidence”; outside-root URLs report
“link 'URL' is outside the reviewed roots”. Archive integrity still covers every helper.

Text mentions and definitions are deliberately different claims. A text:name named link
checks only literal occurrence in the selected lines; it cannot excuse another bare name,
export a name to another paragraph, or supply the positive verdict's supporting citation.
This avoids inferring intent from prose or letting a fixture bootstrap definition authority.
I5a's bare LLVM names therefore remain invalid; the reviewer must label these as text links.
A valid citation establishes existence, not the substantive truth of a review conclusion.
All fixtures preserve reviewer bytes: tests never repair, reorder, or normalize final messages.
Harness process trailers are retained in raw logs and separated only into independently hashed
final-message artifacts by removing exactly the recorded final harness line.
