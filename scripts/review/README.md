# Reviewer evidence contract

Citation contract: use repository-relative path:N[-M][,N[-M]...] or path#LN-LM, optionally as Markdown links. En-dash ranges are accepted. Absolute file:// links are normalized to an exact repository path. Basename labels require a unique file or an immediately following full link to the same starting line. A ``[`name`](path#LA-LB)`` link asserts that name occurs inside those lines. Every citation must resolve; invented citations make the output invalid. Backticked dotted, underscore or camelCase identifiers must resolve component by component in the reviewed tree, removed side of the reviewed diff, or the pinned external-name list. Report a missing identifier with a standalone ABSENT: name line. For proposed fixes in FINDINGS/REJECT use `proposed:newName`. Plain words and hash ranges are not identifiers. Positive CLEAN/clean/ACCEPT requires READ: paths actually read and at least one resolving file:line citation supporting the conclusion. ALWAYS do the best long term thing rather than cutting corners.

Identifier lexicon: ASCII initial letter or underscore, then Unicode word characters, optional Lean !/?/apostrophe suffix; dotted sequences of these components. Only tokens with a dot, underscore, or lowercase-to-uppercase transition are identifier citations. Code containing spaces, plain words, filenames and commit ranges are outside that lexicon. `ABSENT:` resolves the reported name, not other names. All unresolved citations are listed in the invalid reason. Invalid is not a verdict; unknown statuses fail closed. READ directives retain their separate repository-access checks.

External names require a reviewed external-names.tsv entry with the exact lean-toolchain pin and upstream provenance. Host installations never authorize names.

Fixture provenance is in fixtures/iss0040/provenance.json. Source archives contain original git blobs from those commits, not reconstructed snippets. Raw reviewer outputs retain original trailers and are tested directly at the citation layer; final-message framing is tested separately.

N2 law-to-witness pairing is a distinct semantic obligation: the generic citation contract checks existence and anchors, not that a cited witness proves a law. A future opt-in N2 contract must specify law, Instance and Planted fields in the same location grammar and check exact source tags. The owning workstream is N2 (law classification and closed Instance/Planted evidence); [R-0691](../../ROADMAP.md) owns the structured schema, exact source-tag validation, law-to-witness pairing and planted missing/mismatched-witness controls. It cannot be inferred safely from arbitrary prose tables.

Validation ordering: known repository failures, timeouts and process errors take precedence. After a recognized verdict (case insensitive, returned in the caller’s canonical spelling), citation invalidity is reported before final-message framing errors. This makes a raw uncited CLEAN invalid even when it also omits READ/REPOSITORY directives. Valid citation evidence still cannot compensate for missing directives. Sign-off collection accepts --base (default origin/main); verification uses the sign-off check’s merge base.

Python repository fixtures use scripts/checks/lib/git_sandbox.py, which obtains the environment from the canonical git_sandbox.sh helper before repository creation and citation lookups. This clears hook-local repository variables and isolates caller configuration, hooks and signing. The structural sandbox scan covers Python makers as well as shell makers. In a linked-worktree hook, the original citation fixture committed repeatedly into the caller: the failing commit reported “nothing to commit, working tree clean” rather than recording the requested original blobs.

Review pieces are split from a commit-to-commit git diff. Readiness fixtures copy tracked tooling paths only, so ignored Python caches cannot become tracked fixture inputs; planted untracked and ignored files must stay out of reviewer prompts. The stand-in reviewer reads a file in its supplied piece and cites its first line; an uncited positive verdict must block readiness with the shared contract diagnostic.

Identifier authority excludes the declared IDENTIFIER_EXCLUSIONS in output_contract.py: frozen legacy/, ISSUES.tsv, archived review fixtures, contract test_*.py files and the external-name registry itself. These remain explicitly citable locations. Removed-side identifiers use the same exclusions. This prevents committed fabricated evidence from authorizing itself.
