`--source PATH` audits a read-only checkout by elaborating a private source copy.
No existing build products are trusted. Every anonymous example is retained by
`lean_lex.py examples`, the same rewrite as the trust gate. The consumer is appended
to **theorems.lean**, whose `populationConstants` defines the single population for
N2 and the existing axiom inventory. Generated declarations are excluded from N2
by declaration selection ranges and Lean projection/matcher/equation provenance, never by
suffix. The axiom inventory still includes generated declarations. The shared rewrite
reserves `⟪example⟫` in authored identifiers before generating retained names;
strings and comments may still contain it. This authenticates the generated-example
provenance used by all consumers: a hand-written proof cannot opt out of
classification by spelling a synthetic example name. `example-provenance` is a FAIL,
not an analysis timeout or a skipped declaration.

Controls compile the generic checker and shared population functions once in a
fresh private directory, without importing any specification. Each fixture still
elaborates its own private source and audits its own imported population, and runs
the shared row-safety preflight. There is no persistent cache or reused source verdict.
This keeps the complete exact-diagnostic controls in the PR job without reducing
coverage or moving required checks out of the PR tier.

The gate returns 0 for PASS, 1 for FAIL, and 2 for INCOMPLETE. Source elaboration,
unreadable source provenance, analysis exceptions, exhausted unfolding/heartbeat budgets,
and command timeouts cannot pass. Each finding includes its diagnostic category
and fully qualified declaration name. Reports list Helpers, Representation lemmas,
Obligations, exemptions and manual audits. Recognized direct projections and
reflexivity cannot be exempted. Manual audit annotations waive no checks.

Instance proofs must be closed full applications of their named law, including
all implicit and proof arguments. An independent proof of the same conclusion
is not an Instance. References are resolved once and pairing compares declaration
identities, so relative and quoted references cannot drift from the qualified
spelling. Cases are pairing labels, not declaration references. All other backticked
names resolve against the environment. Planted propositions
are generated by substituting the named definition in the law statement **before**
instantiating with the Instance argument vector, then conjoining its hypothesis
types with the negated conclusion. This preserves the exact arguments even if
an argument itself mentions a subject. Subject dependencies hidden behind defined
contract aliases are traversed with a bounded dependency search.

Instance and Planted comparisons expand only definitions depending on protected
subjects while preserving all named subjects/mutants simultaneously, then replace
each subject/mutant constant at its actual universe levels
with a fresh local variable. Definitional equality can normalize surrounding
contracts but cannot erase operation arguments or replace a mutant by its result.
The shared `protectedEq` comparison disables smart unfolding only inside the
protected conversion: ordinary definitional unfolding compares contract definitions
even when protected discriminants prevent computation. This applies uniformly to
Instance and Planted comparisons, including generated polymorphic/specialized
matchers; it grants no declaration exemption. See
[N2 inline-match diagnosis and reproducer](N2-inline-match.md).
Mutants must also be definitionally different from their subjects, independently
of their distinct names. Negation and inequality conclusions are accepted.
A wrapper matching on the opaque operation result remains a contract conclusion;
a universal exposed independently of that result still requires closed arguments.

Resolution preserves explicit root qualification, searches ancestor namespaces in
order, and recovers command-level opens with
Lean’s source parser (including scoped boundaries, hiding and aliases), and keeps imported private names
outside their declaring module. Ordinary Accepted/Refused examples carry no N2
obligation and are not scanned unless they also have an N2 annotation. Backticks
in annotated declaration prose still name declarations, so locals and expressions
fail. Evidence headers reject duplicate, unparsed and unterminated fields;
Obligation headers validate slice and roadmap-row syntax. Every selected module
must contribute authored classified content, including Obligation-only modules.
Unscoped audits reject source modules outside the import closure. Missing source
provenance is INCOMPLETE; matcher/equation metadata and source-parent ranges identify
generated children without suffix exclusions. Authored declarations carrying proof bodies, including `def` and `opaque` proofs,
must be classified as well as theorems. Axioms and data constructors are handled
by their own kinds and do not acquire proof-body classifications.

Approval references must be nonempty and resolved (`PENDING` fails). The final
carrier is `(approved: review reference)`; it does not require extra identity tags.
A literal self-approval fails. If source additionally records `(writer: identity)`
and `(reviewer: identity)`, both must be present and their normalized identities
must differ. The independent reviewer verifies the reference against the actual
review of record: the gate cannot authenticate people or establish that an external
reference is truthful. Reviewers must do the best long-term thing rather than cut
corners. No exemption may suppress a recognized projection, an Instance check or
a Planted check.

### N2 A3 fix round 1: state ownership and wall recovery

Planning runs in a private `AuditState`, with journaling disabled, and restores
Lean Meta state on success as well as error. Evidence
parsers also have private findings and resolution caches. Each admitted analysis
owns fresh findings and resolutions, computes its terminal verdict locally, then
merges diagnostics into the global deduplicated report. Terminal analysis records
are never deduplicated: identical findings and identities still represent distinct
jobs. Mutable cross-job evidence/provenance references are scheduler-owned data;
resolution caches and emitted findings are not shared across analyses.

`workConstants` memoizes every expression constructor after evaluating its
children. `mentionsVisit` uses a query-local visited declaration set and delegates
expression traversal to that cache; `mentions` and `mutate` insert their results
outside their early-return helpers. `moduleDepends` caches completed module walks;
its equality/missing-module exits are constant-time leaves, not recursive walks.
The `resolve` and `direct` memo wrappers also insert after returning from their
uncached/step helper; no compound-match early return bypasses those inserts.
`withProtected` now visits each shared expression once while collecting terms and
memoizes replacement by expression, protected term, and replacement value.
The depth-15 shared application DAG control has a bound of 63 work units and
requires the root cache entry. The early-exit mutation must report exactly
`dag-root-not-cached` at depth 10 and `work-budget` at depth 15.

The audit writes a private append-only JSON-string journal. BEGIN separates attempts without truncating earlier progress. A READY record
commits the complete ordered population before admission; JOB and START record
selection and actual admission. Findings are flushed when
emitted; END commits each terminal result. Planning and global report merging do
not journal findings a second time. The bounded runner's private outcome file,
not exit status or printed text, identifies watchdog expiry. After both attempts
expire, the driver reconciles complete journal records across both attempts by frozen
job index. A completed result wins over a later interrupted retry; ended
INCOMPLETE results win over unfinished attempts, and every emitted FAIL survives.
A partial final JSON record is ignored. It keeps
completed results and FAILs already emitted by an interrupted analysis, then emits
one named terminal INCOMPLETE for every unfinished job: `reason=wall-watchdog`
for a started job, `reason=wall-watchdog-unrun` for the remainder. Interrupted
usage is `unavailable`, never claimed as zero. Unrun usage is zero. The recovery
summary preserves `reported=N`, `attempted+unrun=N`, and
`completed+incomplete=N`. It explicitly marks aggregate usage unavailable. A
watchdog before READY remains an enumerator INCOMPLETE because no complete
population has yet been established; it cannot claim population accounting.

Budget interpretation remains **assumed, pending owner**: per-analysis budgets
are independent; option B (one shared budget) remains the alternative. Wall-time
policy is also pending owner: retain the existing process watchdog and account
