# Proof audits

N2 is the mechanized vacuity audit owned by ROADMAP **R-0219** (proof status,
non-vacuity and evidence mutation). The owner-approved final convention is the
contract for `vacuity.{lean,sh}`. Meta code lives here; ConcreteSpec remains Init-only.

Current review disposition and exact-commit validation: [N2 round 2](N2-round2.md).

Run under `nix develop`:

```
bash scripts/proofs/vacuity.sh --controls
bash scripts/proofs/vacuity.sh --scope ConcreteSpec.Spec.Frame --scope ConcreteSpec.Proofs.Frame
bash scripts/proofs/vacuity.sh
```

`--source PATH` audits a read-only checkout by elaborating a private source copy.
No existing build products are trusted. Every anonymous example is retained by
`lean_lex.py examples`, the same rewrite as the trust gate. The consumer is appended
to **theorems.lean**, whose `populationConstants` defines the single population for
N2 and the existing axiom inventory. Generated declarations are excluded from N2
by declaration selection ranges and Lean projection/matcher/equation provenance, never by
suffix. The axiom inventory still includes generated declarations. The shared rewrite
reserves `⟪example⟫` in authored identifiers before generating retained names;
strings and comments may still contain it. This authenticates the generated-example
provenance used by all consumers: a hand-written proof cannot opt out of
classification by spelling a synthetic example name. `example-provenance` is a FAIL,
not an analysis timeout or a skipped declaration.

Controls compile the generic checker and shared population functions once in a
fresh private directory, without importing any specification. Each fixture still
elaborates its own private source and audits its own imported population, and runs
the shared row-safety preflight. There is no persistent cache or reused source verdict.
This keeps the complete exact-diagnostic controls in the PR job without reducing
coverage or moving required checks out of the PR tier.

The gate returns 0 for PASS, 1 for FAIL, and 2 for INCOMPLETE. Source elaboration,
unreadable source provenance, analysis exceptions, exhausted unfolding/heartbeat budgets,
and command timeouts cannot pass. Each finding includes its diagnostic category
and fully qualified declaration name. Reports list Helpers, Representation lemmas,
Obligations, exemptions and manual audits. Recognized direct projections and
reflexivity cannot be exempted. Manual audit annotations waive no checks.

Instance proofs must be closed full applications of their named law, including
all implicit and proof arguments. An independent proof of the same conclusion
is not an Instance. References are resolved once and pairing compares declaration
identities, so relative and quoted references cannot drift from the qualified
spelling. Cases are pairing labels, not declaration references. All other backticked
names resolve against the environment. Planted propositions
are generated by substituting the named definition in the law statement **before**
instantiating with the Instance argument vector, then conjoining its hypothesis
types with the negated conclusion. This preserves the exact arguments even if
an argument itself mentions a subject. Subject dependencies hidden behind defined
contract aliases are traversed with a bounded dependency search.

Instance and Planted comparisons expand only definitions depending on protected
subjects while preserving all named subjects/mutants simultaneously, then replace
each subject/mutant constant at its actual universe levels
with a fresh local variable. Definitional equality can normalize surrounding
contracts but cannot erase operation arguments or replace a mutant by its result.
Mutants must also be definitionally different from their subjects, independently
of their distinct names. Negation and inequality conclusions are accepted.
A wrapper matching on the opaque operation result remains a contract conclusion;
a universal exposed independently of that result still requires closed arguments.

Resolution preserves explicit root qualification, searches ancestor namespaces in
order, and recovers command-level opens with
Lean’s source parser (including scoped boundaries, hiding and aliases), and keeps imported private names
outside their declaring module. Ordinary Accepted/Refused examples carry no N2
obligation and are not scanned unless they also have an N2 annotation. Backticks
in annotated declaration prose still name declarations, so locals and expressions
fail. Evidence headers reject duplicate, unparsed and unterminated fields;
Obligation headers validate slice and roadmap-row syntax. Every selected module
must contribute authored classified content, including Obligation-only modules.
Unscoped audits reject source modules outside the import closure. Missing source
provenance is INCOMPLETE; matcher/equation metadata and source-parent ranges identify
generated children without suffix exclusions. Authored declarations carrying proof bodies, including `def` and `opaque` proofs,
must be classified as well as theorems. Axioms and data constructors are handled
by their own kinds and do not acquire proof-body classifications.

Approval references must be nonempty and resolved (`PENDING` fails). The final
carrier is `(approved: review reference)`; it does not require extra identity tags.
A literal self-approval fails. If source additionally records `(writer: identity)`
and `(reviewer: identity)`, both must be present and their normalized identities
must differ. The independent reviewer verifies the reference against the actual
review of record: the gate cannot authenticate people or establish that an external
reference is truthful. Reviewers must do the best long-term thing rather than cut
corners. No exemption may suppress a recognized projection, an Instance check or
a Planted check.

The v1 recognizer checks returned hypotheses, Expr.proj, registered projection
functions (including And.left/right), single-constructor recursor projections,
constructor repackaging (including empty proof constructors), and reflexivity.
It also compares the conclusion semantically against hypotheses and the two sides
of equality/iff conclusions, catching unfolded-premise and wrapped-rfl identities.
Raw delta reduction spends a shared proof-traversal counter for each distinct
elaborated expression, including each definition unfolded; it does not ask whnfR
to unfold an arbitrary definition chain in one step. Completed results are cached
by expression (including local-variable identities), per law, so substituted let
bindings and repeated constructor fields reuse complete answers. All constructor
proof fields are inspected; none is sampled or omitted. Production audits declare
a 4,096 distinct-expression bound per law and report `NOTE projection-cost` with
the actual visits and limit. Explicit low-budget controls still run at 3 and 64;
exhaustion is INCOMPLETE and cannot become PASS through the cache. Process and
heartbeat bounds also remain enforced. The C2 historical law combines typing,
evaluation, admission and lookup proofs, sharing the first two proofs in admission;
the former 64-visit tree walk charged repeated expanded subproofs again. The exact isolated C2 proof (`vacuity_fixtures.py --focused-c2`) took 81 visits
with the former tree walk and 49 with the DAG cache; thus memoization alone removes
its 64-visit exhaustion. That control requires complete nonprojection results at
both 64 and 4,096, without hardcoding a visit count. Server replay must still
confirm whole-module completion; isolated proof controls do not certify a head.
Hypothesis discharge scanning follows proof helpers transitively with a visited
set and a shared traversal budget; data/typeclass arguments are excluded.
Closed helper bodies are applied to the actual supplied arguments before reduction.
Open helper bodies also retain their actual supplied arguments; there is no
per-declaration cache that replaces supplied proofs by hypothetical binders.
The visited key includes the full local context, so a result obtained in an
unreachable context cannot suppress a check of the same term in a reachable one.
A hypothetical branch can be excluded by a checked refutation of its context,
including several assumptions jointly (contradiction and, at an elimination,
`simp_all` certificates). Failure to find a certificate grants no exemption.
An open derivation of `False` is followed through transparent helpers to its
suppliers, rather than treating its intermediate result as a supplied impossible
inhabitant. Local hypothetical contradictions are not actual suppliers; closed
impossible inhabitants and opaque supplied producers of impossible inhabitants
are rejected. This applies to data-dependent supplied impossibilities too.
There is no library trust list, proof-shape allowlist, or nesting cutoff. The
shared traversal budget remains 20,000 visits; resource exhaustion in traversal
or refutation search propagates as INCOMPLETE. The projection bound is unchanged.
The exact Init-only `fixtures/F3b-Repro.lean` is a positive control, including both
`by decide` cases and all its original passing proof forms. Joint hypothetical
binders are positive controls; actual jointly contradictory supplied proofs,
reachable helper branches and data-dependent supplied impossibilities are exact
`instance-false-discharge` negative controls. Under the Instance convention,
these negatives actually discharge a premise through `False.elim`; an unreachable
branch under unsupplied contradictory binders does not do so.
`vacuity_round5.py c1|c2 [--baseline]` probes only the three reported helper bodies
in freshly archived real sources (baseline 550fab85e or current checker); it does
not claim whole-module completion. R-0219 owns this semantic repair. Server replay
and the complete 17-scope c1/c2 audits remain required before promotion.

Analysis failures are isolated by declaration and evidence case. Each reports
`INCOMPLETE analysis-budget-or-error <fully-qualified-name> stage=... law=... case=...`
(for evidence); existing findings survive and later analysis units continue.
Runtime heartbeat exceptions are explicitly caught. Every unit retains the same
original command heartbeat deadline; after it expires, remaining units are named
INCOMPLETE rather than retried with a larger budget. Only scheduler/report
bookkeeping runs outside that deadline, still under the process wall bound.
`scripts/proofs/vacuity_reporting.py` exercises exact work-budget, runtime-heartbeat,
and ordinary-error diagnostics alongside an unrelated later law failure, names
a failed Planted analysis together with its paired Instance, and
checks the same complete-report validator used by `--replay`. The standard
`--controls` entry point includes these controls. A partial report is never clean
historical evidence, regardless of which FAIL lines it contains.
