# Example coverage manifest — single source of truth for CI example checking.
#
# Every .con file under examples/ MUST have exactly one build-outcome line here:
#   <path> <outcome> [fields]
#
# Outcomes (checked by scripts/tests/check_examples.sh):
#   compile        — must compile standalone: `concrete <file> -o <out>` exits 0.
#   compile-lib    — a module with no `main` (proof/VC teaching code, owned
#                    semantically by its gate): `concrete <file> --emit-llvm` must
#                    succeed and the IR must compile to an object (`clang -c`).
#   project-build  — file belongs to a project-form example; CI runs
#                    `concrete build` once in the nearest ancestor directory
#                    containing a Concrete.toml, which must exit 0.
#   project-lib    — a project that cannot be linked in CI (a native library is
#                    absent): `concrete build --emit-llvm` in its package root must
#                    succeed and the IR must compile to an object (`clang -c`).
#   expected-error — intentionally-failing diagnostics example; standalone
#                    compile MUST exit non-zero.
#   known-bug NNN <text>
#                  — a valid program an OPEN compiler bug blocks. The compile must
#                    fail with <text> in its output (alternatives separated by
#                    ` || `) and docs/bugs/NNN_*.md must read OPEN. Once the bug is
#                    fixed the compile succeeds and the gate fails until the entry
#                    is promoted.
#   skip owner=scripts/tests/<gate>.sh reason=<why>
#                  — not compiled here. The owner must exist, be invoked by an
#                    inline `run:` command of the CI workflow, and name the file
#                    (or its example directory) as a whole path token; the reason
#                    is required. A skip without a valid owner FAILS.
#
# Run rules (checked by scripts/tests/check_example_outputs.sh; see its header):
# every `compile` entry and every project root (`examples/<dir>/`, for the
# project-build entries) needs `@run` cases or one `@norun ... reason=...`.
#   @run <unit> <case> exit=<N> interp=<yes|fails:<marker>> [ret=<V>]
#        [stdin=<file>] [stdout=empty] [-- <args...>]
# Expected stdout lives in <example dir>/expected/<case>.stdout; fixtures (args,
# stdin) live under the example directory. In a fails: marker `~` stands for a
# space.
#
# Removed examples (and why):
#   examples/snippets/enum.con (2026-10-20) — obsolete: written in removed syntax
#     (`Foo.Bar` paths, `->` match arms) around explicit enum discriminants, which
#     the language rejects (E0001, a planned Phase 12 feature); enum_match.con
#     covers enums and match.
#
# When adding a new example, add it here with the outcome it must satisfy, and,
# if it is runnable, its @run rules and expected output.
