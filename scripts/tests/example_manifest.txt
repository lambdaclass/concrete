# Example coverage manifest — single source of truth for CI example checking.
#
# Every .con file under examples/ MUST have exactly one line here:
#   <path> <expected-outcome>
#
# Outcomes:
#   compile        — must compile standalone: `concrete <file> -o <out>` exits 0.
#   project-build  — file belongs to a project-form example; CI runs
#                    `concrete build` once in the nearest ancestor directory
#                    containing a Concrete.toml, which must exit 0.
#   expected-error — intentionally-failing diagnostics example; standalone
#                    compile MUST exit non-zero.
#   skip           — not checked by this gate. Either a pressure example that
#                    does not compile yet (see docs/project/EXAMPLE_LIFECYCLE.md), or a
#                    file exercised by a dedicated gate with special flags
#                    (proof_patterns, vc_discharge, vc_suite, smt/teaching,
#                    contract_stability, obligation_core_probe, stale snippets,
#                    two_kernel_demo and multi_kernel_policy — the last two need
#                    an EXTERNAL kernel (coqc/isabelle) that this gate's shell
#                    does not provide, so scripts/tests/check_multi_kernel.sh
#                    owns them and skips itself when the tools are absent).
#
# Checked by scripts/tests/check_examples.sh, which FAILS if a .con file under
# examples/ is missing from this manifest (or listed here but deleted on disk).
# When adding a new example, add it here with the outcome it must satisfy.
