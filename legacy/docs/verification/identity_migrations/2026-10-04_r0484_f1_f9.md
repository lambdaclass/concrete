# Identity migration — R-0484 F1/F9 std change (2026-10-04)

**Trigger.** Removing `process_fork`, `ForkResult` and `Child::new` from `std/src/process.con`
(R-0484 audit F1/F9). Every example's package identity is computed over its whole source set,
std included (`packageIdentityOf`, `Concrete/Proof/DefinitionIdentity.lean`), so the edit moved
the PACKAGE component of every scoped definition identity in the corpus.

**Symptom before migration.** `check_attestation_manifest` 55/1 (`GeneratedAttestations.lean`
168 lines stale) and `check_dependency_edges` 312/6 (verdicts 35/0 -> 32/3, correspondence
8/9 -> 3/9). Both reproduced on a clean rerun.

**What was verified before regenerating anything.** Regenerating `GeneratedAttestations.lean`
changed 39 references. For every one, the (module, declaration, implementation digest) triple
is unchanged and only the package digest differs; no other line in the file changed. The
proved bodies are byte-identical; only package scope moved.

**Rename procedure (content-keyed, not name-pattern).** Each old generated name was paired with
the new one carrying the same (module, declaration, implementation) triple and the same table
prefix. 41 of 42 old names paired uniquely. The resulting package-digest map is consistent
(no package maps to two targets):

| old package digest | new package digest |
|---|---|
| `0b4c54cf` | `e7882240` |
| `194e5755` | `d96e79da` |
| `44a81ba0` | `d2993ec4` |

**The one ambiguity.** `main.check_nonce` with implementation `0a3ca200…` exists in two programs
(`crypto_verify` and `proof_pressure`, see the RE-SELECTED note in `Concrete/Proof/Proof.lean`),
so content alone could not pair `cryptoFns_95c968e5_check_nonce` and
`cryptoFns_d6d04163_check_nonce`. Resolution: `95c968e5 -> 8ea7ad72` is fixed independently by
four other definitions unique to that package (`compute_tag`, `verify_message`, `verify_tag`,
and its own `check_nonce` pairing), leaving `d6d04163 -> aa9c5ba5` by elimination; the generator
emits both versions in the same order and `aa9c5ba5` occupies `d6d04163`'s position.

**Consumers migrated.** `Concrete/Proof/Proof.lean` (23), `proofs/Examples/HmacSha256/Proofs.lean`
(15), `scripts/tests/check_gate_mutation_coverage.sh` (18 anchor occurrences). Then
`refresh_classifications.sh`, `build_identity.sh`, rebuild.

**Result.** `check_attestation_manifest` 56/0, `check_dependency_edges` 317/0 with verdicts and
correspondence back to their baseline (35/0, 8/9), classification/build-identity/proof
freshness and migration manifest green. The return to baseline is the evidence the migration is
correct; the regenerated pins alone would not establish it.
