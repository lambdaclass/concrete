# Identity migration — R-0484 audit F6 std change (2026-10-06)

**Trigger.** Removing eight never-called foreign bindings from `std/src/libc.con` (audit finding
F6: `puts`, `fdopen`, `raise`, `putchar`, `snprintf`, `strtol`, `htonl`, and libc's duplicate
`realloc`). Package identity is computed over a package's whole source set, std included, so the
edit moved the PACKAGE component of the scoped definition identity of every example that
depends on std.

**Symptom before migration.** `check_attestation_manifest` 55/1 (`GeneratedAttestations.lean`
168 lines stale).

**What was verified before accepting the regeneration.** `GeneratedAttestations.lean`: 84 lines
removed and 84 added, identical once every hex digest is masked — only package digests moved;
module, declaration and implementation digests are unchanged, so the attested bodies are
byte-identical. `ClassificationTable.lean`: 26 lines, also identical after masking.

**Rename procedure: by SOURCE PATH, not by name.** The package-digest map was read from the
attestation manifest (`scripts/gen/attestation_manifest.sh`) at `17e00efb` and after the change:
each manifest row names the source file its package came from, and every path has exactly one
digest on each side. The map is a bijection over the 21 packages; 7 moved:

| source | old package | new package |
|---|---|---|
| `examples/constant_time_tag/src/main.con` | `718e2bcc` | `2fb7672e` |
| `examples/crypto_verify/src/main.con` | `8ea7ad72` | `5dd693a1` |
| `examples/elf_header/src/main.con` | `e7882240` | `1c979907` |
| `examples/fixed_capacity/src/main.con` | `d2993ec4` | `496ec664` |
| `examples/hmac_sha256/src/main.con` | `d96e79da` | `ccd40964` |
| `examples/parse_validate/src/main.con` | `be672785` | `0ea61229` |
| `examples/proof_pressure/src/main.con` | `aa9c5ba5` | `8b058212` |

Each old generated name `<table>_<old8>_<decl>` was mapped to `<table>_<new8>_<decl>`; every
target was required to exist in the regenerated file and the map to be injective (42 names).

**A first attempt was wrong, and the gate caught it.** It keyed names with the package hash
masked. `crypto_verify` and `proof_pressure` both define `main.check_nonce` with the same
implementation (`0a3ca200…`), so masking collapsed them: both references in `cryptoFns` were
rewritten to one package. `check_dependency_edges` then failed with `cryptoFns` refused as a
`duplicateDefinition`, corpus verdicts 35/0 -> 33/2 and correspondence 8/9 -> 6/9. Redone by
source path as above; `check_attestation_refs_order` now asserts directly that the two
`check_nonce` references name the two distinct packages the manifest attributes to those two
sources.

**Consumers migrated.** `Concrete/Proof/Proof.lean` (23), `proofs/Examples/HmacSha256/Proofs.lean`
(15), `scripts/tests/check_gate_mutation_coverage.sh` (18 anchor occurrences). Then
`refresh_classifications.sh`, `build_identity.sh`, rebuild.

**Result.** `check_attestation_manifest` 56/0; `check_dependency_edges` verdicts and
correspondence back to baseline (35 proved / 0 unjustified, `cryptoFns` 5 scoped entries, 8/9),
with its two probe-manifest pins updated for the probe bodies that now state the admission
fields (assertion count and label set unchanged at 317).
