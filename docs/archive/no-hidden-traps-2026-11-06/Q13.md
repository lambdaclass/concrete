SPARK facts (AdaCore SPARK UG 5.2.10/5.2.11, docs.adacore.com/spark2014-docs/html/ug/en/source/subprogram_contracts.html):
- "By default, GNATprove verifies termination of all functions".
- Procedures: without `Always_Terminates`, GNATprove "does not attempt to verify termination and is
  only concerned with their partial correctness"; `Always_Terminates` requests it (optionally
  conditional); a package annotated `Always_Terminates` makes its procedures required to terminate.
- `Subprogram_Variant` for recursion: a check on every recursive call that the value progresses.
- `No_Return`: procedure never returns normally; compatible with `Always_Terminates`;
  example `Loop_Forever` uses `No_Return`, `Always_Terminates => False`.
So SPARK = termination verified by default for functions; opt-in per procedure or per package.

Options for Q13 (termination first, then the other facts):
(b) Facts always derived and reported; a written module/project policy may require them.
    A function with no evidence is reported "not established" with a reason, silently allowed.
(d) "No unknowns" at the function level: every function proven to terminate or explicitly marked
    as possibly non-terminating; unmarked + unproven refused. Risk: the marker propagates to every
    caller (a function calling a possibly non-terminating function is itself possibly
    non-terminating) = function colouring in signatures, which PHILOSOPHY refuses for async.
(d-site) Claude's refinement: "no unknowns" at the SOURCE of non-termination, not on signatures.
    Every loop and every recursive cycle either carries checked termination evidence (counted
    `for`; `#[variant(e)]` proved; a Lean termination theorem) or is explicitly marked at that
    loop / cycle as possibly unbounded (e.g. a server's accept loop). Indirect calls: every
    possible target covered, else the call site is marked. Foreign calls: the trusted extern
    declaration states termination (trusted fact) or the call is treated as marked.
    Each function's `terminates` fact is then DERIVED transitively and is never "unknown": it is
    "proved" or "may not terminate, because of <written marker at file:line> via <call path>".
    No signature annotation, no function category (OD116 stands: OD116 refused a `total fn`
    category that contracts may call). Plus (b): a module/project policy may require
    `terminates` (and the other facts), refusing any marked source reachable from it.
    Result: the owner always knows beforehand, for every function, whether it terminates, and if
    not, exactly which written construct is responsible. No silent unknown; no colouring.
Other facts:
- stack bound: depends on the final artifact and target; cannot be "no unknowns" at check time
  for every function (unbounded-measure recursion is legal when terminating). Proposed: derived +
  reported + policy (b) + launcher claim 1 (Q14).
- may-abort, allocates, blocks, calls foreign code: derived from written constructs and explicit
  capabilities (abort() written; Alloc/grants explicit; trusted/extern explicit), so they are
  always known by construction; reported + policy (b).
- recursion depth bound: as stack.
Spelling of the possibly-unbounded marker goes to the owner (owner reviews all syntax); e.g.
`#[unbounded]` before the loop / on a recursive function, `#[may_not_terminate]`, `#[forever]`.
