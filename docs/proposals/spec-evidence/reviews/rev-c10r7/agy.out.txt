### 2. Findings

1. **`ConcreteSpec/Spec/Frame.lean:487-500` & `ConcreteSpec/Proofs/Frame.lean:1207-1216` — [major] [REAL DEFECT] `Nat` subtraction truncation in `toyTrace` and `runToy` makes `ToyTraceSafe` lower-bound checks vacuous at `origin = 0` and masks stack/offset underflow**
   - **Problem**: `toyTrace` computes slot addresses as `st.stackPointer - offset` in `Nat` (`Spec/Frame.lean:491`), and `runToy` computes `.release bytes` as `st.stackPointer - bytes` in `Nat` (`Spec/Frame.lean:479`). `ToyTraceSafe origin bound samples` checks `origin ≤ sample.1` and `origin ≤ address ∧ address < sample.1` (`Spec/Frame.lean:499-500`).
     - `toyBody_stack_safe` quantifies over arbitrary `before : Machine Nat Nat`, which includes `before.stackPointer = 0` (`origin = 0`).
     - When `origin = 0`, `0 ≤ sample.1` and `0 ≤ address` are trivially true for every `Nat`! An instruction stream `[.reserve 8, .slot 100 99, .release 8]` starting at `stackPointer = 0` accesses `8 - 100 = 0` in `Nat`, which satisfies `0 ≤ 0 ∧ 0 < 8`, so `ToyTraceSafe 0 8` judges an out-of-frame underflow 92 slots below the frame **safe**. Likewise, `[.release 100]` at `stackPointer = 0` saturates to `0` and satisfies `ToyTraceSafe 0 8`.
     - Even for `origin > 0`, every underflowing offset `offset ≥ st.stackPointer` silently clamps to slot `0`, so `ToyTraceSafe` only catches underflow in `toyBase` because `toyBase.stackPointer` was chosen to be `1` instead of `0`.
   - **Concrete fix**: Do not compute addresses or releases via unchecked truncating `Nat` subtraction. Either:
     1. Record the raw instruction offset/release or check the guard `offset ≤ st.stackPointer` (and `0 < offset ∧ offset ≤ st.stackPointer - origin`) in `toyTrace` / `ToyTraceSafe` (or return `Option (Int × Option Int)` / fail on `offset > st.stackPointer` or `bytes > st.stackPointer`), and
     2. Add a planted below-frame underflow mutant (e.g., `.slot 9 99` after `.reserve 8`, and `.slot 100 99` at `stackPointer = 0`) that is rejected for **all** `origin : Nat`, including `origin = 0`.

2. **`ConcreteSpec/Spec/Frame.lean:519-540` & `ConcreteSpec/Proofs/Frame.lean:1185-1193, 1224-1231, 1391-1396` — [major] [REAL DEFECT] Containment patch: `ToyTraceSafe` is bolted onto `toyCall_conforms` outside `Signature.Call` / `TransitionConforms`, and omitted from `toyCallSeq_conforms`**
   - **Problem**:
     - `Signature` carries `stackBound`, yet `Signature.Call` and `TransitionConforms` still only relate pre/post `Machine` states and never enforce `stackBound` or active-frame access safety. As a result, `(outsideToyCall toyBase 11 7).machine` and `(overBudgetToyCall toyBase 11 7).machine` still satisfy `toySignature.Call`!
     - Instead of strengthening `Signature.Call` / `TransitionConforms`, the diff bolts `ToyTraceSafe` onto `toyCall_conforms` as an external third conjunct.
     - Worse, `toyCallSeq` (`Spec/Frame.lean:538-539`) immediately discards `.samples` from the first call (`(toyCall base arg result₁).machine`) and runs the second call via `runToy`, so `toyCallSeq_conforms` (`Proofs/Frame.lean:1391-1396`) checks neither peak stack bounds nor active-frame spill safety across sequential calls.
   - **Concrete fix**: Integrate operational trace/stack-bound safety into the call contract (`Signature.Call` / `TransitionConforms`, or make `Machine` / `Call` carry the execution trace) and have `toyCallSeq` (via trace concatenation in `executeToy (toyBody result₁ ++ toyBodyAt 2 result₂)`) and `toyCallSeq_conforms` enforce `ToyTraceSafe` across the full sequential execution.

3. **`ConcreteSpec/Proofs/Frame.lean:1195-1216, 1269-1282` — [major] [REAL DEFECT] `toyBody_stack_model` is a hardcoded constant comparison with no structural translation between `ToyInstruction` and `StackCode`, and its `Instance` violates `_review/VACUITY_CONVENTION_FINAL.md`**
   - **Problem**:
     - **Hardcoded shortcut**: `toyBody_stack_model` relates `toyTrace (toyBodyAt resultReg result) before` to `stackSamples (.frame 8 .done) before.stackPointer`. Neither side is derived from the other: there is no function compiling `StackCode` to `List ToyInstruction` or extracting `StackCode` from `List ToyInstruction`. Both are fixed constants, and `toyBody_stack_safe` (`Proofs/Frame.lean:1210-1216`) still unfolds `toyTrace, toyBodyAt, runToy` and performs the same 8-way `rcases hs` + `omega` that proves the bound directly without `stackSamples_bounded`.
     - **Convention violation on `Instance`**: Because `toyBody_stack_model` takes `(sample : Nat × Option Nat)` and `(hs : sample ∈ toyTrace ...)` as parameters and its `Instance` (`Proofs/Frame.lean:1269-1272`) discharges `hs` inside the proof term via `(by decide)`, the `Instance` proposition is `((9, some 1) : Nat × Option Nat).1 ∈ stackSamples (.frame 8 .done) (toyInput toyBase 11).stackPointer`—which does not mention `toyTrace` or `toyBodyAt` at all.
   - **Concrete fix**: Define a structural translation between `StackCode` and `List ToyInstruction` (e.g., `StackCode.compile : StackCode → List ToyInstruction` or `extractStackCode : List ToyInstruction → Option StackCode`), prove a general law `∀ code before sample, sample ∈ toyTrace (code.compile ...) before → sample.1 ∈ stackSamples code before.stackPointer`, derive the `sample.1 ≤ before.stackPointer + toySignature.stackBound` bound in `toyBody_stack_safe` from `stackSamples_bounded` without redoing 8-way `rcases` on `hs` for the depth bound, and state the law so its closed `Instance` retains `toyTrace` in the theorem statement (e.g., `∀ sample ∈ toyTrace ..., sample.1 ∈ stackSamples ...`).

4. **`ConcreteSpec/Spec/Frame.lean:862-870` — [minor] [PREFERENCE] `ToyLaunchCorrect` binds `root` and `requestedResult` outside `Launcher.Run` / `LauncherConforms`**
   - **Problem**: `ToyLaunchCorrect` adds `artifact.1 = root ∧ result = requestedResult` on top of `toyLauncher.Run`, whereas `Launcher.Run` and `LauncherConforms` themselves still take an arbitrary `artifact` and `result` without tying them to the requested root module or entry evaluation result.
   - **Concrete fix**: Fold the root-identity and startup-outcome relation (`Startup`) into `Launcher` / `LauncherConforms` so the reusable launcher contract, not just `ToyLaunchCorrect`, binds the requested root and result across both `.refused125` and `.entered`.

5. **`ConcreteSpec/Spec/Frame.lean:193-213` — [nit] [PREFERENCE] `runEffect` duplicates `EffectCommand.permissions` expressions**
   - **Problem**: `runEffect` still computes its returned `Footprint` inline rather than referencing `command.permissions tgt before`.
   - **Concrete fix**: Either have `runEffect` use `command.permissions tgt before` when constructing `some (after, footprint)` or have `runEffect` return `Option State` while `EffectResult` checks `(command.permissions tgt before).Preserves before after`.
