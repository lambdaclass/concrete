### Findings

1. **`ConcreteSpec/Spec/Adequacy.lean:145-154` & `ConcreteSpec/Proofs/Adequacy.lean:241-246` — [major] [REAL DEFECT] `ReportedQueries` leaves the terminal query unconstrained and decouples `.stuck` cases from `Conclusion`**
   - **Problem:** In `ReportedQueries`, the constructors `stuckContinuation`, `noAnswer`, and `badAnswer` quantify over an arbitrary free `{q : Query O}` with no connection to `step P c` or `Conclusion`:
     ```lean
     | stuckContinuation {c events issued q} :
         ReportedQueries (.stuck c) ⟨c, events, issued⟩ (issued ++ [q])
     | noAnswer {c events issued q} :
         ReportedQueries (.noAnswer c) ⟨c, events, issued⟩ (issued ++ [q])
     | badAnswer {c events issued q} :
         ReportedQueries (.badAnswer c) ⟨c, events, issued⟩ (issued ++ [q])
     ```
     Because `runFromQ_sound` states `Conclusion P ρ ... pos ∧ ReportedQueries ... pos (runFromQ ...).queries` as separate conjuncts:
     1. For `noAnswer`, `badAnswer`, and `stuckContinuation`, `ReportedQueries` only asserts `∃ q, queries = pos.queries ++ [q]`—it does **not** assert that `q = Query.issue pos.events p vs site st pos.queries` for the request at `pos.config`.
     2. For `.stuck c`, both `ReportedQueries.stuck` (`queries = issued`) and `ReportedQueries.stuckContinuation` (`queries = issued ++ [q]`) match the same `Ending.stuck c`, independent of which `Conclusion` constructor (`stuck` vs `stuckContinuation`) held. A broken `runFromQ` that fabricated a dummy query on `step P c = none` would still satisfy `runFromQ_sound`.
   - **Concrete fix:** Fold the reported queries directly into `Conclusion` (or index `Conclusion P ρ : Ending O → Position O → List (Query O) → Prop`) so each ending constructor pins down the exact query list using the request's `Query.issue events p vs site st issued`:
     ```lean
     inductive Conclusion (P : Program O) (ρ : QueryOracle O) :
         Ending O → Position O → List (Query O) → Prop where
       | final {f pos} :
           pos.config.final? = some f →
           Conclusion P ρ (.final f) pos pos.queries
       | stuck {c events issued} :
           step P c = none →
           Conclusion P ρ (.stuck c) ⟨c, events, issued⟩ issued
       | stuckContinuation {c events issued p vs site st k a} :
           let q := Query.issue events p vs site st issued
           step P c = some (.request p vs site st k) →
           answer ρ q = some a →
           O.allows p vs st a = true →
           k a = none →
           Conclusion P ρ (.stuck c) ⟨c, events, issued⟩ (issued ++ [q])
       | noAnswer {c events issued p vs site st k} :
           let q := Query.issue events p vs site st issued
           step P c = some (.request p vs site st k) →
           answer ρ q = none →
           Conclusion P ρ (.noAnswer c) ⟨c, events, issued⟩ (issued ++ [q])
       | badAnswer {c events issued p vs site st k a} :
           let q := Query.issue events p vs site st issued
           step P c = some (.request p vs site st k) →
           answer ρ q = some a →
           O.allows p vs st a = false →
           Conclusion P ρ (.badAnswer c) ⟨c, events, issued⟩ (issued ++ [q])
       | outOfFuel {c events issued} :
           c.final? = none →
           Conclusion P ρ (.outOfFuel c) ⟨c, events, issued⟩ issued
     ```
     Then in `runFromQ_sound`, `Conclusion P ρ (runFromQ P ρ fuel events issued c).ending pos (runFromQ P ρ fuel events issued c).queries` replaces both `Conclusion` and `ReportedQueries` and uniquely determines the terminal query in every branch.

2. **`ConcreteSpec/Proofs/Adequacy.lean:369, 415, 715, 729, 743` — [minor] [PREFERENCE] Monotonicity, `complete_le`, and blocking/finite exclusion of `InfiniteExecution` are only stated for lifted C1 `Oracle`, not general `QueryOracle`**
   - **Problem:** `InfiniteExecution` is now defined over `ρ : QueryOracle O`, but `not_infinite_of_final`, `not_infinite_of_noAnswer`, `endlesslyBlocked_of_noAnswer`, `runFrom_mono`, and `runFrom_complete_le` only quantify over `ρ₀ : Oracle O` (via `ρ₀.toQueryOracle`). If an oracle actually depends on `q.occurrence`, these theorems cannot be applied directly to `runQ P ρ` / `runFromQ P ρ`.
   - **Concrete fix:** Prove `runFromQ_mono` and `runFromQ_complete_le` for general `ρ : QueryOracle O`, prove `not_infinite_of_finalQ` / `not_infinite_of_noAnswerQ` for `runQ P ρ`, and derive the `runFrom` / `run` versions via `runFromQ_toReport`.
