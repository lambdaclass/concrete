1. **ConcreteSpec/Spec/Frame.lean:823 — major — REAL DEFECT: launcher correctness loses the requested root and result.**

   `ToyLaunchCorrect` receives only `reserved`. In the successful branch, it checks the artifact and result supplied by the launcher itself. Consequently, the mutant

   ```lean
   fun root reserved result => toyLaunch (root + 1) reserved (result + 1)
   ```

   still satisfies this correctness predicate for every input. It launches the wrong root and returns the wrong result, while supplying internally consistent closure, entry and exit data. The existing exit mutant changes only the observation, so it misses this weakness.

   **Concrete fix:** parameterize `ToyLaunchCorrect` by the requested root and result. Require the returned artifact’s root and returned result to equal those inputs, alongside `Launcher.Run`. Add separate planted wrong-root and wrong-result executions.

2. **ConcreteSpec/Proofs/Frame.lean:1176 — major — REAL DEFECT: the advertised in-frame spilling property is absent from the ABI contract.**

   The revised instructions actually spill inside the reserved frame. However, `toyCall_conforms` proves only final-state `Signature.Call` properties. Those properties allow arbitrary writes at or above the caller’s initial stack pointer.

   Replacing the private `.slot 7 99` with `.slot 0 99` writes at `base.stackPointer + 8`, just outside the reserved interval, while preserving every property in the theorem. Likewise, a body can temporarily reserve substantially more than `toySignature.stackBound`, release it, and satisfy the same theorem.

   `stackSamples_bounded` concerns the separate `StackCode` language; there is no correspondence connecting its samples to `runToy`.

   **Concrete fix:** give toy instruction execution an operational trace of stack depths and accessed addresses. Prove that accesses stay within the active allocation and that peak depth respects the signature bound. Connect any `StackCode` abstraction to those actual executions. Plant both an out-of-frame spill and a temporary over-budget reservation. This toy-level connection can be proved now; native code generation is not required.

3. **ConcreteSpec/Spec/Frame.lean:208 — major — REAL DEFECT: an effect executor can authorize its own corruption by enlarging its returned footprint.**

   `EffectResult` checks preservation against the footprint returned by the operation under review. It never establishes that this footprint is the command’s permitted footprint.

   For the closed byte-store fixture, a mutant can perform the existing liveness corruption and add block `0` to the returned metadata permissions. The store remains defined and the enlarged footprint permits that corruption, so `EffectResult` accepts it. The existing `corruptEffect` mutant preserves the original footprint and therefore does not expose this weakness.

   **Concrete fix:** derive command permissions independently from the pre-state and command, with an independently specified allocation identity where necessary. Require the returned footprint to equal those permissions, or establish an appropriate inclusion restricting it to them. Add a mutant that corrupts metadata and enlarges its reported permissions.

4. **ConcreteSpec/Proofs/Frame.lean:1551, :1608, :1626 — minor — REAL DEFECT: three planted mutants do not have their subject’s type.**

   The final convention explicitly requires identical subject and mutant types, including implicit arguments.

   - `rejectingKeptChecker` omits `[DecidableEq F] [DecidableEq H]` present on `checkKeptPair`.
   - `untrackedKeptTransfer` and `droppingKeptTransfer` omit `[DecidableEq H]` present on `transferKept`.

   Their concrete examples express useful counterexamples, but these tags fail the stipulated substitution convention.

   **Concrete fix:** retain the subjects’ complete implicit and instance parameter lists on these mutant definitions, even when unused.
