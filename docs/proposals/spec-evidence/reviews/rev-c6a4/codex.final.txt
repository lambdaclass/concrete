**Findings**

1. **ConcreteSpec/Spec/Observe.lean:404; ConcreteSpec/Proofs/ObserveOutput.lean:122 — major — REAL DEFECT: a typeclass parameter does not fix physical semantics to the operands.**

   Changing `PhysicalEffects` from `structure` to `class` changes instance inference, not the theorem’s quantification. `[F : PhysicalEffects O S.Output]` remains an arbitrary argument. Callers can supply a local instance—or an explicit instance argument—with both `emit` and `past` returning `[]`.

   Against that instance, an output-erasing adapter satisfies `OutputCorrespondence`, and any oracle satisfies `OracleFaithful`. Both operational laws then succeed with no physical outputs. The assertion at lines 408–411 that the interpretation cannot be swapped is therefore false. `no_erasing_correspondence` only rejects erasure **after assuming a nonempty interpretation under the selected instance**; it does not close this escape.

   **Long-term fix:** make physical effects an authoritative component of the semantic operand/signature bundle used by execution and adapter admission. Adapter construction must not independently choose that interpretation. Prove the concrete primitive interpretation independently and test erasure while retaining that same bundle. Keep the list-accumulation result as a helper.

2. **ConcreteSpec/Spec/Observe.lean:223; ConcreteSpec/Proofs/ObserveReport.lean:368 — major — REAL DEFECT: the path repair relocates the invariant check instead of establishing independent path correctness.**

   `sourceSites` now tests `PathOk` and drops failing entries. `sourceSites_valid` proves validity by following that filter. Meanwhile, `runFrom_source_trap` still requires `pathOk : PathOk src.path`. Moving the proof from a structure field to a theorem argument does not remove the admission premise identified in round 3.

   The reported path identity, line and byte-column conjuncts are improvements. Nevertheless, the path-validity component still succeeds because the producer rechecks precisely that invariant, and the operational law excludes invalid source paths. The host-root mutant is rejected by runtime validation, so it does not independently establish correct path production.

   **Long-term fix:** establish project-relative path production from an independently specified source-file/project identity boundary, then prove that site construction and reporting preserve it. Treat filtering/lookup equations as helpers, not path-production evidence. Do not introduce an invalid-path disposition without resolving the QUESTION below.

3. **ConcreteSpec/Proofs/ObserveEnvironment.lean:652, 682 — minor — REAL DEFECT: the blocking Planted mutant has a different declaration type from its subject.**

   `Environment.oracle` is polymorphic in `S` and `Input`. `BlockingEnvDemo.fabricateReplyOnBlockOracle` accepts only `Environment Demo.signature Unit`. Their applications have compatible types in this fixture, but the mutant declaration does not have the subject declaration’s type, as FINAL N2 requires.

   **Fix:** define a polymorphic mutant with the exact `Environment.oracle` type. For example, it can fabricate a typed reply by invoking the supplied handler on another history; use a history-sensitive blocking fixture where the actual request blocks but that other invocation answers. Alternatively, introduce a named specialized subject and formulate the law and evidence consistently over it.

4. **ConcreteSpec/Proofs/Observe2.lean:439; _review/CARRY.md:3 — minor — REAL DEFECT: the carried byte-column theorem audit is not completed in this tree.**

   `byteColumn_ascii_eq_char_col`, `byteColumn_multibyte_gt_char_col`, and `sourcePrefixSpan_hasByteColumn`, which round 3 reports as present, resolve nowhere in `ConcreteSpec`. The current source laws provide useful UTF-8/tab and newline witnesses, but the claimed ASCII and multibyte theorem inventory cannot be audited or credited.

   **Fix:** reconcile the carry against the actual declarations. Supply substantive producer-level ASCII/multibyte laws with closed Instances and premise-preserving mutants where required. A definitional `HasByteColumn` equation belongs among computation helpers, not newly manufactured Law evidence.
