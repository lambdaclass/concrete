1. **[major] `ConcreteSpec/Spec/Exec.lean:87-89`, `96-124`, `178-181`, `301-304` — `Config` and `Operands` have no extensible state/store carrier, and `Stmt.assign` only mutates top-level `Var`s**
   - **Problem:** The module header (`ConcreteSpec/Spec/Exec.lean:14-16`) claims: *"The scalar operations (C2), memory (C4) and the environment (C6) are instances; they add operations, never change what the statements below mean (the freeze boundary: an extension preserves the old fragment's executions)."* However:
     1. `Config` (`Exec.lean:178-181`) consists solely of `ctrl`, `locals : AList Var O.Val`, and `frames`, and `Operands.eval : AList Var Val → Expr → Res Val` (`Exec.lean:87`) cannot read anything outside `locals`. Even if C4 threads memory effects through `O.Prim`, `step` on `.prim` (`Exec.lean:301-304`) leaves all state unchanged except binding `x` in `locals` (`(x, v) :: L`), and operand evaluation (`O.eval`) cannot read memory or sub-places at all.
     2. C1 explicitly states: *"Freeze: machine configurations with current command, locals, places, call frames and structured continuations...    - **Fix:** Parameterize `Operands` by a store/memory state `State : Type` (carried in `Config`), give `Operands` place/lvalue evaluation (`PlaceExpr`, `evalPlace : State → AList Var Val → PlaceExpr → Res Place`, `writePlace : State → Place → Val → Res State`), pass `State` to `O.eval` and `Out.request`, and prove the RHS-before-destination-place evaluation order law on `Stmt.assign`.

2. **[major] `ConcreteSpec/Spec/Exec.lean:282-283`, `295-300`, `356-366`, `383-392` — Deferred calls registered inside a function body are silently skipped when the function returns if the body is not wrapped in an explicit `Stmt.block`, and `Completes`/`unwind_runs_plan` cannot cross a `.ret` frame**
   - **Problem:** When `.call` enters `fn` (`Exec.lean:298-299`), it pushes `.scope fn.block (fn.params.map Prod.fst) [] :: .ret dst L :: k`.      1. In `Passes` (`Exec.lean:365`), `Passes e (.ret ..) = False`, so `unwind_runs_plan` (`Proofs/Exec.lean:177-205`) only proves unwinding *up to* `.ret`, never the full transition from `return e` in a callee back to `.done` in the caller.
