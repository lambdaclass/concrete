### Findings

1. **`ConcreteSpec/Spec/Observe.lean:190-200`, `ConcreteSpec/Spec/Observe.lean:329-340`, `ConcreteSpec/README.md:90-100` — [BLOCKER] [REAL DEFECT] Deferring final external state to R-0571 leaves C6 observations unsound.**
   - **Problem:** `Execution.finite`, `TerminalObservation`, `FullObservation`, `SameObservation`, and `reportObservation` still omit the final external state / store. Recording this omission in `README.md` under `R-0571` is a deferral shortcut. Under the current definitions, two finite runs with identical event histories and exit codes but different final externally visible memory/store states are judged `SameObservation`.
   - **Concrete Long-Term Fix:** Retain the final store `O.Store` in C1 terminal endings (`Exec.Final` / `Exec.Ending.final`), project the externally visible final state via `ExecAdapter`, include that projected final state in `Execution.finite`, `TerminalObservation`, and `SameObservation`, and prove that C1 terminal runs and stuttering transformations (`silent_internal_steps`, `delay_preserves_observation`, `full_observation_preservation`) preserve the final external state.

2. **`ConcreteSpec/Proofs/ObserveReport.lean:15-35` — [BLOCKER] [REAL DEFECT] `ReportTraceValid` defines `none => True`, allowing a trivial `none`-returning mutant to pass `runFrom_report_trace`.**
   - **Problem:** `ReportTraceValid C input none` is defined as `True`. Consequently, `runFrom_report_trace` switches off its obligation whenever `reportObservation` returns `none`. A broken implementation `def brokenReportObservation ... := none` satisfies `runFrom_report_trace` trivially on every run, and a `.final` or `.noAnswer` run whose adapter lookup fails (`A.terminal? f = none` or `A.request ... = none`) also satisfies `ReportTraceValid` by `True`.
   - **Concrete Long-Term Fix:** Strengthen `ReportTraceValid` (or parameterize it by the `Exec.Report O` / `Exec.Ending O`) so that `none` is only valid when the evaluator report is genuinely non-observational (`.outOfFuel`, `.stuck`, `.badAnswer`), whereas a well-formed `.final` or `.noAnswer` run must produce `some (.terminal ...)` or `some (.blocked ...)` with a valid trace.

3. **`ConcreteSpec/Proofs/ObserveOutput.lean:14-25`, `ConcreteSpec/Proofs/ObserveOutput.lean:108-117`, `ConcreteSpec/Spec/Observe.lean:305-328` — [MAJOR] [REAL DEFECT] `project_physical_outputs` assumes per-event correspondence as an ad-hoc premise discharged by `fun _ => rfl`.**
   - **Problem:** `ExecAdapter.OutputCorrespondence A physical` (`∀ event, publicOutputs (A.events event) = physical event`) is not part of `ExecAdapter.WellFormed` and is assumed directly as a hypothesis of `project_physical_outputs`. In both the `Instance` (`ObserveOutput.lean:110`) and `Planted` (`ObserveOutput.lean:117`), `physical` is chosen to be `fun n => [toString n]`, which is definitionally `publicOutputs (adapter.events n)`, so the premise `corresponds` is discharged by `fun _ => rfl`.
   - **Concrete Long-Term Fix:** Integrate physical output semantics into the operand/oracle contract and `ExecAdapter.WellFormed` (where the operand spec independently defines physical outputs vs. request/response events), and prove history-level physical output preservation from `WellFormed` on reachable `Exec.runFrom` histories without discharging the correspondence hypothesis by `rfl`.

4. **`ConcreteSpec/Proofs/ObserveEnvironment.lean:16-108` — [MAJOR] [REAL DEFECT] `doubling_reply_correct` and `RoutingDemo.reply_correct` are laws over toy arithmetic demo functions rather than C6 environment/oracle contracts.**

These theorems only verify toy definitions in demo namespaces; they do not test any general C6 contract mechanism in `ConcreteSpec.Spec.Observe`.
   - **Concrete Long-Term Fix:** Define a general C6 executable/decidable environment producer or typed oracle combinator in `ConcreteSpec.Spec.Observe` (constructing an `Exec.Oracle O` and `Responds` transitions from typed operation handlers) and prove as a general C6 `Law` that the constructed oracle produces `Responds`-compliant, properly routed answers and satisfies `ExecAdapter.WellFormed`.

5. **`ConcreteSpec/Proofs/ObserveOutput.lean:87-105`, `ConcreteSpec/Proofs/Observe2.lean:547-555` — [MAJOR] [REAL DEFECT] General `output_before_trap_kept` demoted to `Helper` while the `Law` (`OutputDemo.output_then_trap`) is restricted to a hardcoded demo.**

6. **`ConcreteSpec/Proofs/Observe2.lean:389-399` — [MAJOR] [REAL DEFECT] `trapLine_injective` is misclassified as `Helper (inversion) (approved: PENDING)` instead of a `Law`.**
