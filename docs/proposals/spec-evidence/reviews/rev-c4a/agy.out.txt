### Part A & Part B Audit Summary

1. **Item 20 (`decodePtr` / `encodePtr`)**:
   - `encodePtr` is now total (drops `_valid : p.Valid tgt`), encoding `(ordered tgt.byteOrder (leBytes tgt.ptrSize p.addr)).zipIdx.map (fun (v, i) => .init v (some (p, i)))`.
   - `decodePtr` does **not** compare against `encodePtr`; it independently verifies:
     1. Head byte carries fragment `(p, 0)`.
     2. `bs.length = tgt.ptrSize`.
     3. `octets bs = some os` (all bytes initialized).
     4. `bs = os.zipIdx.map (fun (v, i) => .init v (some (p, i)))` (every byte `i` in `0 ..< ptrSize` carries fragment `(p, i)` of that exact same pointer `p`).
     5. `leValue (ordered tgt.byteOrder os) = p.addr` (octets numerically decode to `p.addr`).
     6. `p.Valid tgt` (target validity).
   - All other byte patterns return `none`.
   - `decodePtr_encodePtr` and `decodePtr_some` prove the round-trip and converse by genuine numeric octet algebra (`octets_fragments`, `leBytes_leValue`, `leValue_leBytes`, `ordered_ordered`), not by `if bs = encodePtr ...` tautology.

2. **Re-check removal (`Memory.access`)**:
   - The redundant `p.Valid tgt` check in the non-empty branch of `Memory.access` is removed.
   - `access_valid` proves `p.Valid tgt` for non-empty accesses from `m.WellFormed tgt` (`hw.fits` and `hw.spaces`) and the block bounds (`x.base ≤ p.addr`, `p.addr + n ≤ x.base + x.size`, `n ≠ 0`, `x.base + x.size ≤ 2 ^ tgt.addrBits - 1`).
   - Together with `access_success` and `access_some_inv`, removing the re-check preserves the exact set of operations that succeed on well-formed states.

### Findings

1. **`ConcreteSpec/Proofs/Memory.lean:252` — `alloc_failure` omits four failure branches of `Memory.alloc` (minor, REAL DEFECT)**
   - **Problem**: `alloc_failure` was refactored from `¬ m.Fits tgt (candidate s base size align)` to an explicit disjunction of three geometric conditions (`base % align ≠ 0 ∨ 2 ^ tgt.addrBits - 1 < base + size ∨ ∃ e ∈ m.blocks, e.2.live = true ∧ e.2.Overlaps (candidate s base size align)`). While those three are now non-tautological relative to `Fits`, `Memory.Fits` has four additional failure clauses (`¬ IsPow2 align`, `target.maxObject < size`, `0 < size ∧ base = tgt.null`, `s ∉ tgt.spaces`) that are no longer covered by `alloc_failure`. A mutant allocator that drops the `IsPow2 align`, `maxObject`, `null`, or `s ∉ tgt.spaces` check still satisfies `alloc_failure`.
   - **Concrete fix**: Include all seven raw failure disjuncts in `alloc_failure` (written directly in terms of `align`, `base`, `size`, `s`, `tgt`, and `m.blocks` without mentioning `Fits`):
     ```lean
     theorem alloc_failure (tgt : Target) (m : Memory) (s : AddrSpace) (base size align : Nat)
         (h : ¬ IsPow2 align ∨ base % align ≠ 0 ∨ 2 ^ tgt.addrBits - 1 < base + size ∨
           tgt.maxObject < size ∨ (0 < size ∧ base = tgt.null) ∨
           (∃ e ∈ m.blocks, e.2.live = true ∧ e.2.Overlaps (candidate s base size align)) ∨
           s ∉ tgt.spaces) :
         m.alloc tgt s base size align = .error .unavailable
     ```
     and add corresponding `mutatedAlloc` cases in `Audit`.

2. **`ConcreteSpec/Proofs/Memory.lean:561` — `decodePtr_valid_inv` is a dead projection of `decodePtr_some` (nit, PREFERENCE)**
   - **Problem**: `decodePtr_valid_inv` is strictly `(decodePtr_some tgt bs p h).2` and is not used anywhere else in the diff.
   - **Concrete fix**: Either remove `decodePtr_valid_inv` or prove it as a one-line projection `(decodePtr_some tgt bs p h).2`.
