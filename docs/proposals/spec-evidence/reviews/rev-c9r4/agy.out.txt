### Overview of Round 4 Items (1–10)

- **Item 1 (Site-key table & renumbering)**: `SiteKeyTable.nodup_renumber` and `SiteKeyTable.lookup_renumber` are real laws over `SiteKeyTable.renumber`. However, `OutsideFunctionEdit.persistentKeys` is a projection law over a 1-field propositional structure (`OutsideFunctionEdit`) rather than a theorem over an operation that assigns keys per function.
- **Item 2 (Specialization canonicalization)**: `SpecializationTable.canonicalize` and its five laws (`canonicalize_nodup`, `canonicalize_edge_sound`, `canonicalize_complete`, `canonicalize_share`, `canonicalize_distinct`) are genuine operational laws.
- **Item 3 (Load check refusing collisions naming both)**: `LoadedModules.load`, `load_refusal_sound`, `load_refusal_complete`, and `load_admitted` operate on `List LoadedModule` and refuse both cross-package top-level collisions (OD44) and same-package/different-origin collisions.

- **Item 5 (Evidence discharge consuming context and obligation identity)**: `SafetyEvidence.discharge` checks context, obligation ID, table lookup, and proposition equality, **but** uses `classical` propositional equality `e.fact = obligation.fact` (`propext`), which collapses all true propositions into one and makes `discharge_proposition_mismatch`'s hypothesis unsatisfiable for any true obligation.
- **Item 6 (`trapLine` planted)**: `Observe2.lean` adds `trapLineWithoutColumn` and `spDifferentColumn` as a planted counter-example for `trapLine_injective`.
- **Item 7 & Item 10 (Premise schema completeness, closed enum, versioned schema, unknown categories refused)**: `PremiseKind` is a closed enum for the decided rows and `EncodedPremise.read` is versioned, **but** `EncodedPremise.read_unknown` takes `PremiseKind.decode reader record.category = none` (the internal guard of `read`) as a premise, which switches off the obligation if `decode` has a catch-all, and there is no law for version-mismatch refusal.
- **Item 8 (Owner Decision: `FunctionRelativeKey`)**: `FunctionRelativeKey` is a structured path of `(ConstructKind, SegmentName)` segments without raw child indices, **but** (a) `key_insert_*` and `descendant_insert_*` pass `before ++ inserted :: after` as the `preceding` list (so `after` is still *before* `target`, and insertion of any sibling *after* `target` in a forest is never stated or proved), (b) `KeyConstruct.pathAt` computes ordinals only among immediate parent children rather than same-kind siblings under the nearest named ancestor, and (c) `ConstructName.rename` conflates renaming a `.named` construct with pinning an `.unnamed` construct while `SegmentName.label` erases the distinction between them.
- **Item 9 (Owner Decision: `PackageId`)**: `PackageId` is structured `name : String` + `version : PackageVersion` with no content hash, and `PackageOrigin` is separate and checked at load time.

### Findings

1. **`ConcreteSpec/Spec/Prim.lean:296-309` & `ConcreteSpec/Proofs/Prim.lean:173-181, 567-595` — BLOCKER — REAL DEFECT: `SafetyEvidence.discharge` uses `classical` equality on `Prop` (`e.fact = obligation.fact`), which identifies all true propositions by `propext` and makes `discharge_proposition_mismatch` vacuous on true obligations**
   - **Problem**: `SafetyEvidence` carries `proof : e.fact`, so `e.fact` is always a true `Prop`. In Lean 4, `if fact : e.fact = obligation.fact` under `classical` uses `propext` and excluded middle: for *any* `obligation` whose `obligation.fact` is true (e.g., `2 + 2 = 4`), `(1 + 1 = 2) = (2 + 2 = 4)` holds by `propext`, so `evidence.discharge` succeeds and fabricates a proof of `2 + 2 = 4` from `1 + 1 = 2`! Conversely, the premise `mismatch : e.fact ≠ obligation.fact` in `SafetyEvidence.discharge_proposition_mismatch` is equivalent to `¬ obligation.fact` and can **never** hold for two distinct true propositions (the Vacuity instance at line 568 only works because `1 + 1 = 3` is false).
   - **Long-term fix**: Do not compare raw `Prop`s with `classical` `propext`. Give obligations and evidence a decidable statement representation (e.g., a typed/syntactic proposition descriptor or statement key `stmt : ObligationStmt` with an interpretation ` ObligationStmt.Interp : ObligationStmt → Prop`, where `SafetyEvidence` carries `stmt : ObligationStmt` and `proof : stmt.Interp`, and `SafetyObligation` carries `stmt : ObligationStmt`). Check `if h : e.stmt = obligation.stmt` computably (making `SafetyEvidence.discharge` computable without `classical`), transport `e.proof` along `congrArg ObligationStmt.Interp h`, and prove `discharge_proposition_mismatch` for two distinct *true* statements (e.g., `1 + 1 = 2` vs `2 + 2 = 4`). Also remove the now-dead `SafetyEvidence.Usable` (`ConcreteSpec/Spec/Prim.lean:275, 311`) or wire `discharge` through it.

2. **`ConcreteSpec/Proofs/Ident.lean:509-512, 915-925` — BLOCKER — REAL DEFECT: `EncodedPremise.read_unknown` takes the internal `decode` result as a premise, switching off the law against a catch-all decoder, and lacks a version-mismatch refusal law**
   - **Problem**: `EncodedPremise.read_unknown` states:
     ```lean
     theorem EncodedPremise.read_unknown (reader : SpecVersion) (record : EncodedPremise)
         (current : record.spec = reader) (unknown : PremiseKind.decode reader record.category = none) :
         record.read reader = none
     ```
     Because `EncodedPremise.read` is defined by `if record.spec = reader then match PremiseKind.decode reader record.category with | none => none ...`, this theorem merely restates the `none` branch of `read`. Worse, if `PremiseKind.decode` had a catch-all branch (`| _ => some .assume`), the premise `PremiseKind.decode reader record.category = none` would be `False`, switching off the theorem instead of catching the bug! In addition, there is no theorem proving that version mismatches (`record.spec ≠ reader` or `reader ≠ specVersion`) are refused.
   - **Long-term fix**: State `EncodedPremise.read_unknown` against the closed `PremiseKind` enumeration rather than `decode = none`:
     ```lean
     theorem EncodedPremise.read_unknown (reader : SpecVersion) (record : EncodedPremise)
         (unknown : ∀ kind : PremiseKind, kind.encode ≠ record.category) :
         record.read reader = none
     ```
     (which holds without even assuming `record.spec = reader`), and add `EncodedPremise.read_version_mismatch (reader : SpecVersion) (record : EncodedPremise) (mismatch : record.spec ≠ reader ∨ reader ≠ specVersion) : record.read reader = none`.

3. **`ConcreteSpec/Spec/Ident.lean:519-520` & `ConcreteSpec/Proofs/Ident.lean:53-55, 526-548` — BLOCKER — REAL DEFECT: `OutsideFunctionEdit.persistentKeys` is a projection law that restates its structure field**
   - **Problem**: `OutsideFunctionEdit` is a 1-field `Prop` structure:
     ```lean
     structure OutsideFunctionEdit (before after : FnId → SiteKeyTable) (edited : FnId) : Prop where
       keysUnchanged : ∀ f, f ≠ edited → List.map Prod.snd (after f) = List.map Prod.snd (before f)
     ```
     And `theorem OutsideFunctionEdit.persistentKeys` is `edit.keysUnchanged f outside`. That is a pure projection law (forbidden by both the owner's vacuity rule and `VACUITY_CONVENTION_FINAL.md`).
   - **Long-term fix**: Define the actual per-function key-table assignment operation over a program's function bodies (e.g., `assignProgramKeys (bodies : FnId → List KeyConstruct) (sites : FnId → List SiteId) : FnId → SiteKeyTable` or `KeyConstruct.assignTable (owner : StableOwner) (forest : List KeyConstruct)`), and prove as a real theorem that updating `bodies` at `edited` (and arbitrary lexical site renumbering across functions) leaves `List.map Prod.snd` unchanged for every `f ≠ edited`.

4. **`ConcreteSpec/Spec/Ident.lean:333-420` & `ConcreteSpec/Proofs/Ident.lean:59-150` — MAJOR — REAL DEFECT: `KeyConstruct` insertion laws only test insertion inside `preceding`, `pathAt` does not scope ordinals to the nearest named ancestor, and `rename` conflates naming with pinning**
   - **Problem**:
     1. In `KeyConstruct.key_insert_differentKind`, `key_insert_named`, `descendant_insert_differentKind`, and `descendant_insert_named`, the argument `before ++ inserted :: after` is passed as `preceding : List KeyConstruct`. That means `before`, `inserted`, and `after` are **all before `target`**! There is no law for `KeyConstruct.pathAt` showing that inserting *any* sibling (including an unnamed sibling of the *same* kind) **after** `target` in a forest preserves `target`'s key, nor that inserting a named or different-kind sibling *before* `target` in a forest shifts `target`'s route index from `i` to `i + 1` while preserving `pathAt`:
        `KeyConstruct.pathAt (before ++ inserted :: target :: after) ((before.length + 1) :: route) = KeyConstruct.pathAt (before ++ target :: after) (before.length :: route)`.
     2. Owner Decision 8 specifies: *"unnamed items by ordinal among same-kind siblings under the nearest named ancestor with an optional pinning label"*. `KeyConstruct.pathAt` instead resets ordinal counting at every unnamed intermediate node (`forest.take index`) rather than accumulating or scoping under the nearest named ancestor.
     3. `ConstructName.rename` (`Ident.lean:382`) rewrites `.unnamed _` to `.unnamed (some name)`, conflating renaming a named declaration/item with attaching a pinning label to an unnamed item, and providing no unpin operation. Furthermore, `KeyConstruct.segment` maps both `.named name` and `.unnamed (some name)` to `.label name`, so a named sibling and a pinned unnamed sibling of the same kind with the same string produce identical `KeySegment`s.
   - **Long-term fix**: Separate renaming a `.named` construct from pinning/unpinning an `.unnamed` construct; distinguish named segments from pinned-label segments (or enforce disjointness in well-formed scopes); state the forest-level insertion-stability laws on `KeyConstruct.pathAt` for both insertions before `target` (same-kind named, different-kind unnamed) and arbitrary insertions after `target`; and align ancestor scoping with Owner Decision 8.
