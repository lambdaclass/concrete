CHANGES. The final-store repair is appropriately scoped, but physical-output semantics remain disconnected from C1 execution, the environment repair still contains admission repackaging, and the path law violates the binding vacuity rule.

This was a source-only review. I modified nothing, ran no builds or gates, used no network, and ran no git commands. Proof and tag assessments below are manual, not kernel-checked results.

**Findings**

1. **ConcreteSpec/Proofs/ObserveOutput.lean:37 — major — REAL DEFECT: the physical-output repair remains an algebraic wrapper around the old premise.**

   `project_physical_outputs` still assumes `ExecAdapter.OutputCorrespondence A physical` separately. Its entire proof applies the list lemma to `(Exec.runFrom …).events`; it establishes no relationship between `physical` and the primitive/oracle effects that generated those events. Neither `ExecAdapter.WellFormed` nor C1 operands independently specify those physical outputs.

   Replacing `fun _ => rfl` with a case split in `adapter_correspondence` changes the witness’s proof shape, not this structural problem. An output-erasing implementation can still choose `physical := fun _ => []` and satisfy the generic contract. Consequently, `output_before_trap_kept` at line 62 retains the same limitation.

   **Fix:** define physical-output meaning independently in the operand/oracle interface, require adapter correspondence to that meaning, and derive preservation for actual runs. Keep list distribution as a helper. Use an output-erasing implementation against the unchanged physical semantics as the rejection control.

2. **ConcreteSpec/Proofs/ObserveEnvironment.lean:20 — major — REAL DEFECT: environment correctness is still substantially admission repackaging, and the new environment is disconnected from the C1 oracle.**

   `Environment.Valid.allows` assumes handler-result compliance; `.mayBlock` assumes handler-result blocking permission. `environment_respond_valid` case-splits on that same result and repackages those premises into `Responds`. Routing is supplied by the dependent result type and the definition of `respond`. This is the constructor-repackaging pattern prohibited for Law credit.

   The new `Environment` and `stepHistory` also do not construct or constrain an `Exec.Oracle`; the law does not establish `ExecAdapter.WellFormed` for an oracle used by `Exec.runFrom`. Thus the requested general environment/oracle repair is incomplete, despite replacing demo-only theorem names.

   **Fix:** retain this admission bridge as a helper; implement a typed handler-to-oracle adapter, establish its answer/history/store correspondence and `WellFormed` obligations, and prove operational response/routing laws for its actual runs. Preserve the arithmetic fixtures as closed evidence for those laws.

3. **ConcreteSpec/Proofs/ObserveReport.lean:290 — major — REAL DEFECT: `trapTerminal_eq_some_iff` restates a runtime invariant check.**

   `trapTerminal` looks up the span, tests `decide sp.PathOk`, and constructs precisely the terminal on the right-hand side of this iff. The proof unfolds that operation and inverts its branches. This is exactly the runtime-recheck/definition-restatement case prohibited by the owner’s rule.

   The absolute-path and backslash mutants demonstrate that deleting validation changes the function; they do not make this definition-restatement independent semantic evidence.

   **Fix:** classify the lookup equation as a computation helper. Establish path correctness from an independently defined source/site production pipeline, with valid source paths carried through site resolution into actual reported traps. Test a faulty producer/resolver while keeping the independent path requirement unchanged.

4. **ConcreteSpec/Proofs/ObserveReport.lean:31 — major — REAL DEFECT: blocked `ReportTraceValid` results are not tied to the evaluator ending.**

   The terminal branch requires a corresponding `.final` ending. The blocked branch requires only a valid permitted pending trace and the projected-history equation. It does not require `.noAnswer`, the pending configuration’s request step, or its adapter mapping.

   For example, with a blocking-permitted request `q`, a mutant can turn a zero-fuel run with empty history into `some (.blocked [.request q] q)`. This satisfies the blocked branch even though the report is `.outOfFuel`. The separate fuel law rejects that implementation, but `runFrom_report_trace` does not deliver its advertised ending correspondence.

   **Fix:** add the corresponding `.noAnswer` configuration, request step and typed-request mapping to the blocked specification, and add a planted fabricated-blocking observation for an out-of-fuel report.

5. **ConcreteSpec/Proofs/ObserveOutput.lean:14; ConcreteSpec/Proofs/ObserveReport.lean:122 — minor — REAL DEFECT: invalid Helper classes.**

   Both declarations use `Helper (induction)`. The final convention permits only `inversion|projection|congruence|arithmetic|computation`.

   **Fix:** use `Helper (computation)` with the existing induction explanation, or explicitly obtain a convention change. I approve their helper status, but not the current tags.
