1. **major — ConcreteSpec/Spec/Exec.lean:108, 307–326:** The new `Store` threads primitive effects, but cannot implement the promised C5 ownership instrumentation. `eval` returns only a value, `evalArgs` evaluates every argument against the same state, and bind/call/return preserve that state. Thus evaluating `move x` cannot mark its source consumed or transfer its ownership to a callee; two argument reads see identical ownership state. This is an interface gap despite deferring the actual instrumentation to C5. **Fix:** provide state-threading operand evaluation and ownership transition hooks, or explicitly define this as an erased machine and provide an instrumented refinement interface with a projection law. Include a representative move-through-call example showing ownership transfer and rejection of reuse.

2. **minor — ConcreteSpec/Spec/Exec.lean:96–97:** “An operation with no allowed answer is stuck” disagrees with the driver’s classifications. Such a primitive still produces `.request`; an oracle returning `none` yields `.noAnswer`, while every supplied answer yields `.badAnswer`. Neither yields `.stuck`. **Fix:** qualify this as absence of a transition in `Step`, and explain that `runFrom` reports missing/refused oracle answers separately; alternatively provide an explicit primitive-precondition failure path if evaluator-level stuckness is intended.
