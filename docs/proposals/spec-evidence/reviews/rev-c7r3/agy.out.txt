### Findings

1. **`ConcreteSpec/Spec/Leak.lean:306`** — **blocker** — **REAL DEFECT**
   - **Problem:** [`ResetConservation`](file:///home/unbalancedparen/ConcreteSpec/Spec/Leak.lean#L306-L309) states live-byte conservation using truncated `Nat` subtraction:
     ```lean
     def ResetConservation (before after : Account) (recordedOutflow : Nat) : Prop :=
       after.requested = before.requested ∧
         after.live = before.live - recordedOutflow ∧
         after.peak = before.peak ∧ after.functionPeak = before.functionPeak
     ```
     Because `Account.reset` sets `after.live = 0`, `0 = before.live - recordedOutflow` in `Nat` holds for **every** `recordedOutflow ≥ before.live`. For example, `ResetConservation ⟨100, 5, 12, 5⟩ (Account.reset ⟨100, 5, 12, 5⟩) 999` is provably true (`0 = 5 - 999`), directly contradicting the docstring claim that *"a wrong record makes this predicate false"*. Only an under-recorded outflow (`4 < 5`) was tested in `Proofs/Leak.lean:632`.
   - **Concrete fix:** Express the live-byte equation in `Int` (matching `run_conservation`) so over-recording is also rejected, and add the planted over-record counterexample:
     ```lean
     def ResetConservation (before after : Account) (recordedOutflow : Nat) : Prop :=
       after.requested = before.requested ∧
         (after.live : Int) = (before.live : Int) - (recordedOutflow : Int) ∧
         after.peak = before.peak ∧ after.functionPeak = before.functionPeak
     ```
     and in [`ConcreteSpec/Proofs/Leak.lean`](file:///home/unbalancedparen/ConcreteSpec/Proofs/Leak.lean#L631-L633):
     ```lean
     example : ¬ ResetConservation ⟨100, 5, 12, 5⟩ (Account.reset ⟨100, 5, 12, 5⟩) 6 := by
       simp [ResetConservation, Account.reset]
     ```
     Also state [`reset_conservation`](file:///home/unbalancedparen/ConcreteSpec/Proofs/Leak.lean#L617-L625) using `resetOutflow lineage m (.reset lineage)` (or equate it to `(m lineage).live`) so the single-step conservation law exercises `resetOutflow` directly.

2. **`ConcreteSpec/Proofs/Leak.lean:258` and `ConcreteSpec/Proofs/Leak.lean:271`** — **major** — **REAL DEFECT**
   - **Problem:** In [`secure_ni`](file:///home/unbalancedparen/ConcreteSpec/Proofs/Leak.lean#L258-L267) and [`secure_ct`](file:///home/unbalancedparen/ConcreteSpec/Proofs/Leak.lean#L271-L280), `start secret` has a single scalar secret `secret : Int` and declassifies `secret` itself (`body .secret .secret`). Consequently, `hreleases : r₁.releases = r₂.releases` reduces to `[releaseValue s₁] = [releaseValue s₂]`, which forces `s₁ = s₂` (`subst s₂` in both proofs). Thus:
     - For every pair of distinct states `s₁ ≠ s₂`, the `r₁.releases = r₂.releases` premise is `False` (vacuous implication).
     - Whenever the premises hold (`s₁ = s₂`), the two initial configurations `start s₁` and `start s₂` are identical (`rfl`), degenerating relational 2-safety into reflexivity on a single deterministic run.
     - Because `timingStart` is not constant-time (`timing_not_ct`), `ConstantTime` has **no** witness on any pair of distinct configurations (`c₁ ≠ c₂`) with inhabited premises anywhere in the file.
   - **Concrete fix:** Give `start` an un-declassified secret component alongside the released secret (for example, `start (released hidden : Int) : Config ops` with a secret negative local `[(⟨"hidden", 0⟩, -Int.natAbs hidden - 1)]`, or a pair in the shared store where only the first component is released). Then for `released₁ = released₂` and `hidden₁ ≠ hidden₂`, the two configurations are distinct (`c₁ ≠ c₂`), low-equivalent, have inhabited equal release traces (`r₁.releases = r₂.releases`), and still require `hreleases` to deduce `released₁ = released₂` in both `secure_ni` and `secure_ct`.

3. **`ConcreteSpec/Proofs/Leak.lean:1010`** — **minor** — **REAL DEFECT**
   - **Problem:** [`unestablished_report_sound`](file:///home/unbalancedparen/ConcreteSpec/Proofs/Leak.lean#L1010-L1015) was flagged in the vacuity audit for being guard-vacuous (`b.status = .boundEstablished → ...` has a false antecedent on all four `.notEstablished` fields). Keeping the identical theorem and adding a docstring saying `"this lemma is intentionally vacuous"` leaves a guard-vacuous theorem in `Proofs/Leak.lean`, while [`mixed_status_report_sound`](file:///home/unbalancedparen/ConcreteSpec/Proofs/Leak.lean#L948-L956) already tests `.notEstablished` alongside `.boundEstablished` fields non-vacuously.
   - **Concrete fix:** Remove `unestablished_report_sound` (or replace it with a single-field `Bound.Sound actual ⟨limit, .notEstablished⟩` unit control `example` next to the `Bound.Sound` controls at `Proofs/Leak.lean:861-868`), relying on `mixed_status_report_sound` for partial-evidence report soundness.
