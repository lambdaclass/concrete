Theorems in [Proofs/Memory.lean](ConcreteSpec/Proofs/Memory.lean):

- `decodeInt_encodeInt`: valid integers round-trip in either byte order.
- `decodeInt_inRange`: decoded integers are in range.
- `decodeBool_encodeBool`: bools round-trip.
- `decodeBool_valid`: successful decoding requires the corresponding byte `0` or `1`.
- `decodePtr_encodePtr`: pointers round-trip under a well-formed target.
- `alloc_result`: success returns identity `m.next`, the specified new memory, and fitting premises.
- `alloc_fresh`: that identity was absent.
- `alloc_block`, `alloc_initialized`: the new block is present, live, unexposed and entirely uninitialized.
- `alloc_failure`: an unavailable request returns only the error.
- `alloc_wellFormed`: allocation preserves the memory invariant.
- `alloc_ne_existing`, `free_alloc_ne_existing`: allocation never reuses an existing identity, including after release.
- `free_retains`: release retains the block, marks it dead/unexposed, and preserves `next`.
- `access_zero`: zero-byte access checks only alignment and non-nullness.
- `access_no_provenance`, `access_after_free`: nonzero accesses without provenance or through released provenance fail.
- `access_some`: successful nonempty access supplies its live block and bounds.
- `store_load`: a successful store reads back exactly its bytes.
- `store_other_block`, `store_same_block_frame`: stores preserve other blocks and bytes outside their range.
- `fromExposed_sound`: reconstructed provenance identifies an eligible containing block, or a one-past block when none contains the address.
- `candidate_contains_unique`: two eligible blocks cannot contain the same address.
- `eqAddr_provenance`: address equality ignores provenance.
- Supporting lemmas establish byte-order involution (`ordered_ordered`), encoding/decoding lengths (`leBytes_length`, `ordered_length`, `octets_length`, `encodeInt_length`), initialized-octet recovery (`octets_init`), numeric recovery/bounds (`leValue_leBytes`, `leValue_lt`, `intByte_power`), update lookup (`block_modify`), overlap symmetry, and splice read/frame properties (`splice_read`, `splice_frame`).

Theorems in [Proofs/Hybrid.lean](ConcreteSpec/Proofs/Hybrid.lean):

- `encode_length`: encoding occupies the active scalar size.
- `rep_roundtrip`: valid scalar encodings decode to their values.
- `decode_valid`: decoding supplies the requested type and a valid value.
- `read_structured`: unmaterialized reads return the structured value.
- `write_read`: successful typed writes read back their value.
- `typed_store_frame`: active-byte writes preserve outside bytes, including padding metadata.
- `materialize_reuse`: existing materialized storage is reused unchanged.
- `materialize_projection`: success installs the returned range.
- `materialize_idempotent`: repeating materialization preserves that range and state.
