BUGS (all Codex-CONFIRMED at main f7a973b0 / ea212942):
- ISS-0023 (high), G1: signoff.sh:75 (used for the quote at :159) resolves the quote's hex prefix with ref-aware `git rev-parse`, so a branch named like an ambiguous prefix selects one object: two commits sharing 6efc0de, `git branch 6efc0de <a>` makes `record` accept quote "approve 6efc0de" for a. Structural cause: object-prefix validation uses ref-aware resolution. Fix: resolve prefixes only against objects (e.g. `git rev-parse --disambiguate=<prefix>` or `git cat-file --batch-check` on the object store, refusing ambiguity), never refs; the same for every prefix check in signoff.sh (request bodies too).
- ISS-0024 (medium), G2: .githooks/pre-push:54-57 recognises an owner-signoff push by topology, filenames and modes only: a parentless commit of seven 100644 files each containing `x` passes the no-source-tree tier (exit 0). Fix: the hook runs `signoff.sh verify <sha from the ref name>` semantics on the pushed commit (with an explicit base the record allows the hook to determine, or a structural verify mode that checks everything except the cap's base-dependent part — choose and justify), and refuses anything that does not verify; fix the control to expect refusal of junk and acceptance of a real record.
- ISS-0025 (low), G3: signoff.sh:140-143 (reached by verify at :219, used by train.sh:522) does not check the record commit is parentless: a valid tree re-committed with the source commit as parent verifies. Fix: verify requires zero parents.
- ISS-0026 (high), F3: signoff.sh:194 (header inserted at :113) treats any occurrence of the SHA in the request body as targeting: a request "Review exact commit B. Fix: the binding must come from the request as sent — the request file must itself begin with `reviewed: <full sha>` (or an equivalently structured line the reviewer was actually sent), record must not synthesise it, and the body must not name any other commit as the one under review; choose the smallest rule that makes the reproducer fail and keep existing recorded refs verifiable (check refs/owner-signoff/ea5181b5… and refs/owner-signoff/fb097fa4… still verify, fetching them from origin read-only; if a rule would invalidate them, stop and report instead of loosening).
