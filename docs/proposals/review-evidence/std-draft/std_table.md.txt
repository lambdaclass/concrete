## Conflicts

- **grep at 18: command-line input gap.** The adopted `grep PATTERN FILE` stage needs argument access (`docs/proposals/EXAMPLES.md:23`), but args/cli are not placed. The legacy accessor returns an allocating String (`legacy/std/src/args.con:22`); legacy CLI stores Vec/String (`legacy/std/src/cli.con:27`, `legacy/std/src/cli.con:50`). Allocation arrives at 19 and Vec/String at 22 (`ROADMAP.md:229`, `ROADMAP.md:232`), after zero-heap slice 18 (`ROADMAP.md:228`). A nonallocating argument contract is unresolved; this table does not choose one. The same gap applies to the file encryptor at 18 if it takes command-line paths, which its adopted row does not specify.
- **All early byte consumers: legacy Bytes cannot be carried unchanged.** EVM 15, crypto 15/18, grep fixed buffers 16/18, QOI 19/21, PNG 21 and Wasm 21 need byte operations before growable Vec storage at 22; Bytes itself is unplaced. Legacy Bytes owns raw, allocating storage (`legacy/std/src/bytes.con:7`, `legacy/std/src/bytes.con:30`); allocation is 19 and source raw pointers are 24 (`ROADMAP.md:229`, `ROADMAP.md:234`). Fixed arrays/views at 15 and HeapArray at 21 support earlier safe implementations; they do not establish a Bytes module placement. The stage rows are `docs/proposals/EXAMPLES.md:23` through `docs/proposals/EXAMPLES.md:28`.
- **EVM 21 growable memory: potential container conflict.** The showcase asks for growable memory in its 21 → 23 expansion (`docs/proposals/EXAMPLES.md:25`), while HeapArray at 21 is fixed-length and Vec arrives at 22 (`ROADMAP.md:231`, `ROADMAP.md:232`). If growth is required at 21, its implementation contract is missing; the row does not establish that Vec arrives early.
- **Unplaced codec/crypto dependencies.** QOI 19/21, PNG 21–22, EVM 15/21/23 and Wasm 21 need endian byte operations; PNG also needs CRC32, and EVM's full version needs Keccak (`docs/proposals/EXAMPLES.md:24`, `docs/proposals/EXAMPLES.md:25`, `docs/proposals/EXAMPLES.md:27`). Their module arrivals are not placed, so these are scheduling gaps, not demonstrable later-slice conflicts. DEFLATE is an adopted PNG program requirement, not an independently scheduled std module. The crypto 7 stage is scalar only: arrays arrive at 15, so complete array-based ChaCha20/Poly1305/X25519 implementations cannot be claimed at 7 (`ROADMAP.md:217`, `ROADMAP.md:225`; `docs/proposals/EXAMPLES.md:28`).
- **Proposed base64 at 17: legacy implementation conflicts.** This is not an adopted placement (`docs/proposals/EXAMPLES.md:3`, `docs/proposals/EXAMPLES.md:62`). Legacy encode/decode allocate Bytes (`legacy/std/src/base64.con:40`, `legacy/std/src/base64.con:62`), before allocation at 19 and growable containers at 22; a fixed-buffer version has no decided API.
- No other definite stage-before-module conflict follows from the adopted rows: maps arrive with store/EVM/Wasm stage 23; network/time arrive with the sequential server at 27. RocksDB acceptance is **after 25**, and ethlambda **after 28**, both subject to the R-0604 dependency audit (`ROADMAP.md:467`, `ROADMAP.md:469`, `ROADMAP.md:474`); their complete module requirements must not be inferred as already audited. No concurrency model is chosen here.
