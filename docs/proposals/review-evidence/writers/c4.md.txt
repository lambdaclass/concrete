## Part A (first, commit separately): ConcreteSpec/Proofs/Memory.lean
Prove, for Spec/Memory.lean as it is (you may fix real bugs in it, say which):
1. Representation: decodeInt (encodeInt tgt t n) = some n for t.InRange n (both byte orders); decodeInt only yields values in range; decodeBool (encodeBool b) = some b and decodeBool only yields from bytes 0/1; decodePtr (encodePtr tgt p) = some p.
2. Allocation: on success the new identity was absent and is m.next; the new block is live, unexposed, all bytes uninit; alloc preserves Memory.WellFormed; on failure nothing changes (stated as: the caller's memory is untouched, i.e. the result carries no memory).
3. Identity never reused: after free the block is still present (not live), and a later alloc's identity differs from every existing identity.
4. Access: after free, every nonzero access through a pointer with that block's provenance fails; a zero-byte access needs only alignment and a non-null address; a nonzero access with no provenance fails.
5. store/load: a store then a load of the same pointer and length returns the stored bytes (under WellFormed); frame law: a store leaves every other block unchanged, and leaves bytes of the same block outside the written range unchanged.
6. fromExposed (Q3.9): under WellFormed, if the result has provenance b then b is a candidate (live, exposed, nonempty, same space) that contains the address, or, when no candidate contains it, one the address is one past; and at most one candidate contains a given address (no tie-break needed). Ptr.eqAddr ignores provenance.
Add a header listing the laws, like ConcreteSpec/Proofs/Exec.lean. Import it from ConcreteSpec.lean.

## Part B: the hybrid state (proposal C4 "State choice", owner-approved question 2)
In a new module ConcreteSpec/Spec/Hybrid.lean (+ Proofs/Hybrid.lean): structured places for safe typed storage plus the byte blocks of Spec/Memory.lean, related by a partial place-to-block/range projection and Rep; not two independently writable copies. Define: materialization (a place gets a stable block/range on raw address-taking/expose; existing materialized storage is reused; sizeof/alignof never materialize); typed read of a materialized place = partial Rep decode of current bytes (failure = no value, never a fabricated one); typed write to materialized storage = encode the new value's active bytes, keep every byte outside the active representation (padding) unchanged, do not re-choose padding; raw writes update bytes. Prove: typed write then typed read returns the value; a typed write preserves bytes outside its active representation; materialization is idempotent (reuses the mapping); an unmaterialized typed read uses the structured value. Scope it to scalar values (ints, bool) and structs of them if padding is needed to state the store rule; enums, pointers-in-structs and the C8 padding oracle can be listed as left out. Provide an `Operands`-compatible Store shape (or explain the instance plan) so C1's machine can run over it; do not change Exec.lean.

Out of scope: borrow/loan/authority (C5), allocator algorithms, FFI, the C8 oracle, any surface syntax. The meaning of a pointer read from bytes that are not one whole stored pointer is an OPEN owner question: keep decodePtr's current behaviour and do not extend it.
