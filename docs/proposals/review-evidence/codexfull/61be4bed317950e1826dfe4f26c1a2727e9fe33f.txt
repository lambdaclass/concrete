+### Background agent jobs get a bounded watcher (2026-11-08)
+
+`scripts/agent/launch.sh` starts a writer, reviewer or gate once as a bounded transient systemd
+user unit and records its output and exit status. The agent runs the printed `WAIT` command as its
+own background task, so completion re-invokes the agent instead of leaving a finished job unnoticed.
+A lost unit and a deadline overrun are distinct non-passing results, and writers are never retried
+automatically. Job directories are exclusive, command arguments survive systemd expansion byte for
+byte, and the quoted `WAIT` command is safe for paths containing shell metacharacters. Lost units
+retain their timeout/signal/OOM result where systemd provides one; query failures are operational
+errors. Stub-backed controls cover these behaviours and all watcher outcomes.

+#!/usr/bin/env bash
+# Run one background agent job and pair it with a bounded watcher.
+#
+#   launch.sh start [--mem SIZE] [--tasks N] [--dir DIR] NAME SECS -- CMD [ARGS...]
+#   launch.sh wait JOBDIR
+#   launch.sh status JOBDIR
+#
+# start exclusively creates a new job directory and runs CMD once in a transient
+# systemd user unit, with MemoryMax (8G by default), TasksMax (1024),
+# RuntimeMaxSec=SECS, the caller's PATH, HOME and working directory. A fixed
+# wrapper reads the NUL-separated argv file, so systemd cannot expand the command.
+# The directory records cmd, argv, unit, deadline, out.log and an atomic status.
+# The job itself exits 0 only after writing status atomically, or 2 if that write
+# fails, independently of CMD's recorded status; a recorded job never ends failed.
+# The printed UNIT, DIR and shell-quoted absolute WAIT are its only output.
+# Writers are never retried.
+#
+# wait polls until status appears, the unit becomes inactive, or deadline plus
+# grace (120s by default) passes. It re-checks status after an inactive observation.
+# A normal exit prints JOB ... ENDED status=N and the last 40 log lines, then
+# returns N. A lost unit returns 125 with the retained systemd Result (or unknown),
+# read before reset-failed collects the unit and cached in result. An overrun
+# returns 124 (INCOMPLETE); a systemd query failure returns 2. AGENT_WAIT_INTERVAL
+# and AGENT_WAIT_GRACE override the 10s poll and 120s grace. status observes once.
+set -uo pipefail
+
+usage() {
+  echo "usage: launch.sh start [--mem SIZE] [--tasks N] [--dir DIR] NAME SECS -- CMD [ARGS...] | launch.sh wait JOBDIR | launch.sh status JOBDIR" >&2
+  exit 2
+}
+
+fail() {
+  echo "launch.sh: $*" >&2
+  exit 2
+}
+
+positive_integer() {
+  case "$1" in
+    ''|*[!0-9]*) return 1 ;;
+  esac
+  [ "${#1}" -le 9 ] || return 1
+  [ "$((10#$1))" -gt 0 ]
+}
+
+self_dir() {
+  local source dir
+  source="${BASH_SOURCE[0]}"
+  case "$source" in */*) dir="${source%/*}" ;; *) dir=. ;; esac
+  (CDPATH= cd "$dir" && pwd -P)
+}
+
+start() {
+  local mem=8G tasks=1024 dir="" name="" secs="" cwd="" safe="" unit="" jobdir="" base="" parent="" script=""
+  while [ "$#" -gt 0 ]; do
+    case "$1" in
+      --mem) [ "$#" -ge 2 ] || usage; mem="$2"; shift 2 ;;
+      --tasks) [ "$#" -ge 2 ] || usage; tasks="$2"; shift 2 ;;
+      --dir) [ "$#" -ge 2 ] || usage; dir="$2"; shift 2 ;;
+      --) break ;;
+      -*) fail "unknown start option: $1" ;;
+      *) break ;;
+    esac
+  done
+  [ "$#" -ge 4 ] && [ "$3" = -- ] || usage
+  name="$1"; secs="$2"; shift 3
+  [ "$#" -gt 0 ] || usage
+  case "$name" in
+    ''|[!A-Za-z0-9]*|*[!A-Za-z0-9_.-]*)
+      fail "NAME must be 1-64 characters: alphanumeric, then alphanumerics, '.', '_' or '-'" ;;
+  esac
+  [ "${#name}" -le 64 ] || fail "NAME must be at most 64 characters"
+  positive_integer "$secs" || fail "SECS must be a positive integer"
+  positive_integer "$tasks" || fail "--tasks must be a positive integer"
+  [ -n "$mem" ] || fail "--mem must not be empty"
+  command -v systemd-run >/dev/null 2>&1 || fail "systemd-run --user is unavailable (systemd-run not found)"
+
+  secs="$((10#$secs))"; tasks="$((10#$tasks))"
+  cwd="$(pwd -P)" || fail "cannot determine the working directory"
+  safe="${name//[^A-Za-z0-9_.-]/-}"
+  unit="agent-${safe}-$(date +%s)-$$.service"
+  if [ -n "$dir" ]; then jobdir="$dir"; else
+    base="${AGENT_JOBS_DIR:-$HOME/.cache/concrete-agent-jobs}"
+    jobdir="$base/$unit"
+  fi
+  while [ "${#jobdir}" -gt 1 ] && [ "${jobdir%/}" != "$jobdir" ]; do jobdir="${jobdir%/}"; done
+  case "$jobdir" in */*) parent="${jobdir%/*}"; parent="${parent:-/}" ;; *) parent=. ;; esac
+  mkdir -p -- "$parent" || fail "cannot create job directory parent: $parent"
+  mkdir -- "$jobdir" || fail "job directory already exists or cannot be created: $jobdir"
+  jobdir="$(CDPATH= cd "$jobdir" && pwd -P)" || fail "cannot resolve job directory"
+  script="$(self_dir)/launch.sh"
+  printf '%s\n' "$unit" > "$jobdir/unit" || exit 2
+  printf '%s\n' "$(( $(date +%s) + secs ))" > "$jobdir/deadline" || exit 2
+  printf '%q ' "$@" > "$jobdir/cmd" || exit 2
+  printf '\n' >> "$jobdir/cmd" || exit 2
+  printf '%s\0' "$@" > "$jobdir/argv" || exit 2
+
+  if ! systemd-run --user --unit="$unit" \
+      --property=MemoryMax="$mem" --property=TasksMax="$tasks" \
+      --property=RuntimeMaxSec="$secs" --property=WorkingDirectory="$cwd" \
+      --setenv=PATH="$PATH" --setenv=HOME="$HOME" \
+      --setenv=AGENT_JOB_DIR="$jobdir" --setenv=AGENT_LAUNCH_SELF="$script" \
+      /bin/bash -c 'exec /bin/bash "$$AGENT_LAUNCH_SELF" run' >/dev/null; then
+    fail "systemd-run --user is unavailable or could not start $unit"
+  fi
+  printf 'UNIT=%s\nDIR=%s\nWAIT=bash %q wait %q\n' "$unit" "$jobdir" "$script" "$jobdir"
+}
+
+run_job() {
+  local dir="${AGENT_JOB_DIR:-}" rc=0 tmp=""
+  local -a argv=()
+  [ -n "$dir" ] && [ -r "$dir/argv" ] || exit 2
+  mapfile -d '' -t argv < "$dir/argv" || exit 2
+  [ "${#argv[@]}" -gt 0 ] || exit 2
+  "${argv[@]}" > "$dir/out.log" 2>&1 || rc=$?
+  tmp="$dir/.status.$$"
+  if printf '%s\n' "$rc" > "$tmp" && mv "$tmp" "$dir/status"; then
+    exit 0
+  fi
+  rm -f "$tmp"
+  exit 2
+}
+
+JOBDIR="" UNIT="" DEADLINE="" ACTION=wait DONE=0
+
+load_job() {
+  JOBDIR="$1"
+  [ -n "$JOBDIR" ] && [ -d "$JOBDIR" ] || fail "job directory not found: $JOBDIR"
+  [ -r "$JOBDIR/unit" ] && [ -r "$JOBDIR/deadline" ] || fail "job directory lacks unit or deadline: $JOBDIR"
+  IFS= read -r UNIT < "$JOBDIR/unit" || fail "cannot read $JOBDIR/unit"
+  IFS= read -r DEADLINE < "$JOBDIR/deadline" || fail "cannot read $JOBDIR/deadline"
+  case "$DEADLINE" in ''|*[!0-9]*) fail "invalid deadline in $JOBDIR/deadline" ;; esac
+  command -v systemctl >/dev/null 2>&1 || fail "systemctl is unavailable"
+}
+
+collect_unit() {
+  systemctl --user reset-failed "$UNIT" >/dev/null 2>&1 || :
+}
+
+normal_exit() {
+  local rc=""
+  IFS= read -r rc < "$JOBDIR/status" || fail "cannot read $JOBDIR/status"
+  case "$rc" in ''|*[!0-9]*) fail "invalid status in $JOBDIR/status" ;; esac
+  [ "$rc" -le 255 ] || fail "invalid status in $JOBDIR/status"
+  DONE=1
+  printf 'JOB %s ENDED status=%s\n' "$UNIT" "$rc"
+  if [ "$ACTION" = wait ] && [ -f "$JOBDIR/out.log" ]; then tail -n 40 "$JOBDIR/out.log"; fi
+  collect_unit
+  return "$rc"
+}
+
+unit_result() {
+  local result=""
+  result="$(systemctl --user show "$UNIT" --property=Result --value 2>/dev/null)" || result=""
+  case "$result" in ''|success) result=unknown ;; esac
+  printf '%s\n' "$result"
+}
+
+lost_exit() {
+  local reason="" tmp=""
+  DONE=1
+  if [ -f "$JOBDIR/result" ]; then
+    IFS= read -r reason < "$JOBDIR/result" || fail "cannot read $JOBDIR/result"
+  else
+    reason="$(unit_result)"
+    tmp="$JOBDIR/.result.$$"
+    if printf '%s\n' "$reason" > "$tmp" && mv "$tmp" "$JOBDIR/result"; then :
+    else rm -f "$tmp"; fi
+    collect_unit
+  fi
+  printf 'JOB %s ENDED without a status (killed, timed out or OOM): %s\n' "$UNIT" "$reason"
+  return 125
+}
+
+inspect() {
+  local state="" query_rc=0 now="" grace="${AGENT_WAIT_GRACE:-120}"
+  DONE=0
+  if [ -f "$JOBDIR/status" ]; then normal_exit; return "$?"; fi
+
+  state="$(systemctl --user is-active "$UNIT" 2>&1)" || query_rc=$?
+  case "$state" in
+    active|activating|reloading|deactivating)
+      now="$(date +%s)"
+      case "$grace" in ''|*[!0-9]*) fail "AGENT_WAIT_GRACE must be a non-negative integer" ;; esac
+      if [ "$now" -gt "$((DEADLINE + 10#$grace))" ]; then
+        DONE=1
+        printf 'JOB %s STILL RUNNING past its deadline\n' "$UNIT"
+        return 124
+      fi
+      if [ "$ACTION" = status ]; then printf 'JOB %s RUNNING\n' "$UNIT"; fi
+      return 0 ;;
+    inactive|unknown|failed)
+      if [ -f "$JOBDIR/status" ]; then normal_exit; return "$?"; fi
+      lost_exit
+      return 125 ;;
+    *)
+      fail "cannot query systemd for $UNIT (systemctl exit $query_rc): ${state:-no output}" ;;
+  esac
+}
+
+watch() {
+  local interval="${AGENT_WAIT_INTERVAL:-10}" rc=0
+  case "$interval" in ''|*[!0-9]*) fail "AGENT_WAIT_INTERVAL must be a positive integer" ;; esac
+  [ "$interval" -gt 0 ] || fail "AGENT_WAIT_INTERVAL must be a positive integer"
+  load_job "$1"
+  while :; do
+    inspect; rc=$?
+    [ "$DONE" -eq 1 ] && return "$rc"
+    [ "$ACTION" = wait ] || return 0
+    sleep "$interval"
+  done
+}
+
+[ "$#" -ge 1 ] || usage
+ACTION="$1"; shift
+case "$ACTION" in
+  start) start "$@" ;;
+  run) [ "$#" -eq 0 ] || usage; run_job ;;
+  wait) [ "$#" -eq 1 ] || usage; watch "$1" ;;
+  status) [ "$#" -eq 1 ] || usage; watch "$1" ;;
+  *) usage ;;
+esac

#!/usr/bin/env bash
# Run one background agent job and pair it with a bounded watcher.
#
#   launch.sh start [--mem SIZE] [--tasks N] [--dir DIR] NAME SECS -- CMD [ARGS...]
#   launch.sh wait JOBDIR
#   launch.sh status JOBDIR
#
# start exclusively creates a new job directory and runs CMD once in a transient
# systemd user unit, with MemoryMax (8G by default), TasksMax (1024),
# RuntimeMaxSec=SECS, the caller's PATH, HOME and working directory. A fixed
# wrapper reads the NUL-separated argv file, so systemd cannot expand the command.
# The directory records cmd, argv, unit, deadline, out.log and an atomic status.
# The job itself exits 0 only after writing status atomically, or 2 if that write
# fails, independently of CMD's recorded status; a recorded job never ends failed.
# The printed UNIT, DIR and shell-quoted absolute WAIT are its only output.
# Writers are never retried.
#
# wait polls until status appears, the unit becomes inactive, or deadline plus
# grace (120s by default) passes. It re-checks status after an inactive observation.
# A normal exit prints JOB ... ENDED status=N and the last 40 log lines, then
# returns N. A lost unit returns 125 with the retained systemd Result (or unknown),
# read before reset-failed collects the unit and cached in result. An overrun
# returns 124 (INCOMPLETE); a systemd query failure returns 2. AGENT_WAIT_INTERVAL
# and AGENT_WAIT_GRACE override the 10s poll and 120s grace. status observes once.
set -uo pipefail

  echo "usage: launch.sh start [--mem SIZE] [--tasks N] [--dir DIR] NAME SECS -- CMD [ARGS...] | launch.sh wait JOBDIR | launch.sh status JOBDIR" >&2
  exit 2
}

fail() {
  echo "launch.sh: $*" >&2
  exit 2

positive_integer() {
  case "$1" in
    ''|*[!0-9]*) return 1 ;;
  esac
  [ "${#1}" -le 9 ] || return 1
  [ "$((10#$1))" -gt 0 ]
}

self_dir() {
  local source dir
  source="${BASH_SOURCE[0]}"
  case "$source" in */*) dir="${source%/*}" ;; *) dir=. ;; esac
  (CDPATH= cd "$dir" && pwd -P)
}

start() {
  local mem=8G tasks=1024 dir="" name="" secs="" cwd="" safe="" unit="" jobdir="" base="" parent="" script=""
  while [ "$#" -gt 0 ]; do
    case "$1" in
      --mem) [ "$#" -ge 2 ] || usage; mem="$2"; shift 2 ;;
      --tasks) [ "$#" -ge 2 ] || usage; tasks="$2"; shift 2 ;;
      --dir) [ "$#" -ge 2 ] || usage; dir="$2"; shift 2 ;;
      --) break ;;
      -*) fail "unknown start option: $1" ;;
      *) break ;;
    esac
  done
  [ "$#" -ge 4 ] && [ "$3" = -- ] || usage
  name="$1"; secs="$2"; shift 3
  [ "$#" -gt 0 ] || usage
  case "$name" in
    ''|[!A-Za-z0-9]*|*[!A-Za-z0-9_.-]*)
      fail "NAME must be 1-64 characters: alphanumeric, then alphanumerics, '.', '_' or '-'" ;;
  esac
  [ "${#name}" -le 64 ] || fail "NAME must be at most 64 characters"
  positive_integer "$secs" || fail "SECS must be a positive integer"
  positive_integer "$tasks" || fail "--tasks must be a positive integer"
  [ -n "$mem" ] || fail "--mem must not be empty"
  command -v systemd-run >/dev/null 2>&1 || fail "systemd-run --user is unavailable (systemd-run not found)"

  secs="$((10#$secs))"; tasks="$((10#$tasks))"
  cwd="$(pwd -P)" || fail "cannot determine the working directory"
  safe="${name//[^A-Za-z0-9_.-]/-}"
  unit="agent-${safe}-$(date +%s)-$$.service"
  if [ -n "$dir" ]; then jobdir="$dir"; else
    base="${AGENT_JOBS_DIR:-$HOME/.cache/concrete-agent-jobs}"
    jobdir="$base/$unit"
  fi
  while [ "${#jobdir}" -gt 1 ] && [ "${jobdir%/}" != "$jobdir" ]; do jobdir="${jobdir%/}"; done
  case "$jobdir" in */*) parent="${jobdir%/*}"; parent="${parent:-/}" ;; *) parent=. ;; esac
  mkdir -p -- "$parent" || fail "cannot create job directory parent: $parent"
  mkdir -- "$jobdir" || fail "job directory already exists or cannot be created: $jobdir"
  jobdir="$(CDPATH= cd "$jobdir" && pwd -P)" || fail "cannot resolve job directory"
  script="$(self_dir)/launch.sh"
  printf '%s\n' "$unit" > "$jobdir/unit" || exit 2
  printf '%s\n' "$(( $(date +%s) + secs ))" > "$jobdir/deadline" || exit 2
  printf '%q ' "$@" > "$jobdir/cmd" || exit 2
  printf '\n' >> "$jobdir/cmd" || exit 2
  printf '%s\0' "$@" > "$jobdir/argv" || exit 2

  if ! systemd-run --user --unit="$unit" \
      --property=MemoryMax="$mem" --property=TasksMax="$tasks" \
      --property=RuntimeMaxSec="$secs" --property=WorkingDirectory="$cwd" \
      --setenv=PATH="$PATH" --setenv=HOME="$HOME" \
      --setenv=AGENT_JOB_DIR="$jobdir" --setenv=AGENT_LAUNCH_SELF="$script" \
      /bin/bash -c 'exec /bin/bash "$$AGENT_LAUNCH_SELF" run' >/dev/null; then
    fail "systemd-run --user is unavailable or could not start $unit"
  fi
  printf 'UNIT=%s\nDIR=%s\nWAIT=bash %q wait %q\n' "$unit" "$jobdir" "$script" "$jobdir"
}

run_job() {
  local dir="${AGENT_JOB_DIR:-}" rc=0 tmp=""
  local -a argv=()
  [ -n "$dir" ] && [ -r "$dir/argv" ] || exit 2
  mapfile -d '' -t argv < "$dir/argv" || exit 2
  [ "${#argv[@]}" -gt 0 ] || exit 2
  "${argv[@]}" > "$dir/out.log" 2>&1 || rc=$?
  tmp="$dir/.status.$$"
  if printf '%s\n' "$rc" > "$tmp" && mv "$tmp" "$dir/status"; then
    exit 0
  fi
  rm -f "$tmp"
  exit 2
}

JOBDIR="" UNIT="" DEADLINE="" ACTION=wait DONE=0

load_job() {
  JOBDIR="$1"
  [ -n "$JOBDIR" ] && [ -d "$JOBDIR" ] || fail "job directory not found: $JOBDIR"
  [ -r "$JOBDIR/unit" ] && [ -r "$JOBDIR/deadline" ] || fail "job directory lacks unit or deadline: $JOBDIR"
  IFS= read -r UNIT < "$JOBDIR/unit" || fail "cannot read $JOBDIR/unit"
  IFS= read -r DEADLINE < "$JOBDIR/deadline" || fail "cannot read $JOBDIR/deadline"
  case "$DEADLINE" in ''|*[!0-9]*) fail "invalid deadline in $JOBDIR/deadline" ;; esac
  command -v systemctl >/dev/null 2>&1 || fail "systemctl is unavailable"
}

collect_unit() {
  systemctl --user reset-failed "$UNIT" >/dev/null 2>&1 || :
}

normal_exit() {
  local rc=""
  IFS= read -r rc < "$JOBDIR/status" || fail "cannot read $JOBDIR/status"
  case "$rc" in ''|*[!0-9]*) fail "invalid status in $JOBDIR/status" ;; esac
  [ "$rc" -le 255 ] || fail "invalid status in $JOBDIR/status"
  DONE=1
  printf 'JOB %s ENDED status=%s\n' "$UNIT" "$rc"
  if [ "$ACTION" = wait ] && [ -f "$JOBDIR/out.log" ]; then tail -n 40 "$JOBDIR/out.log"; fi
  collect_unit
  return "$rc"
}

unit_result() {
  local result=""
  result="$(systemctl --user show "$UNIT" --property=Result --value 2>/dev/null)" || result=""
  case "$result" in ''|success) result=unknown ;; esac
  printf '%s\n' "$result"
}

lost_exit() {
  local reason="" tmp=""
  DONE=1
  if [ -f "$JOBDIR/result" ]; then
    IFS= read -r reason < "$JOBDIR/result" || fail "cannot read $JOBDIR/result"
  else
    reason="$(unit_result)"
    tmp="$JOBDIR/.result.$$"
    if printf '%s\n' "$reason" > "$tmp" && mv "$tmp" "$JOBDIR/result"; then :
    else rm -f "$tmp"; fi
    collect_unit
  fi
  printf 'JOB %s ENDED without a status (killed, timed out or OOM): %s\n' "$UNIT" "$reason"
  return 125
}

inspect() {
  local state="" query_rc=0 now="" grace="${AGENT_WAIT_GRACE:-120}"
  DONE=0
  if [ -f "$JOBDIR/status" ]; then normal_exit; return "$?"; fi

  state="$(systemctl --user is-active "$UNIT" 2>&1)" || query_rc=$?
  case "$state" in
    active|activating|reloading|deactivating)
      now="$(date +%s)"
      case "$grace" in ''|*[!0-9]*) fail "AGENT_WAIT_GRACE must be a non-negative integer" ;; esac
      if [ "$now" -gt "$((DEADLINE + 10#$grace))" ]; then
        DONE=1
        printf 'JOB %s STILL RUNNING past its deadline\n' "$UNIT"
        return 124
      fi
      if [ "$ACTION" = status ]; then printf 'JOB %s RUNNING\n' "$UNIT"; fi
      return 0 ;;
    inactive|unknown|failed)
      if [ -f "$JOBDIR/status" ]; then normal_exit; return "$?"; fi
      lost_exit
      return 125 ;;
    *)
      fail "cannot query systemd for $UNIT (systemctl exit $query_rc): ${state:-no output}" ;;
  esac
}

watch() {
  local interval="${AGENT_WAIT_INTERVAL:-10}" rc=0
  case "$interval" in ''|*[!0-9]*) fail "AGENT_WAIT_INTERVAL must be a positive integer" ;; esac
  [ "$interval" -gt 0 ] || fail "AGENT_WAIT_INTERVAL must be a positive integer"
  load_job "$1"
  while :; do
    inspect; rc=$?
    [ "$DONE" -eq 1 ] && return "$rc"
    [ "$ACTION" = wait ] || return 0
    sleep "$interval"
  done
}

  export PATH="$job_path" HOME="$job_home" STUB_UNIT="$unit"

  expand_arg() {
    local rest="$1" out="" prefix="" name=""
    while [[ "$rest" == *[\$%]* ]]; do
      prefix="${rest%%[\$%]*}"
      out+="$prefix"

      case "$rest" in

        %%*) out+='%'; rest="${rest:2}" ;;

          rest="${rest:${#prefix}+1}" ;;

expect_rc() { [ "$RC" -eq "$1" ] && ok "$2" || { no "$2: expected exit $1, got $RC"; printf '%s\n' "$OUT" "$ERR" | sed 's/^/      /'; }; }
expect_out() { [ "$OUT" = "$1" ] && ok "$2" || { no "$2: unexpected stdout"; printf 'expected:\n%s\nactual:\n%s\n' "$1" "$OUT" | sed 's/^/      /'; }; }
file_line() { # file exact-line label
  if has_match -F -x -- "$2" < "$1"; then ok "$3"; else no "$3 (missing exact line: $2)"; fi
}
parse_start() {
  UNIT="$(printf '%s\n' "$OUT" | sed -n 's/^UNIT=//p')"

}
release_job() { # release a stub-blocked command and observe its wrapper finishing
  local n=0
  touch "$STUB_RELEASE_DIR/$UNIT"
  while { [ ! -f "$JOBDIR/status" ] || [ -f "$STUB_STATE_DIR/$UNIT/active" ]; } && [ "$n" -lt 50 ]; do
    sleep 0.1; n=$((n+1))
  done
  [ -f "$JOBDIR/status" ] && [ ! -f "$STUB_STATE_DIR/$UNIT/active" ] \
    && ok "$1 cleaned up" || no "$1 did not finish after its release"
}
unit_exit_line() { # exact-line label, after the stub records the job's own exit
  local n=0
  while [ ! -f "$STUB_STATE_DIR/$UNIT/exit" ] && [ "$n" -lt 50 ]; do
    sleep 0.1; n=$((n+1))
  done
  file_line "$STUB_STATE_DIR/$UNIT/exit" "$1" "$2"
}

## Playbooks

Project playbooks live in `.claude/commands/`. Every agent session, on the laptop or the server,
runs the same procedure by name instead of receiving a long prompt:

| command | what it does |
|---|---|
| `/fix-bug <N or description>` | reproduce, classify, repair or contain one bug on its own branch |
| `/roadmap-item <R-NNNN>` | carry one roadmap task to a landable candidate |
| `/file-bug <title>` | file a new bug with `scripts/gen/new_bug.sh` |
| `/creview` | Codex review of the branch through `scripts/review/review.sh` |
| `/rebase` | the safe rebase onto `origin/main` |
| `/land` | hand a validated branch to the landing train (`scripts/land/train.sh`) |

`/creview` and `/cstatus` carry a `c` prefix so they do not shadow Claude Code's built-in `/review`
and `/status`; a new playbook takes a name no built-in uses.

This file owns the rules the commands share. A command links here rather than restating them, so a
rule changes in one place.

## Rules

**Design questions** are decided by [PHILOSOPHY.md](docs/PHILOSOPHY.md). Any important design decision is
put to the owner by Claude or Codex, with a recommendation reasoned from docs/PHILOSOPHY.md.

**Owner decisions: never decide one.** The language decisions OD1 – OD157
([decisions.md](docs/decisions.md#owner-decisions)) are decided only by the project owner. No
agent, orchestrator or reviewer chooses, encodes, implements or provisionally ships any side of any
of them, inside a bug fix or anywhere else. Agents present options and a recommendation to the owner
and wait for an explicit answer. Behaviour already on main that took a side stays as it is, recorded
as a conflict, until the owner answers; nobody extends or reverts it meanwhile.
- The Codex review of every fix (`scripts/review/review.sh` asks it) also answers: "does this fix
  pick a side on any OD in docs/decisions.md?" If yes, or if the fix cannot be made without picking
  one, stop and report to the owner; do not land it. Recording an answer the owner explicitly gave
  is not picking a side; what the review checks then is in
  [REVIEW.md](docs/REVIEW.md#owner-decisions-choosing-versus-recording).

**Bugs.**
- Every bug gets a structural cause and a structural owner: the design fact that let it exist, and
  the roadmap task or pipeline stage that removes the whole class
  ([STRUCTURAL_CLASSES.md](legacy/docs/bugs/STRUCTURAL_CLASSES.md)). A patch without them is not a fix.
- To file a bug, run `scripts/gen/new_bug.sh`, which writes its record and runs the ledger
  generator. To log a change, add a `changelog.d/` fragment
  ([changelog.d/README.md](legacy/changelog.d/README.md)). Never hand-edit a generated view (the bug
  lists, the class table's bugs column, the generated bug dashboard, `CHANGELOG.md`,
  `Concrete/BuildIdentity.lean`); see [scripts/tests/README.md](legacy/scripts/tests/README.md),
  "Shared ledgers".
- Each bug's compiler area is derived from its fix commits ([AREAS.md](legacy/docs/bugs/AREAS.md);
  `python3 scripts/gen/bug_ledger.py report` for the stage, class, month, silent, how-found and
  time-to-fix tables, `--json` or `--sqlite PATH` for queries). Name the bug in the subject of each
  commit that fixes it (`bug NNN: ...`), and after committing a fix rerun
  `scripts/gen/refresh_generated.sh` and commit the regenerated AREAS.md. Add an `area:` line to a
  record only when the record shows the derived area is wrong
  ([README.md](legacy/docs/bugs/README.md#bug-areas)); never fill areas in by hand otherwise.
- For `compiler: new`, a silent defect (wrong code, unsound claim) is stopped at once by repair
  or fail-closed containment; a loud one is filed, pinned and owned. Legacy-compiler defects
  are recorded against `legacy-compiler-final`, never repaired, under
  [ROADMAP's defect disposition and frozen-compiler rule](ROADMAP.md#defect-disposition-rule).

**Who works on what** (owner, 2026-11-08, [decision](docs/decisions.md#decided-2026-11-08-eleven)).
- Claude's quota goes to the critical path: the spec, slice 0 and the front end. Mechanical work

**Branches.**
- Every branch's full clone is `~/projects/clones/<branch>`, removed after the branch lands (owner,
  2026-11-08; R-0619).
- One bug or one rule per branch, in its own worktree (`scripts/worktree-new.sh`,
  [concurrent work](#concurrent-work-one-worktree-per-writer)). This applies to all agent work now, not only once
  R-0545 closes. A branch that changes a language rule lands first and stays small; work that
  depends on it waits or rebases onto it.
- Rebase onto `origin/main` after every landing (`/rebase`), not only before your own landing, so a
  conflict or a changed rule shows up while the branch is small.
- Commit each validated slice. Push the branch to `wip/<branch>` at least every 5 minutes of work
  (`git push origin HEAD:refs/heads/wip/<branch>`); the hook's wip tier only scans for conflict
  markers.
- Never push to `main`, `ci/*` or the remote `fork`. Landings go to both `origin` and
  `lambdaclass`, only through the landing script (`scripts/land/train.sh`).
  `train.sh check` runs the checks before the push, and the push runs the root hook's full set again;
  the train's push to `ci/<name>` and both pushes of `land` are read back with `ls-remote` and
  retried when they did not move the ref (GitHub drops the connection during long hooks); `land` checks that both remotes are at
  the head ([LANDING.md](docs/LANDING.md#land)).
- After any push of your own whose hook ran gates, check that the remote ref moved
  (`git ls-remote origin refs/heads/<branch>`) and push again if it did not.

**Validation.**
- Locally, run only the impact-selected gates (pre-push runs the fast surface gates and the gates
  selected by what the push touches). For the full set, dispatch CI on the branch
  (`gh workflow run CI --ref <branch>`) or use the server (`concrete-remote wip/<branch> 'lake build
  && bash scripts/checks/run.sh'`); never a full local run on the laptop.
- Heavy legs default to the CI server (concrete-ci-2). Set `git config land.gatesHost concrete-ci-2`
  in the clone you land from, and `train.sh check` then runs its impact gates there, bound to the
  train head's SHA. The `ci` push still runs the root hook's full set; it reuses no remote result. An unreachable host is INCOMPLETE and blocks;
  run locally only with `check --local-gates` (docs/LANDING.md, "Gate host").
- At most 2 heavy runs (full suites, mutation campaigns, `lake build` of the whole tree) per machine.
  Queue behind a running one; continue light work meanwhile. Honour a user's explicit CPU limits.
- Run gates inside `nix develop`. A gate that passes by hand but fails under the hook: suspect an
  inherited `GIT_*` variable first.
- Record each result against the exact commit SHA it ran on.
- Read the obligation, not the prose: a header says what was true when it was written. Make gates
  assert properties, not counts, so an improvement does not read as a regression.

- File in the migrated ledger format with `scripts/gen/new_bug.sh`, which writes the `bug-ledger`

**Git safety.**
- Never pipe `git rebase` (or `git merge`, `git cherry-pick`) into anything: a pipe hides the stop.
  After every git operation, check that no merge, rebase, cherry-pick or revert is in progress
  (`git status`; `MERGE_HEAD`, `rebase-merge`, `rebase-apply` under `git rev-parse --git-dir`).
- No bare `git stash`; no interactive git (`-i`).
- Check a process's working directory (`lsof -a -p <pid> -d cwd`) before killing it; many processes
  on this machine belong to other repositories and other sessions.
- Remove a stale `index.lock` only when no process owns it (`lsof <path>/index.lock` is empty);
  otherwise wait and retry.
- Preserve other sessions' edits and untracked files. Never reset or clean a shared checkout.

## Concurrent work: one worktree per writer

**The default: every concurrent line of work gets its own git worktree.**

```sh
scripts/worktree-new.sh <name> [base-committish]
```

This is not an optimization. One working tree cannot serve two writers, because
the file system is the shared mutable state and neither writer can see the
other's intent.

### What went wrong when this was not the default

On 2026-07-31 two agents were found working in the same worktree
(`.claude/worktrees/r0442-proofcore-callee`). Every symptom was initially
misread as something else:

| symptom | what it was blamed on | what it actually was |
| --- | --- | --- |
| an edit to `ProofCore.lean` vanished, and the file dropped out of `git status` | the mutation harness | the mutation harness restoring a backup **over a concurrent edit**, then verifying against the pre-edit hash and reporting success |
| `origin/main` moved three times mid-session | stale fetches | the other agent pushing |
| two `push-both.sh` runs waiting on CI for the same SHA | a duplicated invocation | two agents each publishing |

The first row is the expensive one: work was destroyed *and* the tool reported
that nothing was wrong. A postcondition that compares against a stale baseline
confirms the corruption it was meant to catch.

### What a worktree does and does not isolate

| | |
| --- | --- |
| **Isolated** | working tree, index, `HEAD`, current branch |
| **Shared** | object store, remotes, **the stash stack**, branch namespace |

So worktrees fix file-level races, not coordination:

- Pushes must still be sequenced — hence the lock in `push-both.sh`.
- `git stash` is still unsafe across worktrees; bare `git stash` / `git stash pop`
  is banned repo-wide. Use a temporary WIP commit, or
  `git stash push -u -m "<unique-tag>"` and recover by SHA with `apply`, never
  `pop`.
- A branch name is a shared resource. `worktree-new.sh` refuses to reuse one
  rather than let `git` fail halfway, because the existing branch may belong to
  another writer.

### Enforcement is at the point of danger, not by head-count

Two heuristics for "is another agent here?" were measured and both cried wolf:

- matching process names (`pgrep -lf "codex|claude"`) reported **115** — every
  shell wrapper's command line contains the `.claude` snapshot path;
- counting processes whose CWD is the tree reported **7** in a worktree freshly
  created by a single agent — its own shells and background waiters all sit there.

Neither distinguishes "two writers" from "one agent working normally", and a
warning that fires on non-events trains the reader to ignore the one that
matters. So concurrency is caught where the signal is a fact:

- **`scripts/tests/test_mutation.sh`** records a hash of the content it itself
  wrote. At restore time, content that is neither its mutation nor the original
  means a third party wrote the file: it **refuses to restore**, preserves their
  version under `CONCURRENT-EDIT/`, keeps its own backup for reconciliation, and
  fails the run. It cannot silently overwrite an edit it did not make.
- **`scripts/push-both.sh`** takes an exclusive lock in the **common** git dir
  (`git rev-parse --git-common-dir`), not the worktree — remotes are shared, so a
  per-worktree lock would miss two worktrees publishing at once.

### Working while something long is running

Long-running work does not always require an idle tree. Distinguish the phases:

| phase | tree must be stable? |
| --- | --- |
| pre-push hook running gates | **yes** — gates read the working tree |
| `run_ci_gates_local.sh` | **yes** — same reason |
| `test_mutation.sh` | **yes** — it rewrites source in place |
| `push-both.sh` waiting for remote CI | **no** — it only polls `gh` |

The CI wait touches no files, so work can continue during it — in another
worktree. Treating the whole publish as tree-freezing is over-caution; treating
the hook phase as safe is the error that costs a run.

### Landing, review and load (development throughput)

On 2026-10-22 a finished branch took 6 – 10 h to reach main for about 1 h of work.
The [development throughput](ROADMAP.md#development-throughput) track in the
roadmap owns the repair. These rules apply to every writer now:

- **One bug or one rule per branch** (R-0545). A branch that changes a language or
  checker rule lands first and small, with the migrations of main's fixtures and
  nothing else. A branch that needs two rules is two branches.
- **Review per slice, delta after the first pass** (R-0544). After the first full
  review, each round reviews only the diff since the previous round. Past the risk
  cap (the round caps under **Review** above),
  split the slice. Review ownership and memory-safety work with neutral prompts and
  piecewise diffs.
- **At most 2 heavy local runs per machine** (R-0543). Full gate sets, closure-mode
  runs and mutation campaigns count as heavy. Agents run the fast and
  impact-selected gates; full sets go to the servers (R-0541) or to CI. The
  machine-wide semaphore `scripts/checks/lib/heavy_slots.sh` holds the full runners,
  `run_tests.sh --full` and the mutation drivers to two slots; for any other heavy
  command, check the load and queue behind a running heavy run instead of starting a third.
- **Ready branches land together** (R-0539). Ready branches are integrated into one
  train candidate with one CI run, rather than each rebasing onto the last landing,
  through `scripts/land/train.sh` ([LANDING.md](docs/LANDING.md)). A train built by hand
  follows the same rules: one integrated candidate, results recorded against its
  exact SHA, and bisection by member only on red.

### Running the full gate set on the server

The full set runs on a server (or in CI), never on the laptop:

```
~/bin/concrete-remote <pushed-ref> \
  'lake build && bash scripts/checks/run.sh'
```

`concrete-remote` checks the ref out as a `git clone --shared` (not a worktree:
two mutation-driver gates refuse worktrees) and sets the runner's default width
to the measured best for that host (`CONCRETE_GATE_JOBS_DEFAULT`; override with
`CONCRETE_REMOTE_JOBS=N`, or pass `JOBS=N` in the command). The measurements and
the critical path were taken on concrete-ci-1, since deleted (2026-10-23), and are
in [GATE_PROFILE.md](legacy/docs/project/GATE_PROFILE.md#parallel-scaling-on-concrete-ci-1-r-0546-step-4).

**A gate must be safe to run beside every other gate.** In a pass the gates run
JOBS-wide in one checkout, and several passes run on one host. So a gate:

- writes scratch only under `mktemp -d` (or a `.$$` name), never a fixed
  `/tmp/<name>` — `check_gate_hygiene.sh` refuses fixed `/tmp` paths;
- never edits a tracked file in place, not even to restore it a moment later.
  A probe that perturbs a source runs in a private copy of the checkout
  (`run_fast_surface_gates.sh --mutate`, `check_attestation_manifest.sh`). An
  in-place edit of a `.lean` file makes every concurrent `require_fresh_binary`
  rebuild the shared compiler from it;
- runs sub-steps concurrently only under one lock it already holds (fresh.sh
  refuses a second concurrent acquisition) and records each sub-step's exit
  status, so a lost result is a failure, not a pass.

A pool failure that passes on the runner's sequential re-check is listed under
"Recovered under sequential re-run" and in `.ci-gate-timings.tsv` (stage
`pool`, verdict `FAIL`, then stage `recheck`). Treat it as a race in that gate
to fix, not as noise.

### Killing a publish does not un-publish it

`push-both.sh` runs `git push` as a CHILD process. Killing the script does not
kill that child, and a `git push` already in flight will complete.

Measured 2026-07-31: a publish was killed during its pre-push hook, `git ls-remote`
showed the primary unchanged, and that was read as "nothing was published". The
`git push` child was still running; it finished moments later and advanced the
primary. The next publish was then rejected as non-fast-forward — harmless here,
but the reasoning behind the kill was a race read as a guarantee.

So: a ref check taken *at* the moment of the kill proves nothing about a push
that has already started. If a publish must be abandoned, re-check the remote
AFTER the process tree is gone (`pgrep -f "git push"` clear), and treat the
remote's actual state as the answer rather than the state you saw before killing.

### Background agent jobs always have a watcher

Start every background writer, reviewer or gate with `scripts/agent/launch.sh start`, then
immediately run the printed `WAIT` command as your own background task so the job's end re-invokes
you. Never start a detached unit without its watcher. A writer gets one attempt only: a killed or
timed-out job is investigated, never automatically re-run. Each start exclusively creates a new job
directory (an existing `--dir` is refused) and preserves argv through a file rather than systemd's
command expansion. A missing status returns 125 with systemd's retained result when known; a bus or
`systemctl` query failure is an operational error (2), not a completed job.

### Orchestrating a publish: never infer state from process names

`pgrep -f "push-both"` matches the WAITER'S OWN command line, which contains that
string. Every `until ! pgrep -f "push-both"; do sleep 30; done` loop therefore
waits on itself forever, and a status check written the same way reports "publish
running" when nothing is. Measured 2026-08-01: six background tasks were stuck on
this at once, and the reported state was wrong for as long as they ran. It is the
same failure as counting `pgrep -lf "codex|claude"` and getting 115 — a
process-name match catches the matcher.

Do this instead:

* capture the launched PID and `wait "$pid"`;
* verify completion by checking the EXACT REMOTE SHA (`git ls-remote`), which is
  the fact you actually care about;
* query CI for that SHA (`gh run list --commit <full-sha>` — the full SHA; the
  short form returns nothing);
* never infer state from a process-name match.

For a one-off inspection, `ps -eo command | grep -c "[p]ush-both.sh"` excludes
itself via the bracket, but a ref check is still the better answer.

### Background agent jobs get a bounded watcher (2026-11-08)

`scripts/agent/launch.sh` starts a writer, reviewer or gate once as a bounded transient systemd
user unit and records its output and exit status. The agent runs the printed `WAIT` command as its
own background task, so completion re-invokes the agent instead of leaving a finished job unnoticed.
A lost unit and a deadline overrun are distinct non-passing results, and writers are never retried
automatically. Job directories are exclusive, command arguments survive systemd expansion byte for
byte, and the quoted `WAIT` command is safe for paths containing shell metacharacters. Lost units
retain their timeout/signal/OOM result where systemd provides one; query failures are operational
errors. Stub-backed controls cover these behaviours and all watcher outcomes.

#!/usr/bin/env bash
# The gate environment guard. Every gate sources this first:
#
#   source "$(dirname "${BASH_SOURCE[0]}")/lib/gate_env.sh" || exit 2
#
# Gates run in three places: the dev shell, Linux CI runners and the macOS CI runner. When each took
# coreutils, sed, grep, python and the rest from whatever host it landed on, a gate could pass on one
# and fail on another for reasons unrelated to what it tests: macOS has no `timeout`, and BSD `sed -i`,
# `stat`, `date` and `readlink` take other flags. flake.nix now defines that userland once (the
# `gates` shell), CI runs every step inside it, and the dev shells include it. Each of those shells
# exports CONCRETE_GATES_SHELL=1; a gate started anywhere else refuses here, before it can produce a
# verdict about the wrong environment.
#
# Use `nix develop .#gates` (no Lean; what CI uses, with elan's Lean on PATH) or `nix develop` (the
# dev shell, with its own Lean). An entry point that must start outside both, like the pre-push
# hook, re-executes itself inside `nix develop` before it runs a gate.
#
# check_gate_hygiene.sh proves every gate sources this file.

if [ "${CONCRETE_GATES_SHELL:-}" != 1 ]; then
  echo "error: ${0##*/} refuses to run outside the gate shell: run inside nix develop .#gates (CI) or nix develop" >&2
  exit 2
fi

#!/usr/bin/env bash
# Bounded runs: a timeout is INCOMPLETE, never a failure and never a pass.
#
# The rule (docs/project/PROMOTION_PIPELINE.md, result vocabulary): a test that exceeds its time budget
# has produced no observation. Under machine load a freshly linked binary or a compile can overrun
# a budget sized for an idle machine (test_ssa.sh once reported hundreds of 5-second alarms as
# failures), so a timeout is re-run once, alone, with a larger budget:
#   - the re-run completes      -> its result is judged normally (pass or FAIL), recorded "recovered";
#   - the re-run times out too  -> INCOMPLETE: not a pass, not a failure. A gate with an incomplete
#                                  result exits nonzero, and a qualifying run contains none.
#
# Each attempt runs under lib/bounded_exec.py, which makes the command the leader of a new process
# group, reports its outcome through a status file (never through the command's own streams, so
# nothing the command prints can fake or hide a timeout) and, when the budget expires, sends SIGTERM
# and then SIGKILL to the whole group, so no descendant outlives the attempt into the retry.
#
# Sourcing (`BOUNDED_PARENT="$TMP"; source scripts/checks/lib/bounded.sh`) gives the gate PRIVATE
# state: a fresh directory (mktemp under BOUNDED_PARENT, else $TMPDIR) with an outcome file and a
# log. Every sourcing creates its own directory, so nested or parallel gates never share state.
# With BOUNDED_PARENT under the gate's own scratch directory, its cleanup removes the state too.
#
#   bounded_run [-i STDIN_FILE] [-r RETRY_SECS] SECS -- CMD [ARGS...]
#     Runs CMD (an executable, not a shell function). Its stdout and stderr are buffered per
#     attempt and only a COMPLETED attempt's output is written: an incomplete run writes nothing,
#     so output-matching checks never pass on the partial output of a run that hung. Without -i the
#     command inherits stdin, which a re-run cannot replay: callers that feed input pass -i.
#     Returns CMD's status, or 124 when it timed out on both attempts or the runner reported no
#     outcome. SECS and RETRY_SECS are positive decimal seconds. A command may itself exit
#     124, so test with `bounded_is_incomplete "$rc"`, which also reads the outcome bounded_run
#     recorded (this works across `( cd dir && bounded_run ... )` subshells; run one bounded_run
#     at a time per sourcing). RETRY_SECS defaults to BOUNDED_RETRY_FACTOR (2) times SECS.
#   bounded_summary
#     Lists this gate's recovered and incomplete runs; gates print it before their final tally.
#   bounded_watchdog SECS  -> sets the array TO for the watchdog form: "${TO[@]}" CMD [ARGS...]
#     runs CMD through `bash bounded.sh SECS` in a separate process with the same retry; on a second
#     timeout it writes no command output, prints "INCOMPLETE: ..." on stderr and exits 124. Its
#     recovered and incomplete lines go to this gate's log (handed over on its command line).
#   bounded_gate_status
#     The end-of-gate verdict for a gate using the watchdog form: lists recovered, incomplete and
#     runner-failed runs, removes the state directory, and returns 1 when any run was incomplete or
#     the runner failed, so the gate exits nonzero whatever its own checks concluded from a hung
#     command's empty output. Last line:
#       bounded_gate_status && [ "$FAIL" -eq 0 ]
#
# If the runner itself fails (no outcome reported), the command's output is discarded and the run
# is incomplete (status 124, a "runner-failed" log line): never a pass. If the runner is cancelled (the
# gate is interrupted or terminated), it kills the command's group first.
#
# Without python3 commands run directly with no watchdog: one warning when the gate sources this
# file, never inside a command's output, and the watchdog form then runs commands directly too.
# Such a run is never incomplete.

BOUNDED_RETRY_FACTOR="${BOUNDED_RETRY_FACTOR:-2}"
if [[ "$BOUNDED_RETRY_FACTOR" =~ ^[0-9]+(\.[0-9]+)?$ ]] && awk -v f="$BOUNDED_RETRY_FACTOR" 'BEGIN { exit !(f + 0 >= 1) }'; then :
else echo "bounded.sh: BOUNDED_RETRY_FACTOR must be a number >= 1; using 2" >&2; BOUNDED_RETRY_FACTOR=2; fi
# _bounded_secs_ok S: S is a positive decimal number of seconds (fractions allowed).
_bounded_secs_ok() { [[ "$1" =~ ^[0-9]+(\.[0-9]+)?$ ]] && awk -v s="$1" 'BEGIN { exit !(s + 0 > 0) }'; }
# Fixed-point, trailing zeros trimmed: never scientific notation, which _bounded_secs_ok rejects.
_bounded_mul() { awk -v s="$1" -v f="$2" 'BEGIN { r = sprintf("%.6f", s * f); sub(/0+$/, "", r); sub(/\.$/, "", r); print r }'; }
BOUNDED_SH="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)/$(basename "${BASH_SOURCE[0]}")"
BOUNDED_EXEC="$(dirname "$BOUNDED_SH")/bounded_exec.py"
BOUNDED_DIR="$(mktemp -d "${BOUNDED_PARENT:-${TMPDIR:-/tmp}}/bounded.XXXXXX")"
BOUNDED_OUTCOME_FILE="$BOUNDED_DIR/outcome"
BOUNDED_LOG="$BOUNDED_DIR/log"
# The watchdog form appends to its caller's log, handed over explicitly on its command line.
if [ "${BASH_SOURCE[0]}" = "$0" ]; then
  # A standalone watchdog removes its state however it ends.
  trap 'rm -rf "$BOUNDED_DIR"' EXIT
  [ -z "${BOUNDED_WATCHDOG_LOG:-}" ] || BOUNDED_LOG="$BOUNDED_WATCHDOG_LOG"
fi
: >> "$BOUNDED_LOG"
BOUNDED_HAVE_WATCHDOG=1
if ! command -v python3 >/dev/null 2>&1; then
  BOUNDED_HAVE_WATCHDOG=0
  [ "${BASH_SOURCE[0]}" = "$0" ] || echo "  warn python3 not found — commands run without a hang watchdog" >&2
fi

bounded_is_incomplete() {
  [ "$1" = 124 ] && [ "$(cat "$BOUNDED_OUTCOME_FILE" 2>/dev/null)" = incomplete ]
}

bounded_run() {
  local stdin_file="" retry="" secs="" rc tries=0 budget tmp outcome
  while [ $# -gt 0 ]; do
    case "$1" in
      -i) stdin_file="$2"; shift 2 ;;
      -r) retry="$2"; shift 2 ;;
      --) shift; break ;;
      *) if [ -z "$secs" ]; then secs="$1"; shift; else break; fi ;;
    esac
  done
  [ -n "$secs" ] && [ $# -gt 0 ] || { echo "bounded_run: usage: bounded_run [-i FILE] [-r SECS] SECS -- CMD..." >&2; return 2; }
  [ -n "$retry" ] || retry="$(_bounded_mul "$secs" "$BOUNDED_RETRY_FACTOR")"
  if ! _bounded_secs_ok "$secs" || ! _bounded_secs_ok "$retry"; then
    echo "bounded_run: budgets must be positive numbers of seconds (got $secs, retry $retry)" >&2; return 2
  fi
  echo done > "$BOUNDED_OUTCOME_FILE"
  if [ "$BOUNDED_HAVE_WATCHDOG" != 1 ]; then
    if [ -n "$stdin_file" ]; then "$@" < "$stdin_file"; else "$@"; fi
    return $?
  fi
  tmp="$(mktemp -d "$BOUNDED_DIR/run.XXXXXX")"
  budget="$secs"
  while :; do
    tries=$((tries + 1))
    rm -f "$tmp/status"
    if [ -n "$stdin_file" ]; then
      python3 -I "$BOUNDED_EXEC" --timeout "$budget" --kill-after "${BOUNDED_KILL_AFTER:-10}" --status "$tmp/status" -- "$@" < "$stdin_file" > "$tmp/out" 2> "$tmp/err"
    else
      python3 -I "$BOUNDED_EXEC" --timeout "$budget" --kill-after "${BOUNDED_KILL_AFTER:-10}" --status "$tmp/status" -- "$@" > "$tmp/out" 2> "$tmp/err"
    fi
    outcome="$(cat "$tmp/status" 2>/dev/null)"
    case "$outcome" in
      "exit "*) break ;;
      timeout) [ "$tries" = 1 ] || break; budget="$retry" ;;
      *) outcome=runner-failed; break ;;
    esac
  done
  if [ "$outcome" = timeout ]; then
    echo incomplete > "$BOUNDED_OUTCOME_FILE"
    echo "incomplete ${secs}s+${retry}s $*" >> "$BOUNDED_LOG"
    rc=124
  elif [ "$outcome" = runner-failed ]; then
    # The runner reported nothing (it failed or was cancelled): no observation, so the run is
    # incomplete exactly as a double timeout is (status 124, bounded_is_incomplete true).
    echo "bounded_run: the runner reported no outcome for: $*" >&2
    echo incomplete > "$BOUNDED_OUTCOME_FILE"
    echo "runner-failed ${secs}s $*" >> "$BOUNDED_LOG"
    rc=124
  else
    cat "$tmp/out"; cat "$tmp/err" >&2
    rc="${outcome#exit }"
    [ "$tries" = 2 ] && echo "recovered ${secs}s $*" >> "$BOUNDED_LOG"
  fi
  rm -rf "$tmp"
  return "$rc"
}

bounded_summary() {
  local nrec ninc
  nrec=$(grep -c '^recovered' "$BOUNDED_LOG" 2>/dev/null || true); nrec=${nrec:-0}
  ninc=$(grep -c '^incomplete\|^runner-failed' "$BOUNDED_LOG" 2>/dev/null || true); ninc=${ninc:-0}
  [ "$nrec" -gt 0 ] || [ "$ninc" -gt 0 ] || return 0
  echo "Bounded runs: $nrec recovered (timed out, then completed alone), $ninc incomplete (timed out twice, or the runner failed):"
  sed 's/^/  /' "$BOUNDED_LOG"
}

bounded_watchdog() {
  if [ "$BOUNDED_HAVE_WATCHDOG" = 1 ]; then
    TO=(env "BOUNDED_WATCHDOG_LOG=$BOUNDED_LOG" "BOUNDED_PARENT=$BOUNDED_DIR" bash "$BOUNDED_SH" "$1")
  else
    TO=(env)  # no python3: run commands directly (the gate warned once when it sourced this file)
  fi
}

bounded_gate_status() {
  local ninc
  bounded_summary
  ninc=$(grep -c '^incomplete\|^runner-failed' "$BOUNDED_LOG" 2>/dev/null || true); ninc=${ninc:-0}
  [ "$ninc" -eq 0 ] || echo "INCOMPLETE: $ninc command(s) timed out twice or lost their runner: this run is incomplete, not passed"
  rm -rf "$BOUNDED_DIR"
  [ "$ninc" -eq 0 ]
}

# Watchdog form: `bash bounded.sh SECS CMD...` (through bounded_watchdog's TO array).
if [ "${BASH_SOURCE[0]}" = "$0" ]; then
  [ $# -ge 2 ] || { echo "usage: bash $0 SECS CMD [ARGS...]" >&2; exit 2; }
  secs="$1"; shift
  bounded_run "$secs" -- "$@"; rc=$?
  if bounded_is_incomplete "$rc"; then
    echo "INCOMPLETE: timed out twice (${secs}s, then $(_bounded_mul "$secs" "$BOUNDED_RETRY_FACTOR")s alone) or lost its runner: $*" >&2
  fi
  exit "$rc"
fi

## Rules

**Design questions** are decided by [PHILOSOPHY.md](docs/PHILOSOPHY.md). Any important design decision is
put to the owner by Claude or Codex, with a recommendation reasoned from docs/PHILOSOPHY.md.

**Owner decisions: never decide one.** The language decisions OD1 – OD157
([decisions.md](docs/decisions.md#owner-decisions)) are decided only by the project owner. No
agent, orchestrator or reviewer chooses, encodes, implements or provisionally ships any side of any
of them, inside a bug fix or anywhere else. Agents present options and a recommendation to the owner
and wait for an explicit answer. Behaviour already on main that took a side stays as it is, recorded
as a conflict, until the owner answers; nobody extends or reverts it meanwhile.

  pick a side on any OD in docs/decisions.md?" If yes, or if the fix cannot be made without picking

  is not picking a side; what the review checks then is in
  [REVIEW.md](docs/REVIEW.md#owner-decisions-choosing-versus-recording).

**Bugs.**

## Concurrent work: one worktree per writer

**The default: every concurrent line of work gets its own git worktree.**

```sh
scripts/worktree-new.sh <name> [base-committish]
```

This is not an optimization. One working tree cannot serve two writers, because
the file system is the shared mutable state and neither writer can see the
other's intent.

### What went wrong when this was not the default

On 2026-07-31 two agents were found working in the same worktree
(`.claude/worktrees/r0442-proofcore-callee`). Every symptom was initially
misread as something else:

| symptom | what it was blamed on | what it actually was |
| --- | --- | --- |
| an edit to `ProofCore.lean` vanished, and the file dropped out of `git status` | the mutation harness | the mutation harness restoring a backup **over a concurrent edit**, then verifying against the pre-edit hash and reporting success |
| `origin/main` moved three times mid-session | stale fetches | the other agent pushing |
| two `push-both.sh` runs waiting on CI for the same SHA | a duplicated invocation | two agents each publishing |

The first row is the expensive one: work was destroyed *and* the tool reported
that nothing was wrong. A postcondition that compares against a stale baseline
confirms the corruption it was meant to catch.

### What a worktree does and does not isolate

| | |
| --- | --- |
| **Isolated** | working tree, index, `HEAD`, current branch |
| **Shared** | object store, remotes, **the stash stack**, branch namespace |

So worktrees fix file-level races, not coordination:

- Pushes must still be sequenced — hence the lock in `push-both.sh`.
- `git stash` is still unsafe across worktrees; bare `git stash` / `git stash pop`
  is banned repo-wide. Use a temporary WIP commit, or
  `git stash push -u -m "<unique-tag>"` and recover by SHA with `apply`, never
  `pop`.
- A branch name is a shared resource. `worktree-new.sh` refuses to reuse one
  rather than let `git` fail halfway, because the existing branch may belong to
  another writer.

### Enforcement is at the point of danger, not by head-count

Two heuristics for "is another agent here?" were measured and both cried wolf:

- matching process names (`pgrep -lf "codex|claude"`) reported **115** — every
  shell wrapper's command line contains the `.claude` snapshot path;
- counting processes whose CWD is the tree reported **7** in a worktree freshly
  created by a single agent — its own shells and background waiters all sit there.

Neither distinguishes "two writers" from "one agent working normally", and a
warning that fires on non-events trains the reader to ignore the one that
matters. So concurrency is caught where the signal is a fact:

- **`scripts/tests/test_mutation.sh`** records a hash of the content it itself
  wrote. At restore time, content that is neither its mutation nor the original
  means a third party wrote the file: it **refuses to restore**, preserves their
  version under `CONCURRENT-EDIT/`, keeps its own backup for reconciliation, and
  fails the run. It cannot silently overwrite an edit it did not make.
- **`scripts/push-both.sh`** takes an exclusive lock in the **common** git dir
  (`git rev-parse --git-common-dir`), not the worktree — remotes are shared, so a
  per-worktree lock would miss two worktrees publishing at once.

### Working while something long is running

Long-running work does not always require an idle tree. Distinguish the phases:

| phase | tree must be stable? |
| --- | --- |
| pre-push hook running gates | **yes** — gates read the working tree |
| `run_ci_gates_local.sh` | **yes** — same reason |
| `test_mutation.sh` | **yes** — it rewrites source in place |
| `push-both.sh` waiting for remote CI | **no** — it only polls `gh` |

The CI wait touches no files, so work can continue during it — in another
worktree. Treating the whole publish as tree-freezing is over-caution; treating
the hook phase as safe is the error that costs a run.

### Landing, review and load (development throughput)

On 2026-10-22 a finished branch took 6 – 10 h to reach main for about 1 h of work.
The [development throughput](ROADMAP.md#development-throughput) track in the
roadmap owns the repair. These rules apply to every writer now:

- **One bug or one rule per branch** (R-0545). A branch that changes a language or
  checker rule lands first and small, with the migrations of main's fixtures and
  nothing else. A branch that needs two rules is two branches.
- **Review per slice, delta after the first pass** (R-0544). After the first full
  review, each round reviews only the diff since the previous round. Past the risk
  cap (the round caps under **Review** above),
  split the slice. Review ownership and memory-safety work with neutral prompts and
  piecewise diffs.
- **At most 2 heavy local runs per machine** (R-0543). Full gate sets, closure-mode
  runs and mutation campaigns count as heavy. Agents run the fast and
  impact-selected gates; full sets go to the servers (R-0541) or to CI. The
  machine-wide semaphore `scripts/checks/lib/heavy_slots.sh` holds the full runners,
  `run_tests.sh --full` and the mutation drivers to two slots; for any other heavy
  command, check the load and queue behind a running heavy run instead of starting a third.
- **Ready branches land together** (R-0539). Ready branches are integrated into one
  train candidate with one CI run, rather than each rebasing onto the last landing,
  through `scripts/land/train.sh` ([LANDING.md](docs/LANDING.md)). A train built by hand
  follows the same rules: one integrated candidate, results recorded against its
  exact SHA, and bisection by member only on red.

The full set runs on a server (or in CI), never on the laptop:


`concrete-remote` checks the ref out as a `git clone --shared` (not a worktree:
two mutation-driver gates refuse worktrees) and sets the runner's default width
to the measured best for that host (`CONCRETE_GATE_JOBS_DEFAULT`; override with
`CONCRETE_REMOTE_JOBS=N`, or pass `JOBS=N` in the command). The measurements and

**A gate must be safe to run beside every other gate.** In a pass the gates run
JOBS-wide in one checkout, and several passes run on one host. So a gate:

- writes scratch only under `mktemp -d` (or a `.$$` name), never a fixed
  `/tmp/<name>` — `check_gate_hygiene.sh` refuses fixed `/tmp` paths;
- never edits a tracked file in place, not even to restore it a moment later.
  A probe that perturbs a source runs in a private copy of the checkout
  (`run_fast_surface_gates.sh --mutate`, `check_attestation_manifest.sh`). An
  in-place edit of a `.lean` file makes every concurrent `require_fresh_binary`
  rebuild the shared compiler from it;
- runs sub-steps concurrently only under one lock it already holds (fresh.sh
  refuses a second concurrent acquisition) and records each sub-step's exit
  status, so a lost result is a failure, not a pass.

A pool failure that passes on the runner's sequential re-check is listed under
"Recovered under sequential re-run" and in `.ci-gate-timings.tsv` (stage
`pool`, verdict `FAIL`, then stage `recheck`). Treat it as a race in that gate
to fix, not as noise.

### Killing a publish does not un-publish it

`push-both.sh` runs `git push` as a CHILD process. Killing the script does not
kill that child, and a `git push` already in flight will complete.

Measured 2026-07-31: a publish was killed during its pre-push hook, `git ls-remote`
showed the primary unchanged, and that was read as "nothing was published". The
`git push` child was still running; it finished moments later and advanced the
primary. The next publish was then rejected as non-fast-forward — harmless here,
but the reasoning behind the kill was a race read as a guarantee.

So: a ref check taken *at* the moment of the kill proves nothing about a push
that has already started. If a publish must be abandoned, re-check the remote
AFTER the process tree is gone (`pgrep -f "git push"` clear), and treat the
remote's actual state as the answer rather than the state you saw before killing.

### Background agent jobs always have a watcher

Start every background writer, reviewer or gate with `scripts/agent/launch.sh start`, then
immediately run the printed `WAIT` command as your own background task so the job's end re-invokes
you. Never start a detached unit without its watcher. A writer gets one attempt only: a killed or
timed-out job is investigated, never automatically re-run. Each start exclusively creates a new job
directory (an existing `--dir` is refused) and preserves argv through a file rather than systemd's
command expansion. A missing status returns 125 with systemd's retained result when known; a bus or
`systemctl` query failure is an operational error (2), not a completed job.

### Orchestrating a publish: never infer state from process names

`pgrep -f "push-both"` matches the WAITER'S OWN command line, which contains that
string. Every `until ! pgrep -f "push-both"; do sleep 30; done` loop therefore
waits on itself forever, and a status check written the same way reports "publish
running" when nothing is. Measured 2026-08-01: six background tasks were stuck on
this at once, and the reported state was wrong for as long as they ran. It is the
same failure as counting `pgrep -lf "codex|claude"` and getting 115 — a
process-name match catches the matcher.

Do this instead:

* capture the launched PID and `wait "$pid"`;
* verify completion by checking the EXACT REMOTE SHA (`git ls-remote`), which is
  the fact you actually care about;
* query CI for that SHA (`gh run list --commit <full-sha>` — the full SHA; the
  short form returns nothing);
* never infer state from a process-name match.

For a one-off inspection, `ps -eo command | grep -c "[p]ush-both.sh"` excludes
itself via the bracket, but a ref check is still the better answer.

#!/usr/bin/env bash
# THE ROOT HOLDS ONLY THE DAY-ONE SET (ROADMAP R-0558). Every tracked top-level entry, and every
# first-level entry under docs/ and scripts/, must be listed in scripts/checks/root_inventory.txt,
# and every listed entry must exist. A negative control runs the same judgment on a synthetic
# listing first.
set -uo pipefail
source "$(dirname "${BASH_SOURCE[0]}")/lib/gate_env.sh" || exit 2
ROOT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)"
cd "$ROOT_DIR"
LIST=scripts/checks/root_inventory.txt
PASS=0; FAIL=0
ok(){ echo "  ok   $1"; PASS=$((PASS+1)); }
no(){ echo "  FAIL $1"; FAIL=$((FAIL+1)); }

# judge LIST: reads tracked paths on stdin, prints one problem per line.
judge() {
  python3 -I -c '
import sys
want = {l.strip() for l in open(sys.argv[1]) if l.strip() and not l.startswith("#")}
have = set()
for p in (l.rstrip("\n") for l in sys.stdin):
    if not p: continue
    parts = p.split("/")
    have.add(parts[0])
    if parts[0] in ("docs", "scripts") and len(parts) > 1:
        have.add(parts[0] + "/" + parts[1])
for e in sorted(have - want): print("not in the day-one set: " + e)
for e in sorted(want - have): print("listed but missing: " + e)
' "$1"
}

echo "=== negative controls ==="
TMP="$(mktemp -d)" || exit 2
trap 'rm -rf "$TMP"' EXIT
printf 'a\nb\ndocs\ndocs/x.md\n' > "$TMP/list"
[ -z "$(printf 'a\nb/c\ndocs/x.md\n' | judge "$TMP/list")" ] && ok "control: exactly the listed set passes" || no "control: listed set refused"
[ -n "$(printf 'a\nb/c\ndocs/x.md\nstray\n' | judge "$TMP/list")" ] && ok "control: an unlisted top-level entry is refused" || no "control: stray accepted"
[ -n "$(printf 'a\nb/c\ndocs/x.md\ndocs/y.md\n' | judge "$TMP/list")" ] && ok "control: an unlisted docs/ entry is refused" || no "control: docs stray accepted"
[ -n "$(printf 'a\ndocs/x.md\n' | judge "$TMP/list")" ] && ok "control: a missing listed entry is refused" || no "control: missing accepted"

echo "=== the tracked root against $LIST ==="
[ -f "$LIST" ] || { no "$LIST is missing"; echo "root_inventory: PASS=$PASS FAIL=$FAIL"; exit 1; }
out="$(git ls-files --cached | judge "$LIST")"
[ -z "$out" ] && ok "the root holds exactly the day-one set" || { no "the root differs from the day-one set:"; echo "$out" | sed 's/^/      /'; }
echo "root_inventory: PASS=$PASS FAIL=$FAIL"
[ "$FAIL" -eq 0 ]

#!/usr/bin/env bash
# has_match [GREP_OPTION...] PATTERN: does the input contain a line grep selects? (bug 283)
#
#   has_match -F "E0217" <<<"$OUT"            # captured text: a here-string, no producer process
#   "$COMPILER" f.con --report x | has_match "status: proved"     # a streaming producer
#
# It answers what `grep -q` answers, without grep -q's early exit. `grep -q` stops reading at its
# first match; a producer still writing into the pipe then dies of SIGPIPE (status 141), and under
# `set -o pipefail` the pipeline reports that death instead of grep's 0. A positive leg then FAILs
# although the pattern is there, and a negated leg (`... && no || ok`) passes although the forbidden
# text is there. has_match reads ALL of its input before it answers (`grep -c`, whose output is a
# capture, never /dev/null, which GNU grep would treat like -q), so the producer always finishes
# writing and pipefail sees only real failures: a producer that fails still fails the pipeline.
#
# Status: 0 a line matched; 1 no line matched. Anything else is no answer at all: a grep error (an
# invalid pattern, an unreadable input) or an option that would stop grep early or replace its
# answer (-q, -m, -l, -L, -c, -V, anywhere in the arguments: GNU grep reads options after the
# pattern too), a file operand (has_match reads standard input only), or a long option outside the
# short list below (GNU grep takes abbreviations, so `--qui` is
# --quiet), prints the reason and stops the script. From the script's own shell that
# is `exit 2`. From a pipeline stage or a substitution, a subshell whose status a negated leg would
# read as "absent", it is SIGKILL to the script (status 137): a signal the script cannot trap and
# carry on past, so neither polarity of leg can turn the error into a verdict.
#
# check_gate_hygiene.sh refuses a pipe into a short-circuiting grep (`| grep -q`, `-m`, `-l`, `-L`)
# and a `| head` feeding has_match, and proves every script that calls has_match loads this file.

has_match() {
  local _hm_a _hm_n _hm_rc _hm_c _hm_j _hm_take=0 _hm_opts=1 _hm_pat=0 _hm_ops=0
  for _hm_a in "$@"; do
    if [ "$_hm_take" = 1 ]; then _hm_take=0; continue; fi   # an option's separate argument
    if [ "$_hm_opts" = 0 ]; then _hm_ops=$((_hm_ops + 1)); continue; fi
    case "$_hm_a" in
      --) _hm_opts=0 ;;
      # Long options only spelled in full and only these: GNU grep also accepts any unambiguous
      # abbreviation (`--qui` is --quiet), so a list of refused names would be bypassable.
      --extended-regexp|--fixed-strings|--basic-regexp|--perl-regexp|--ignore-case|\
--no-ignore-case|--word-regexp|--line-regexp|--invert-match|--null-data|--text|--binary-files=*) ;;
      --regexp=*|--file=*) _hm_pat=1 ;;
      --regexp|--file) _hm_pat=1; _hm_take=1 ;;
      --binary-files) _hm_take=1 ;;
      --*) _has_match_fail "option '$_hm_a' is not one has_match accepts (long options in full: see has_match.sh)" "$@" ;;
      -?*)
        # A short-option cluster: letters until one that takes an argument, which is the rest of
        # the word or, when the word ends there, the next word.
        for (( _hm_j=1; _hm_j<${#_hm_a}; _hm_j++ )); do
          _hm_c="${_hm_a:_hm_j:1}"
          case "$_hm_c" in
            [qmlLcV]) _has_match_fail "option '-$_hm_c' is not a whole-input match" "$@" ;;
            [ef]) _hm_pat=1; [ $((_hm_j + 1)) -eq ${#_hm_a} ] && _hm_take=1; break ;;
            [ABCdD]) [ $((_hm_j + 1)) -eq ${#_hm_a} ] && _hm_take=1; break ;;
          esac
        done ;;
      *) _hm_ops=$((_hm_ops + 1)) ;;
    esac
  done
  # It reads standard input and nothing else: one operand, the pattern, or none after -e/-f. A file
  # operand would leave the drain below reading the caller's own standard input.
  if [ $((_hm_ops + _hm_pat)) -ne 1 ] && ! { [ "$_hm_pat" = 1 ] && [ "$_hm_ops" = 0 ]; }; then
    _has_match_fail "has_match takes a pattern and reads standard input, never a file operand" "$@"
  fi
  # grep -c reads its whole input; the cat after it drains whatever an option still made grep leave
  # (an empty -f pattern list exits without reading), so the producer never meets a closed pipe.
  # Status read through && || so an ERR trap or errexit in the caller does not act on grep's 1 here.
  _hm_n="$(grep -c "$@"; _hm_r=$?; cat >/dev/null; exit "$_hm_r")" && _hm_rc=0 || _hm_rc=$?
  case "$_hm_rc" in
    0|1) return "$_hm_rc" ;;
  esac
  _has_match_fail "grep exited $_hm_rc" "$@"
}

_has_match_fail() {
  local why="$1"; shift
  printf 'has_match: %s (grep arguments:' "$why" >&2
  printf ' %q' "$@" >&2
  printf '); stopping %s with no verdict\n' "${0##*/}" >&2
  # A pipeline stage or a substitution is a subshell: its exit would only end that stage, and the
  # leg would read the status as "no match". Stop the script itself, with a signal it cannot trap.
  if [ "${BASH_SUBSHELL:-0}" -gt 0 ]; then kill -s KILL "$$" 2>/dev/null; fi
  exit 2
}

#!/usr/bin/env python3
"""RETENTION.tsv: parse it, and give each path its one governing row (ROADMAP R-0562).

Usage: retention.py check MANIFEST < paths     problems, one per line (empty: valid and complete)
       retention.py govern MANIFEST < paths    "<path>\\t<row path list>\\t<disposition>" per path

The rule (also the manifest's header): a row's first field is a space-separated list of paths; a
path is governed by the row that lists its longest prefix (a listed path equal to it, or a listed
directory containing it); legacy/P is governed as P. Rows carry a status (open | resolved)
about the legacy/ copy only (a retained row's root file is never deleted through the manifest). No path may be listed twice, so the governing row is unique. A path with
no listed prefix is uncovered, which `check` reports. Lives in scripts/land because the deletion
check of the legacy/ move will read deletion authority from `govern`, and the gate that holds the
manifest to the tree (scripts/checks/retention_manifest.sh) uses the same code.
"""
import sys

DISP = {"retained", "archived", "migrate", "retire"}
HDR = ["path", "kind", "disposition", "destination", "owner", "deletion_criterion", "status"]
STATUS = {"open", "resolved"}


def parse(path):
    problems, rows, listed = [], [], {}
    lines = [l.rstrip("\n") for l in open(path) if not l.startswith("#") and l.strip()]
    if not lines or lines[0].split("\t") != HDR:
        return ["header is not: " + "\t".join(HDR)], rows, listed
    for n, l in enumerate(lines[1:], 2):
        f = l.split("\t")
        if len(f) != len(HDR) or any(not x.strip() for x in f):
            problems.append(f"row {n}: needs {len(HDR)} non-empty tab-separated fields: {l[:60]}")
            continue
        if f[2] not in DISP:
            problems.append(f"row {n}: disposition {f[2]!r} is not one of {sorted(DISP)}")
        if f[6] not in STATUS:
            problems.append(f"row {n}: status {f[6]!r} is not one of {sorted(STATUS)}")
        if f[2] == "retained" and not (f[5].startswith("root: ") and "; legacy/ copy" in f[5]):
            # status releases only the legacy/ copy, so a retained row must say both halves
            problems.append(f"row {n}: a retained row's criterion must read 'root: ...; legacy/ copy...: ...'")
        for p in f[0].split():
            p = p.rstrip("/")
            if p in listed:
                problems.append(f"row {n}: {p} is already listed by the row for {listed[p][0]!r}")
                continue
            listed[p] = (f[0], f[2])
        rows.append(f)
    return problems, rows, listed


def governing(listed, path):
    if path.startswith("legacy/"):
        path = path[len("legacy/"):]  # after the move, legacy/P is the asset P
    parts = path.split("/")
    for i in range(len(parts), 0, -1):
        hit = listed.get("/".join(parts[:i]))
        if hit:
            return hit
    return None


def main():
    if len(sys.argv) != 3 or sys.argv[1] not in ("check", "govern"):
        sys.exit(__doc__)
    problems, rows, listed = parse(sys.argv[2])
    paths = [l.strip() for l in sys.stdin if l.strip()]
    if sys.argv[1] == "check":
        for p in problems:
            print(p)
        uncovered = sorted({p for p in paths if governing(listed, p) is None})
        for p in uncovered:
            print("no row governs " + p)
    else:
        for p in paths:
            g = governing(listed, p)
            print(f"{p}\t{g[0] if g else '-'}\t{g[1] if g else 'uncovered'}")


if __name__ == "__main__":
    main()

#!/usr/bin/env python3
"""RETENTION.tsv: parse it, and give each path its one governing row (ROADMAP R-0562).

Usage: retention.py check MANIFEST < paths     problems, one per line (empty: valid and complete)
       retention.py govern MANIFEST < paths    "<path>\\t<row path list>\\t<disposition>" per path

The rule (also the manifest's header): a row's first field is a space-separated list of paths; a
path is governed by the row that lists its longest prefix (a listed path equal to it, or a listed
directory containing it); legacy/P is governed as P. Rows carry a status (open | resolved)
about the legacy/ copy only (a retained row's root file is never deleted through the manifest). No path may be listed twice, so the governing row is unique. A path with
no listed prefix is uncovered, which `check` reports. Lives in scripts/land because the deletion
check of the legacy/ move will read deletion authority from `govern`, and the gate that holds the
manifest to the tree (scripts/checks/retention_manifest.sh) uses the same code.
"""
import sys

DISP = {"retained", "archived", "migrate", "retire"}
HDR = ["path", "kind", "disposition", "destination", "owner", "deletion_criterion", "status"]
STATUS = {"open", "resolved"}


def parse(path):
    problems, rows, listed = [], [], {}
    lines = [l.rstrip("\n") for l in open(path) if not l.startswith("#") and l.strip()]
    if not lines or lines[0].split("\t") != HDR:
        return ["header is not: " + "\t".join(HDR)], rows, listed
    for n, l in enumerate(lines[1:], 2):
        f = l.split("\t")
        if len(f) != len(HDR) or any(not x.strip() for x in f):
            problems.append(f"row {n}: needs {len(HDR)} non-empty tab-separated fields: {l[:60]}")
            continue
        if f[2] not in DISP:
            problems.append(f"row {n}: disposition {f[2]!r} is not one of {sorted(DISP)}")
        if f[6] not in STATUS:
            problems.append(f"row {n}: status {f[6]!r} is not one of {sorted(STATUS)}")
        if f[2] == "retained" and not (f[5].startswith("root: ") and "; legacy/ copy" in f[5]):
            # status releases only the legacy/ copy, so a retained row must say both halves
            problems.append(f"row {n}: a retained row's criterion must read 'root: ...; legacy/ copy...: ...'")
        for p in f[0].split():
            p = p.rstrip("/")
            if p in listed:
                problems.append(f"row {n}: {p} is already listed by the row for {listed[p][0]!r}")
                continue
            listed[p] = (f[0], f[2])
        rows.append(f)
    return problems, rows, listed


def governing(listed, path):
    if path.startswith("legacy/"):
        path = path[len("legacy/"):]  # after the move, legacy/P is the asset P
    parts = path.split("/")
    for i in range(len(parts), 0, -1):
        hit = listed.get("/".join(parts[:i]))
        if hit:
            return hit
    return None


def main():
    if len(sys.argv) != 3 or sys.argv[1] not in ("check", "govern"):
        sys.exit(__doc__)
    problems, rows, listed = parse(sys.argv[2])
    paths = [l.strip() for l in sys.stdin if l.strip()]
    if sys.argv[1] == "check":
        for p in problems:
            print(p)
        uncovered = sorted({p for p in paths if governing(listed, p) is None})
        for p in uncovered:
            print("no row governs " + p)
    else:
        for p in paths:
            g = governing(listed, p)
            print(f"{p}\t{g[0] if g else '-'}\t{g[1] if g else 'uncovered'}")


if __name__ == "__main__":
    main()

### Killing a publish does not un-publish it

`push-both.sh` runs `git push` as a CHILD process. Killing the script does not
kill that child, and a `git push` already in flight will complete.

Measured 2026-07-31: a publish was killed during its pre-push hook, `git ls-remote`
showed the primary unchanged, and that was read as "nothing was published". The
`git push` child was still running; it finished moments later and advanced the
primary. The next publish was then rejected as non-fast-forward — harmless here,
but the reasoning behind the kill was a race read as a guarantee.

So: a ref check taken *at* the moment of the kill proves nothing about a push
that has already started. If a publish must be abandoned, re-check the remote
AFTER the process tree is gone (`pgrep -f "git push"` clear), and treat the
remote's actual state as the answer rather than the state you saw before killing.

### Background agent jobs always have a watcher

Start every background writer, reviewer or gate with `scripts/agent/launch.sh start`, then
immediately run the printed `WAIT` command as your own background task so the job's end re-invokes
you. Never start a detached unit without its watcher. A writer gets one attempt only: a killed or
timed-out job is investigated, never automatically re-run. Each start exclusively creates a new job
directory (an existing `--dir` is refused) and preserves argv through a file rather than systemd's
command expansion. A missing status returns 125 with systemd's retained result when known; a bus or
`systemctl` query failure is an operational error (2), not a completed job.

### Orchestrating a publish: never infer state from process names

`pgrep -f "push-both"` matches the WAITER'S OWN command line, which contains that
string. Every `until ! pgrep -f "push-both"; do sleep 30; done` loop therefore
waits on itself forever, and a status check written the same way reports "publish
running" when nothing is. Measured 2026-08-01: six background tasks were stuck on
this at once, and the reported state was wrong for as long as they ran. It is the
same failure as counting `pgrep -lf "codex|claude"` and getting 115 — a
process-name match catches the matcher.

Do this instead:

* capture the launched PID and `wait "$pid"`;
* verify completion by checking the EXACT REMOTE SHA (`git ls-remote`), which is
  the fact you actually care about;
* query CI for that SHA (`gh run list --commit <full-sha>` — the full SHA; the
  short form returns nothing);
* never infer state from a process-name match.

For a one-off inspection, `ps -eo command | grep -c "[p]ush-both.sh"` excludes
itself via the bracket, but a ref check is still the better answer.

"""Run one command under a time budget, owning its whole process group (lib/bounded.sh's runner).

  bounded_exec.py --timeout SECS --kill-after SECS --status FILE -- CMD [ARGS...]

The command inherits stdin, stdout and stderr (the caller redirects them) and runs as the leader of
a new session, so it and every descendant that does not create its own session share one process
group. The outcome goes to FILE, never to the command's streams, so nothing the command prints can
fake or hide it:
  exit N      the command finished with status N (128+S when killed by signal S, as a shell reports)
  timeout     the budget expired: the group got SIGTERM, then, KILL_AFTER seconds later, SIGKILL,
              whether or not the leader had already exited, so a descendant that ignores SIGTERM
              does not outlive the attempt.
When the command finishes within its budget its group is left alone, as timeout(1) does.
Both durations must be finite numbers, the budget positive and the grace nonnegative.
This process exits 0 once FILE is written and 2 on a usage error. If it is itself cancelled
(SIGTERM, SIGHUP, SIGINT), it kills the command's group, writes no outcome, and exits 128+signal.

        os.killpg(pgid, sig)
    except (ProcessLookupError, PermissionError):

    try:
        os.killpg(pgid, 0)
        return True
    except ProcessLookupError:
        return False
    except PermissionError:

    try:
        v = float(text)
    except ValueError:
        return None
    if not math.isfinite(v) or v < 0 or (positive and v == 0):

    return v
