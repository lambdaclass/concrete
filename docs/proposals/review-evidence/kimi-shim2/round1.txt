• ### High — aliases bypass the shim completely

  `scripts/land/acceptance_shim.sh:31-36` only recognizes a literal `push` argument. If none exists, it delegates to real Git, where an alias can subsequently expand to `push`.

  Reproduced under `timeout 10` against a scratch protected bare repository:

  ```bash
  G -C w -c alias.p=push p origin main
  ```

  This returned 0 and created `refs/heads/main` on the protected repository. The environment-only spelling also succeeded:

  ```bash
  GIT_CONFIG_COUNT=1 \
  GIT_CONFIG_KEY_0=alias.p \
  GIT_CONFIG_VALUE_0=push \
  G -C w p origin main
  ```

  Thus `GIT_CONFIG_PARAMETERS`-style configuration can bypass the shim without any literal `push` argument. The control at `scripts/checks/landing_script.sh:1062-1084` does not exercise aliases.

  ### High — a protected non-bare repository is exposed through `.git`

  `scripts/land/acceptance_shim.sh:64-82` compares canonical URL directory paths, not the actual Git repository directory. Protecting `/tmp/.../nonbare` does not protect `/tmp/.../nonbare/.git`, although both name the same repository.

  With the shim protecting `$S/nonbare` and a remote pointing at `$S/nonbare/.git`, this succeeded under `timeout 10`:

  ```bash
  G -C w push --force nonbare +main
  ```

  Git reported:

  ```text
  + 9d86fd6...0ac54ff main -> main (forced update)
  ```

  The canonical paths `$S/nonbare` and `$S/nonbare/.git` differ, so the destination is incorrectly classified as an unprotected fixture. The new control only protects and addresses a bare repository, missing this case.
