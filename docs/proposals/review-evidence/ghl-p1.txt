Review a small bash change in the Concrete repository's landing tooling. scripts/land/gates_transport_ssh.sh writes run.sh, which is copied to a gate host over scp and run there by ssh; it runs the impact gates in the host's gate clone and any failure exits 255, which the caller reports as INCOMPLETE (never a pass). NEW: before anything is fetched, run.sh refuses a login whose `id -u` is not a number (fail closed), a root login (uid 0) and a login with no gate clone directory ($RUN_AT_REF_REPO or ~/concrete2 lacking .git), naming the user@host and path. Cause: a train run from an account whose ssh alias for the CI host logs in as root looked for /root/concrete2 and only said "fetch failed". scripts/checks/landing_script.sh adds two end-to-end cases through the real transport with ssh/scp shims (a fake `id` printing 0/root on the host's PATH; the gate clone moved away), each must be INCOMPLETE, name the cause, and fetch nothing.
Note the echo lines produce run.sh code: single-quoted strings are host-side code. Review for correctness defects: quoting, a check that can pass without looking, a way a root or missing-clone login could still run gates or report a pass, and portability to the hosts' bash (Linux) — and whether the tests really exercise the new lines. Format: file:line, defect, concrete failing scenario; label preferences "preference". End with exactly one line: VERDICT: ACCEPT or VERDICT: FINDINGS.

+### The gate host checks its login before it fetches (2026-11-08)
+
+A landing check run from an account whose `concrete-ci-2` ssh alias is the root admin login
+(by design: the provisioned gate identity is `agent` on fede-256gb, which logs into `dev` with the
+`ci_gates` key, dotfiles `servers/agent-home.sh`) looked for `/root/concrete2` and reported only that
+the fetch failed. `scripts/land/gates_transport_ssh.sh` now checks the login on the host before
+anything is fetched: a root login is refused (gates never run as root), a login `id` cannot read is
+refused rather than taken as non-root, and a login without its gate clone names the account and
+path. Each is INCOMPLETE, never a pass. `scripts/checks/landing_script.sh` covers all three through
+the real transport, and none fetches.
