THE NEW FORMAT (replace the current one; there are no existing records to migrate):
- The record commit's tree holds exactly seven 100644 blobs: record.txt, and for each reviewer r in
  codex, kimi, agy: `r-request.txt` (what the reviewer was asked) and `r.txt` (its output only).
- record.txt keys, each once: signoff, commit, date, quote, rounds-at (unchanged), and for each r:
  `request-r: r-request.txt <sha256>` and `verdict-r: r.txt <sha256>`.
- A request file's FIRST line is `reviewed: <the full 40-hex SHA of the commit the reviewer was run
  on>` (a structured field the recorder writes, attesting the commit); every following line is the
  request exactly as sent. verify requires that first line to equal the signed commit exactly, and
  the request body (after that line) to name the commit by an unambiguous prefix of 7+ hex digits
  (the existing `names` helper). Mentions in the OUTPUT no longer count for binding.
- The verdict is read ONLY from the output file r.txt: its last line matching
  `^[[:space:]]*VERDICT: (ACCEPT|REJECT)[[:space:]]*$` must be `VERDICT: ACCEPT`; an output with no
  such line is refused ("the r output has no verdict"). Lines in the request never count.
- `signoff.sh record` takes, per reviewer, `--codex-request FILE --codex FILE` (and kimi, agy). The
  request FILE given to record is the verbatim request; record itself prepends the `reviewed: <sha>`
  line (the commit being signed) when it stores r-request.txt, and hashes what it stores. Keep:
  record verifies before writing the ref; hash-object --no-filters; the cap by diff class; quote
  naming by unambiguous prefix; rounds-at judged by scripts/review/verify.sh.
