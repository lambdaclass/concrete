1. **`scripts/agent/launch.sh:111-115` and `scripts/agent/launch.sh:130-143` — REAL DEFECT (leaked failed units on normal non-zero exit / unrecorded status on `rc=0` write failure):**
   `run_job` writes `$dir/status` **before** calling `exit "$rc"`. When a job exits non-zero (e.g. `rc=3`), `inspect()` can observe `[ -f "$JOBDIR/status" ]` at line 171 while the unit process is still exiting (`active`/`deactivating`). `normal_exit()` then runs `systemctl --user reset-failed "$UNIT"` while the unit is still active (which is a no-op both in real systemd and in the stub's `[ -f "$state/active" ] || rm -f "$state/result"` at `scripts/checks/agent_launch.sh:155`), and moments later `run_job` executes `exit 3`, putting the unit into `failed` forever after `wait` has already returned. Conversely, if writing `$dir/status` fails when `rc=0`, `run_job` still does `exit 0`, so systemd garbage-collects the transient unit (`Result=success`) even though no `status` file was written.
   - **Fix:** Since `$dir/status` already carries the command's exit status `$rc` for `normal_exit()`, have `run_job` exit `0` iff `$dir/status` was atomically written, and exit `2` otherwise:
     ```bash
     if printf '%s\n' "$rc" > "$tmp" && mv "$tmp" "$dir/status"; then
       exit 0
     fi
     rm -f "$tmp"
     exit 2
     ```
     Then every job that records `status` exits `0` (so systemd's default `CollectMode=inactive` unloads the transient unit automatically on exit without ever entering `failed`), and only jobs that fail to write `status` enter `failed` for `lost_exit()`.

2. **`scripts/checks/agent_launch.sh:106-112` and `scripts/checks/agent_launch.sh:287-295` — REAL DEFECT (orphaned infinite-loop process leaked on every run + untested `$JOBDIR/result` readback):**
   - In the `timeout-result` test, the watchdog kills only `$command_pid` (`bash "$LAUNCH" run`), not its child `bash -c 'while [ ! -e "$STUB_RELEASE_DIR/$STUB_UNIT" ]; do sleep 0.1; done'`. Unlike the other fixtures, `timeout-result` never touches `"$STUB_RELEASE_DIR/$UNIT"`, so when `EXIT` removes `$TMP`, `[ ! -e "$STUB_RELEASE_DIR/$STUB_UNIT" ]` stays true forever and the orphaned `while` loop leaks after `agent_launch.sh` exits.
   - Line 295 only checks `[ -f "$STUB_STATE_DIR/$UNIT/reset-failed" ]`; it never checks `[ ! -e "$STUB_STATE_DIR/$UNIT/result" ]` and never runs a second `status`/`wait` against `$JOBDIR` after collection. If the `if [ -f "$JOBDIR/result" ]` read branch in `lost_exit()` (`scripts/agent/launch.sh:155-156`) were removed, all tests in `agent_launch.sh` would still pass.
   - **Fix:** Touch `"$STUB_RELEASE_DIR/$UNIT"` at the end of the `timeout-result` test (and/or in the `EXIT` trap before `rm -rf "$TMP"`), assert `[ ! -e "$STUB_STATE_DIR/$UNIT/result" ]`, and run `capture 10 bash "$LAUNCH" status "$JOBDIR"` (or `wait`) a second time to verify it still returns `125` with `: timeout` from the cached `$JOBDIR/result`.

3. **`scripts/agent/launch.sh:146-150` — REAL DEFECT (`unit_result` reports `success` when a killed/stopped unit is already unloaded):**
   In real systemd, `systemctl --user show "$UNIT" --property=Result --value` on an unloaded unit (e.g. stopped via `systemctl stop` or already garbage-collected) prints `success` (the default `Service.Result` property on an unloaded unit), not an empty string, producing `JOB ... ENDED without a status (killed, timed out or OOM): success`.
   - **Fix:** Treat `""` and `"success"` as `unknown` in `unit_result()`:
     ```bash
     case "$result" in ''|success) result=unknown ;; esac
     printf '%s\n' "$result"
     ```

4. **`scripts/agent/launch.sh:83-85` — REAL DEFECT (`--dir` with a trailing slash always fails on a new directory):**
   If `--dir /path/to/newdir/` is passed with a trailing slash, `parent="${jobdir%/*}"` sets `parent="/path/to/newdir"`. `mkdir -p -- "$parent"` then creates `/path/to/newdir`, causing the immediately following `mkdir -- "$jobdir"` to fail with `File exists` on a brand-new directory (and for `--dir /top`, `parent` becomes `""` and `mkdir -p -- ""` fails).
   - **Fix:** Strip trailing slashes from `jobdir` before computing `parent` (and default an empty `parent` for `/name` to `/`):
     ```bash
     while [ "${#jobdir}" -gt 1 ] && [ "${jobdir%/}" != "$jobdir" ]; do jobdir="${jobdir%/}"; done
     case "$jobdir" in */*) parent="${jobdir%/*}"; parent="${parent:-/}" ;; *) parent=. ;; esac
     ```
