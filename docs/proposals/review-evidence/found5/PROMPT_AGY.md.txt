# Concrete Lean foundation proposal

Status: proposed for owner approval; this document changes no decided rule. The owner chose **write the shared foundation completely, then freeze it before slice 1** (option b). Later slices add instances and rules through these interfaces; changing an interface or weakening a law requires a new owner decision. This consolidates round 3 and the earlier layout reviews, including the orchestrator's resolutions.

References below use the actual anchors in this checkout. **Core rows** means [Q1–Q9](../docs/decisions.md#decided-2026-11-05-core). The pipeline referred to in the brief as the 2026-11-07 decision is recorded here under [the 2026-11-06 pipeline anchor](../docs/decisions.md#decided-project-pipeline-2026-11-06); there is no `decided-2026-11-07-pipeline` anchor. Proposed additions without a decided row are identified as such, not attributed to an invented decision.

## 1. The freeze boundary

Freeze **extensible interfaces and their laws**, not an exhaustive list of future types, grants, instructions or events. Every admitted instance must provide the required laws; an unknown instance is refused, never silently given semantics. Extensions must preserve the old fragment's judgments and executions. A new operation cannot change what an old operation means.

The foundation comprises target profiles; typed identities; types, values and places; control and calls; scalar operations; layout and representation; byte memory; ownership, loans, brands and authority; observations and leakage; evaluator adequacy; primitive contracts; frames and ABI; evidence, facts and diagnostics. An interface includes its state, preconditions, results and preservation laws, not just a record of names.

Before freezing, implement these contracts in the authoritative Lean library, with readable comments, accepted/refused examples and counterexamples to invalid premises. Discharge the four Q9.14 design theorems and the [A2i interaction/erasure obligations](../docs/decisions.md#decided-project-long-term-2026-11-06), including the laws below. Tests alone do not establish them. Existing `ConcreteSpec` fragments are starting material, not evidence that omitted pointer fragments, external frames, initialization or cleanup interactions are already covered. Review and owner approval precede the freeze. This is a writing proposal, not that completed review or approval.

## 2. Contracts to finish before the freeze

Each contract states the frozen interface and laws, its recommended rule, its authority, and the later work it permits.

### C1. Execution, calls and cleanup

**Freeze:** machine configurations with current command, locals, places, call frames and structured continuations; a labeled single-step relation; results for ordinary completion, return, labeled break/continue and terminal abort. A continuation says where execution resumes. Prove sequencing, scope restoration and cleanup preservation, including effects while evaluating an exit value.

**Rule:** evaluate subexpressions completely left to right: receiver before arguments, left operand before right, literal fields/elements in written order, base before index. Assignment evaluates its RHS before any destination subexpression. `&&` evaluates its RHS only if the LHS is true; `||` only if false; both operands are still checked. Resolve calls by typed identity; evaluate arguments before entering the callee. Moves transfer ownership exactly once; copies require a declared, checked Copy instance.

Keep the decided Core loop condition region, counted-loop bound snapshots and counter advancement. Preserve the restrictions on exits inside operands. Return evaluates its result before leaving scopes. Normal block exit, return, break and continue run the deferred calls of each exited scope, inner scope first and reverse registration order within a scope. Deferred operands are read at cleanup, with dependencies kept alive. If cleanup aborts, stop immediately; no remaining cleanup runs. Explicit abort runs no deferred call and does not unwind. Ordinary locals do not acquire implicit user destructors: explicit consumption, storage teardown and resource destruction remain different operations. Arrays destroy elements in increasing index order then backing; OrderedMap uses ascending keys, key before value, then nodes. Destruction is an ordinary checked call and may itself fail to terminate unless stronger evidence exists.

**Authority:** Core Q2.1–Q2.7, Q6.5, Q9.1, Q9.3–Q9.4, Q9.8, Q9.11; [OD10](../docs/decisions.md#od10), [OD53](../docs/decisions.md#od53), [OD69](../docs/decisions.md#od69); STMT-4/5. **Later:** source constructs and their lowering, loop/call bounds and destructor bodies at their slices. No postfix `?`, exceptions or implicit error propagation is introduced.

### C2. Scalars, failure and arithmetic

**Freeze:** mathematical scalar values, finite bit representations, operation contracts and error classification; representation and operation correspondence laws. Integer widths remain those named by `i8`…`i64` and `u8`…`u64`; proposed `usize` is separate. A bool has only false/true, encoded as byte 0/1. Character validity excludes non-Unicode-scalars.

**Rule:** signed representation is two's complement. Division truncates toward zero; nonzero remainder has the dividend's sign. Zero divisors and signed `MIN / -1` and `MIN % -1` are errors, the latter two `Overflow`. Shift counts satisfy `0 ≤ count < width`; valid shifts discard outgoing bits, signed right shift sign-fills and unsigned right shift zero-fills. Plain arithmetic needs closed safety evidence. Checked operations return the decided `Result<T, ArithmeticError>`; wrapping operations compute modulo the width and saturating operations clamp to bounds. `as` is lossless over the entire source domain; lossy conversions use named operations, with checked conversion returning `OutOfRange`.

Use exactly **`TrapKind = arithmetic(ArithmeticError) | bounds | invalidRange | abort`**, with `ArithmeticError = Overflow | DivisionByZero | InvalidShift`. UTF-8 boundary failures are `invalidRange`. These classify unchecked semantics and compiler obligations; they do not authorize implicit traps in accepted safe code. `checked_no_implicit_traps` excludes the first three kinds under its premises. A handled checked error is an ordinary value, not a trap. Explicit abort is permitted terminal behavior. Invalid unsafe execution is stuckness (no permitted next step), not a trap; resource exhaustion and evaluator fuel exhaustion are separate again.

**Authority:** [no hidden traps](../docs/decisions.md#decided-project-no-hidden-traps), [OD11](../docs/decisions.md#od11), [OD99](../docs/decisions.md#od99), [OD106](../docs/decisions.md#od106), [OD114](../docs/decisions.md#od114), TYPE-19, Core Q6.7. **Later:** operation syntax and admission instances; float rules at slice 26. The interface admits float instances but does not invent their unsettled details. No `isize` is added by implication: pointer differences use a mathematical signed offset in the model and an explicitly contracted representable result in source APIs.

### C3. Target, layout and representation

**Freeze:** a well-formed target profile and a layout interface. Separate address width, pointer storage size/alignment, length width, byte order and address spaces; do not infer any from CPU arithmetic width. The profile specifies pointer encoding, distinguished null, accessible spaces and maximum object sizes. Require representable sizes/offsets and checked layout arithmetic; reject an unrepresentable layout rather than wrap. No universal 64-bit assumption, including for 20/24-bit addresses.

Layout laws: positive power-of-two alignment; size a multiple of aggregate alignment; occupied field bytes in bounds and non-overlapping; required field alignment in native/C modes; unique discriminants; and sound decoding of any niche (an otherwise unused encoding used for a variant). Zero-size fields have empty byte ranges and may share offsets. Packed mode replaces natural field alignment with explicit unaligned-access premises; it must not falsely prove packed fields naturally aligned. Above Memory CFG, semantics uses structured values and never depends on layout. The concrete algorithm below is one implementation proving these laws, not the premise of every earlier proof.

**Rule:** native structs retain declaration order, each field rounded up to its alignment, aggregate alignment the maximum (1 for empty), and final size rounded up. Empty aggregates have size 0/alignment 1. Arrays have size `n × size(T)` and alignment `align(T)`, including `n = 0`. Fixed-width integer storage respects value width; alignment is target-defined. Text/StaticStr and views are pointer plus length; text length counts UTF-8 bytes. Shared/mutable views share representation. Address-space selection is explicit profile metadata, including program-memory text: no silent cast to data pointers. `Secret<T>` has T's layout, without implying constant time.

Native enums use the smallest tag fitting their variant count: u8 through 256, u16 through 65,536, u32 through 2^32. Tags are numbered from zero in declaration order. The tag precedes a common payload offset aligned to the largest payload alignment; total size is rounded to the maximum tag/payload alignment. Refuse more than 2^32 variants. A zero-variant semantic type is uninhabited: there is no encoder input or successful decoder result. This does **not** admit an empty-enum source declaration: OD72's refusal remains. Invalid tags cannot inhabit well-formed typed values. Raw decoding is partial and needs validity premises; arbitrary raw stores do not acquire typed validity.

**New owner question — one niche rule:** recommend that an enum with exactly two variants, one payload-free and the other with a single non-null pointer or handle payload, has the payload pointer's size/alignment, null encoding the empty variant. Eligibility requires a proved pointer-sized representation, a reserved null encoding and preservation of ownership/provenance; a multiword handle with release context is ineligible. Raw nullable pointers are ineligible. No other niches are allowed. Alternative: **no niches, permanently**, including this case. Recommend the single rule for predictable pointer-sized optional ownership on small targets and servers; it has one explicit validity proof and avoids future layout changes. This is undecided, not an inference from OD126. If the owner chooses the alternative, omit the exception to tagged layout and freeze the permanent prohibition.

Include native, C and packed modes now. C layout/calling details come from the selected ABI; enums remain forbidden across extern boundaries. Packed structs use declaration order/no padding/alignment 1; C+packed uses C order with packing overriding alignment. Misaligned fields are permitted but references to them are refused. Direct field access uses an explicitly justified unaligned operation, possibly lowered to byte accesses. Preserve FFI-4's existing `align(N)` restriction; surface repr forms wait for slice 25. Stronger over-alignment, MMIO and section-placement syntax remain deferred to workloads. No shortened MCU trap format is adopted.

**Authority:** [runtime/layout decision](../docs/decisions.md#decided-project-runtime-2026-11-06), Core Q3.5–Q3.11, Q4.1–Q4.5; [OD72](../docs/decisions.md#od72), [OD110](../docs/decisions.md#od110), [OD111](../docs/decisions.md#od111), [OD126](../docs/decisions.md#od126), [OD147](../docs/decisions.md#od147); FFI-4/7/8/10. Revisions are listed below. **Later:** syntax, additional target/ABI implementations, concrete allocation and FFI operations; not the layout laws or alignment premises.

### C4. Byte memory and value validity

**Freeze:** blocks with fresh allocation identity, address space, base, extent, alignment and lifetime; byte initialization state; pointer provenance (the allocation a pointer originates from); a typed representation relation `Rep`; partial decoding, access validity and disjoint-memory composition laws. Pointer fragments carry provenance metadata separately from numeric bytes. Do not introduce a poison value that can become an arbitrary typed result.

**Rule:** memory bytes are initialized octets or uninitialized. Allocation starts uninitialized unless its primitive contract initializes it. Track initialization per occupied field/element; moving out removes that slot's typed ownership/read permission. Reading a typed value requires its active representation bytes initialized and valid. Padding and inactive enum storage need not be initialized and cannot affect typed equality, control or observations. Raw byte copying may transport uninitialized padding and provenance fragments without observing them; observing a byte requires initialization. `Rep` ignores padding but checks active tags, bool/char/text validity and pointer fragments. Prove encoding/decoding round-trip for valid typed values, with allowed padding choices, and that decoding yields only valid values.

Block identity is never reused, even if an address is. Deallocation ends all access rights to the old block. Every access needs live provenance, bounds, initialization, alignment or an explicit unaligned mode, and authority/loan permission. One-past pointers may be formed but not dereferenced. Address arithmetic cannot silently wrap into another allocation. Integers carry no provenance; `expose` records the block in the address space, and `from_exposed` uses Q3.9's in-bounds-first, then one-past, then no-provenance rule over eligible exposed blocks. Do not add a new arbitrary tie-break where the decided relation permits choices. Pointer equality follows the decided raw model, not equality of allocation identities alone.

Zero-size slots own distinct logical obligations, occupy no bytes and may share addresses; address equality does not merge owners. Their accesses still require a valid lifetime and permission. Address collisions mean overlapping occupied bytes, not merely equal bases. Address exhaustion belongs to allocator availability. Allocation failure is a typed result conserving the rejected input, not an implicit trap. Require Q1.11's allocator availability laws: progress under availability, unchanged allocator state on failure, release never reducing availability, and a concrete success witness. Callback effects are not rolled back; every element remains accounted for in its typed result. Raw/foreign writes must re-establish validity before safe typed use; violating a trusted premise yields no safety claim, not a fabricated valid value.

**Authority:** Core Q1.8–Q1.12, Q3.7–Q3.11; [memory decision](../docs/decisions.md#decided-project-memory-2026-11-06). Initialization/padding and pointer-fragment details above are proposed completions of Q3.11, not separately decided rows. **Later:** raw-pointer syntax (24), allocator algorithms (19–23), FFI operations (25). They instantiate this model rather than replace it.

### C5. Dynamic borrow, brands and authority

**Freeze:** a preservation invariant relating owner slots, moves, root/projection identities, active loans and parent loans, generative brands, dependency lifetimes, grant/resource identities and operation rights. Prove preservation on each step and across calls, including ghost erasure.

**Rule:** loans retain the original root and projection. Keep **whole-root** conflicts, including disjoint fields: an exclusive loan conflicts with every other active access to that root; shared loans freeze the whole owner against mutation/move. A reborrow suspends conflicting access through its parent until the child ends. A loan-derived pointer is valid only during the loan. Shared views are Copy; mutable views are nonduplicable and end by borrow discipline, without an exactly-once destruction obligation. No optimization exploits exclusivity before the checker guarantee is proved.

Fresh brand binders are nominal, including reset/loop generations; dependencies cannot escape their lifetime. Child allocators own backing and expose parent dependence. Grant narrowing consumes and intersects rights; acquisition preserves the parent as decided; close/give-up consumes its resource on all specified outcomes. Zero representation size never removes linear obligations. Permissions in `with(...)` are erased sets, distinct from runtime grants. `GrantTy` describes launch-grant types; File/Socket/Listener are acquired handles. Clock kind has separate identity/resolution/guarantee metadata. Entropy is a nullary launch-grant type, with its source a named premise.

Heap handles contain a pointer and sufficient stable release context, erased only when release is statically known and needs no per-instance information. Allocator/grant representations are opaque per resource; grant state erases only if stream/device identity, rights and lifecycle are statically determined and all authority transitions are preserved. Prove erasure, rather than assuming one allocator or one capability means zero state.

**Authority:** Core Q1.1–Q1.7, Q3.1–Q3.4, Q7.1–Q7.11; [OD15](../docs/decisions.md#od15), [OD23](../docs/decisions.md#od23), [authority decision](../docs/decisions.md#decided-2026-11-02-authority), [randomness](../docs/decisions.md#decided-2026-11-07-stack-randomness). **Later:** concrete loan/grant operations and source rules; no choice of a new stacked/tree borrow model replacing whole-root rules.

### C6. Observations, environment and concurrency extension

**Freeze:** extensible typed event signatures, request/response matching, finite and infinite traces, terminal observations and an environment relation. A trace is the ordered externally relevant history. Prove preservation of full observations, allowing internal steps that emit no event, without turning infinite internal execution into successful termination.

**Rule:** model startup, capability requests and responses (including blocking), external/FFI effects, public output, logical terminal actions and shutdown. Bind external choices to a shared input/environment history. Error, partial-delivery and blocking behavior belongs to each operation contract; do not assume a hostile environment cooperates. Preserve output preceding a trap and externally visible final state. Normal exit and trap exit 134 remain different observations. Missing launch grants refuse startup with 125. Traps retain kind, typed site and the exact decided line `concrete: trap: <kind> at <path>:<line>:<col> (site <id>)`, project-relative forward-slash path, 1-based line and byte column (tab counts as one byte); no per-build abbreviated variant. Propose the total kind rendering `overflow`, `division_by_zero`, `invalid_shift`, `bounds`, `invalid_range`, `abort`, respectively, and one trailing newline. These spellings complete an undecided rendering detail and need approval with C6; old inconsistent labels are not authority. Cover every mapping with conformance examples.

An environment response may be nondeterministic but must satisfy its contract. Distinguish modeled failure, unmodeled foreign behavior and broken premises. Exhaustion of an allocator can return its specified error; stack guarantees remain subject to the exact artifact's checked bound, reservation and launcher premises. Do not invent a universal resource-exhaustion trap. Fuel exhaustion is an evaluator report, never an external event.

Reserve operation/event parameters for thread identity, access mode and synchronization evidence. Prove sequential results under a single-thread/no-interference premise and a projection that forgets future synchronization events. Later atomic operations must preserve old sequential behavior under that premise; the foundation makes no race-freedom or concurrent correctness claim. This leaves room for atomics without choosing a memory-order model, scheduler or spawning syntax now.

**Authority:** Core Q6.7, Q7.5–Q7.10, Q8.4–Q8.6; [runtime](../docs/decisions.md#decided-project-runtime-2026-11-06), [stack bounds](../docs/decisions.md#decided-2026-11-07-stack-randomness), [concurrency last](../docs/decisions.md#decided-2026-11-07-final-slices). The extension/projection laws are proposed contracts. **Later:** grant-specific events and adapters; concurrency and atomic laws at slice 28, last. Public environment effects are not deterministic merely because input replay is deterministic.

### C7. Secret leakage and accounting

**Freeze:** a separate leakage trace and public-observation relation; public/secret state equivalence; explicit release-site records; byte/resource accounting and their preservation/erasure laws. Leakage means information visible to the baseline timing observer, not ordinary I/O.

**Rule:** record branch choices, exact accessed addresses and the operands relevant to variable-time operations. Include public lengths and the declared effects of external operations. For runs with identical public inputs and matched external choices, secret changes cannot change public observations except through explicit declassification; constant time additionally requires equal leakage under the declared release policy. Declassification records its typed site and reason and releases only the declared value. Preserve wipe events as protected effects that optimization may not erase. Track live/peak backing bytes by allocator lineage, including zero-size ownership without invented bytes; release/reset transitions conserve the specified accounting.

**Authority:** [information flow](../docs/decisions.md#decided-project-infoflow-2026-11-06), [memory/accounting](../docs/decisions.md#decided-project-memory-2026-11-06), Core Q9.10. **Later:** scalar secret rules/proofs at 7, arrays/wipes at 15 and heaps at 19. Binary constant time, hardware timing and actual wiping remain named backend premises until proved; speculative leakage is outside the decided observer model.

### C8. Evaluator adequacy and termination

**Freeze:** both the small-step relation and Q9.9's total fuel-indexed evaluator over instrumented state. Prove evaluator soundness (a reported result has a matching finite execution), completeness (every finite execution is obtained with enough fuel), monotonicity (extra fuel preserves a completed result) and trace-prefix consistency. For nondeterministic effects these statements quantify over the same environment choices.

**Rule:** `outOfFuel` means only insufficient simulation budget. It proves neither divergence nor program failure. Divergence is an infinite execution; a blocked request is separately represented. Termination evidence is a theorem about all allowed runs under its named premises, not the evaluator returning once. Carry per-function termination permissions and evidence dependencies. Resource bounds count specified abstract operations; they are neither elapsed time nor evaluator implementation fuel.

**Authority:** Core Q6.6–Q6.7, Q9.9, [bounded execution](../docs/decisions.md#decided-project-no-hidden-traps), [step bounds](../docs/decisions.md#decided-2026-11-07-step-bounds). **Later:** concrete variants, loop/call cost instances and user proofs. Q9.9 is retained, not replaced by small-step semantics.

**Freeze:** distinct typed identities for declarations/types, functions, binders/places, fields/variants, instances, sites, loans, brands, blocks, grants and obligations; capture-avoiding substitution and renaming laws. Names are presentation only. One primitive-contract interface supplies parameter/result types, authority, ownership/dependencies, pre/postconditions, memory footprint, initialization/validity, failures, events/leakage, resource effects and termination obligations. Every registered primitive supplies a complete contract; there is no catch-all unknown primitive.

Keep safety evidence bound to typed identities, target, contracts and checker/spec versions. Contracts are erased logical assertions; ensures observes the result and surviving parameters after cleanup. Safety admission needs closed evidence; assumptions cannot manufacture it.

## 3. Pipeline and validation contract

Retain the decided stages:

`bytes → lexer → LL(1) parser → AST → resolve → HIR → elaboration → Core → checker → CheckedCore → Mono Core → Place MIR → Memory CFG → SSA → BIR`.

BIR feeds the LLVM printer or the proved BIR→LCB adapter. **Memory CFG stays the single layout/ABI/provenance lowering boundary**; retract P2's folding proposal. Earlier semantics is layout-independent; representation simulations relate it to this boundary.

**Frontend:** retract P1's parse/print criterion. Define byte/token/grammar acceptance independently of the lexer/parser implementation, and source binding, typing and source-to-Core correspondence independently of resolve/elaboration. Prove lexer/parser correspondence to the independent grammar, resolution's binding preservation and elaboration's preservation of meaning, sequencing, cleanup, identities and source sites. Prove checker equivalence to independent admission judgments. Parse/print tests can supplement these proofs but cannot replace them. This retains Core Q8.3/Q9.13 and the decided direct frontend proofs.

Keep direct proofs for sequencing, cleanup, representation and the BIR→LCB adapter. Preserve the decided option of **proved validators for Mono and SSA**, as well as SSA optimizations, register allocation and linking. A validator's acceptance theorem establishes the required correspondence; running a checker without that theorem is not proof. Mono re-admits its output.

**Native closure (P3):** propose a proved AArch64 final-image validator as a 0.1 requirement. Its certificate binds the exact linked image bytes/encodings, relocations, symbol resolution, entry state, launcher and ABI, retained dependencies and target profile to LCB MIR and the instruction semantics. Validate the final image, not just pre-link assembly. Name separately: Lean/kernel and model-translation trust, ISA/hardware correspondence, loader/OS/environment contracts, any unvalidated runtime/foreign code, adequate stack, and backend timing/wipe premises. Until discharged, MIR→machine, assembler/linker/loader and launcher obligations remain explicitly named; an image validator does not prove hardware or OS correctness. This advances an existing later obligation and needs approval.

**Qualification (P4):** run LLVM, LCB and the Lean evaluator on **every supported example and controlled test**, with matched input bytes, grant configuration, external responses and nondeterministic choices. Compare complete observations, not only exit codes: ordered requests/responses/output, terminal classification, trap kind/site/line and observable final external state. Use bounded scripted environments for effectful/blocking cases. Report unsupported or inconclusive runs explicitly; do not count `outOfFuel` as agreement or divergence. Compare leakage separately where the claimed backend evidence supports it. Never require arbitrary user programs to execute three times. Tests qualify implementations; the LCB path is **proved under named premises**, and LLVM remains unverified. Keep the two premise sets separate.
