## Items

### Before slice 1

- **K1. Source provenance through every IR.** Every node in HIR, Core, MIR, CFG, SSA and BIR carries its origin span and a stable ID. Diagnostics, trap-site accounting, debug info and facts depend on this.
  - Placement: identity work (C9 U1-U13 / B0).
- **K2. A textual printer and parser for every IR,** with a round-trip law, so each pass can be tested in isolation.
  - Placement: with the B0 printers (U5/U11).
- **K3. A compiler with no panics.** No panic!, unreachable!, partial def or sorry in compiler code, except entries on an allow-list enforced by a gate.
  - Placement: a PR-tier gate.
- **K5. An optimization architecture, decided early.** The options are verified BIR passes, translation validation, or LLVM on the printer path only. Also decided here: what the LCB path promises about performance.
  - Status: OPEN owner question, after the three-model round, before slice 1 sets passes.
- **K9. A proof-engineering style guide, with a gate.** No large decide terms, pinned simp sets, a proof module per stage, and lemma reuse.
  - Placement: now.
- **K10. An architecture document per stage.** Each states the stage's input invariant, output invariant, linking theorem and trusted pieces, kept in sync by the traceability gate.
  - Placement: now.
- **K12. A versioned stable output schema for facts, diagnostics and CLI JSON.** Extends owner item 16.
  - Placement: identity work.
- **K13. Elm-quality diagnostics** (owner direction):
  - Diagnostics are structured data with one renderer. Each carries a title, a rule ID, a primary span, labelled secondary spans, a plain explanation, and a fix hint only when it is certain.
  - They render as Elm-style text and as JSON.
  - Provenance supplies full spans, related spans across passes, and type-origin tracking.
  - Every rule ID gets an explanation page with a failing example and its fix.
  - A message style guide applies.
  - There are no cascades (owner item 12).
  - A quality gate checks the golden diagnostics (T-f), plus a model-reviewer score against the style guide.
  - Placement: before slice 1, since the lexer and parser are emitting refusals now.

### Later, at their slice

- **K4. Generated-code quality benchmarks.** Runtime and code size of the showcases compared with C at -O2, on both the LCB and LLVM paths, with history on concrete-ci-2.

  - Placement: with the scaling gate's history.

  - Placement: its own slice.
