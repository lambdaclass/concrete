# Frontier Compiler Architecture Research for Concrete

**Scope.** This research series documents six high-leverage compiler-architecture capabilities that solve open problems in mainstream and verified compilers by exploiting invariants **Concrete already enforces**—strict linear ownership, strictly second-class references (no stored or returned references), explicit dual authority (`with(...)` plus linear resource grants), no hidden traps in accepted safe code, executable Lean 4 semantics, and an LLM-authored / audit-first development model ([docs/PHILOSOPHY.md](../../PHILOSOPHY.md)).

Each document grounds its design in the **current Lean architecture on `main`**—specifically the slice-indexed stage-interface carriers in [Concrete/Interfaces/Carriers.lean](../../../Concrete/Interfaces/Carriers.lean) (`MIR`, `Memory`, `SSA`, `BIR`) and [Concrete/Interfaces/Pipeline.lean](../../../Concrete/Interfaces/Pipeline.lean), [Concrete/Interfaces/Contracts.lean](../../../Concrete/Interfaces/Contracts.lean), [Concrete/Contracts.lean](../../../Concrete/Contracts.lean), and [Concrete/Stages.lean](../../../Concrete/Stages.lean) (noting where provisional Slice-0 prototypes in [Concrete/MIR.lean](../../../Concrete/MIR.lean), [Concrete/Memory.lean](../../../Concrete/Memory.lean), and [Concrete/BIR.lean](../../../Concrete/BIR.lean) predate the cutover)—explains **why it works structurally**, states **what (if anything) touches `ConcreteSpec`**, maps each piece to its **exact vertical slice** in [ROADMAP.md](../../../ROADMAP.md), and lists **concrete acceptance gates** and **owner decisions**.

Nothing in this folder decides any open language question or reopens any decided language rule. Every spec-affecting item (notably private layout refinement & compact enum tags under `R-0731`/`R-0502`/`R-0609` and safe open-module boundaries under `R-0734`/`R-0705`) remains explicitly owner-gated until recorded in [docs/decisions.md](../../decisions.md).

## Why Concrete Has an Unfair Structural Advantage

Mainstream systems compilers (LLVM, GCC, `rustc`) and classical verified compilers (CompCert, CakeML) face recurring walls. Concrete's existing language invariants narrow or remove the root cause of each wall (subject to the explicit proof obligations noted in each doc):

| Open Compiler Problem | Why C / C++ / Rust / LLVM / CompCert Hit a Wall | Concrete's Structural Advantage | Research Doc |
|---|---|---|---|
| **UB / `poison` vs. Optimization** | Optimizers rely on `undef`, `poison`, `freeze`, TBAA, and speculative UB assumptions, causing recurring miscompilations (Alive2) or forcing verified compilers to sacrifice speed. | Discharged admission tokens prove overflow/bounds safety with **zero UB**. Shared borrows (`&T`) may still overlap, but `&mut` exclusivity and distinct owned roots provide strong non-aliasing once backed by the C5-to-Memory/BIR exclusivity bridge proof. | [01 — Validated Passes & UB-Free Optimization](01-validated-passes-and-ub-free-opt.md) |
| **Automatic Data-Layout Synthesis** (packing, copy elision, AoS↔SoA) | Data layout drives 5×–50× real-world speedups, but escaping field pointers, `offsetof`, and aliasing make whole-structure layout transforms unsound in C/C++/Rust. | Second-class references never escape or get stored; `Memory` is the single layout authority. Predictable default layouts stay intact while private optimized layouts can be admitted with an exact conversion/refinement proof back to the value model. | [02 — Parametric `LayoutPlan` Synthesis](02-layout-plan-synthesis.md) |
| **Phase Ordering & Proof-Effort Coupling** (isel / regalloc / scheduling / LLM rewrites) | Instruction selection, scheduling, and register allocation are jointly NP-hard; proving clever heuristics in Lean is brittle and expensive. | Separate **untrusted search** (CP-SAT/ILP solvers, e-graphs, MAP-Elites, LLMs) from **kernel-verified Lean validators** checking three separate obligations: per-function refinement, exact trap-site provenance, and resource non-regression. | [03 — Joint Solvers & Verified LLM Optimization](03-joint-solver-and-llm-verified-opt.md) |
| **Cost-Preserving Compilation** (WCET, stack, allocation budgets) | Verified compilers prove functional equivalence only; optimizations and backend lowering silently alter stack/step/memory bounds. | No hidden runtime, explicit allocators, mandatory `#[variant]` bounds, and `CheckpointSimulation` let us add real, non-vacuous cost preservation once loop/call step models exist (Slices 4–5 and `LP0`+, not a vacuous `Unit` hook in Slice 0). | [04 — Cost-Preserving & Compositional Compilation](04-cost-preserving-and-compositional.md) |
| **Compositional Verified Compilation & Linking** | Shared aliased heaps and re-entrant callbacks across module/FFI boundaries make open-module verification (CompCertO / DimSum) notoriously complex. | Safe Concrete module boundaries carry only values, scoped borrows, and explicit linear grants (settled at Slice 8 before `A2c`; re-entrant or retaining FFI stays separately owner-gated). | [04 — Cost-Preserving & Compositional Compilation](04-cost-preserving-and-compositional.md) |
| **Compile-Time & Proof-Brittleness Scaling** | Small body edits trigger cascading re-typechecking, re-monomorphization, and brittle proof re-runs; human review of large LLM diffs does not scale. | Rule 13 (semantic identity over spellings), LL(1) grammar, no hidden globals, and explicit per-function contracts enable canonical bodyless `InterfaceSummary` hashing (`QueryDB`) and semantic-delta `concrete diff` starting at Slice 8. | [05 — Semantic `QueryDB` & Audit Diffing](05-semantic-query-db-and-audit-diff.md) |

## Cutover Scope vs. Later Architectural Upgrades

Per Codex's cutover review, **only two minimal interface changes belong in the stage-interfaces cutover**; everything else lands at its natural later slice so Slice 0 stays lean and never carries vacuous parameters or undoes closed-semantics work:

### In the Cutover's Single Interface Change
1. **Closed pass slots at each IR level** (`MIR`, `Memory`, `SSA`, `BIR`) in [Concrete/Interfaces/Pipeline.lean](../../../Concrete/Interfaces/Pipeline.lean), where proved passes can be registered; **Slice 0's pass lists stay empty** ([doc 01](01-validated-passes-and-ub-free-opt.md#1-pluggable-validatedpass-slots-in-interfacespipeline)).
2. **Split provenance rule** in [Concrete/Interfaces/Contracts.lean](../../../Concrete/Interfaces/Contracts.lean): plain lowering keeps exact coverage (`PreservesOrigins`), while optimizing passes get a separate rule that accounts for every removed/discharged value AND pins every runtime trap to its exact original site ([doc 01](01-validated-passes-and-ub-free-opt.md#2-fixing-preservesorigins-before-optimizations-land)).

### Deferred to Their Natural Later Slices (NOT in the Cutover)
3. **Pass-carried `FactTable` side-channel** across `Core → MIR → Memory → SSA → BIR` (Slice 3+ when octagon/purity facts exist; [doc 01](01-validated-passes-and-ub-free-opt.md#3-first-class-facttable-carrier-through-bir)).
4. **Parametric `LayoutPlan` + private-layout refinement** in `Memory` (Slice 6+, after owner decisions on private layout conversion proofs and compact enum tags; [doc 02](02-layout-plan-synthesis.md#2-architecture-layoutpolicy--layoutplan--parametric-lowering)).
5. **Typed `OptimizationProposal` / `ObligationBundle` wire protocol + multi-obligation BIR/LCB validators** (Slice 0/1 BIR validator skeleton, Slice 3+ `concrete verify-opt`, post-`LP0` joint backend solver; [doc 03](03-joint-solver-and-llm-verified-opt.md#2-the-proposal--validator-boundary)).
6. **Non-vacuous cost preservation & safe open-module `InteractionSemantics`** (cost preservation at Slices 4–5 / `LP0`+—not a vacuous no-cost parameter in Slice 0; safe open-module boundary at Slice 8 before `A2c`, without undoing the cutover's closed `Semantics`; [doc 04](04-cost-preserving-and-compositional.md#1-cost-preserving-compilation)).
7. **Bodyless `InterfaceSummary` + content-addressed `QueryDB`** (Slice 8 generated interfaces `R-0556`, Slice 10 `R-0201`, Phase G `R-0149`; [doc 05](05-semantic-query-db-and-audit-diff.md#1-bodyless-interfacesummary-and-two-level-merkle-identity)).

## Sequencing Advice: Cutover vs. Later Slices

Following the [slice ordering rule](../../../ROADMAP.md#slice-ordering), Codex's cutover review, and the owner's cap of at most two stages in parallel:

1. **In the cutover's single interface change (minimal, zero vacuous hooks):**
   - `R-0730` cutover interface: closed per-IR pass slots (`MIR`, `Memory`, `SSA`, `BIR`) with **Slice 0's pass lists empty**, plus splitting `PreservesOrigins` so plain lowering retains exact coverage while optimizing passes use an elimination-accounting + exact-trap-site rule.
   - Do **not** add a `Unit`-defaulted cost parameter or open-environment parameter during the cutover (a parameter that defaults to "no cost" bounds nothing, and an open-environment parameter would undo closed-semantics work done by the cutover).
2. **Stage 0 (`B0b`) day-one foundations (non-blocking for `B0a`):**
   - `R-0732` BIR validator v1 (checking separate functional, trap-site, and resource obligations), `R-0736` (round-trip IR text format over the current `Interfaces` carriers), `R-0737` (`IdTable` + `ProofLib`), `R-0738` (`concrete reduce`), `R-0739` (early 0.1-grammar kernel sketches), `R-0740` (Trust & Speed Scorecard), `R-0741` (synthetic 32-bit/big-endian `TargetProfile` checks), and `R-0742` (`concrete inspect` IR view).
3. **Pre-freeze owner decisions (Batch 2, before Slices 6–11 / `A2c`):**
   - **Layout (`R-0731`, before Slice 6):** keep the current predictable default layouts, allow private optimized layouts only with a proof they convert back exactly to the spec's value model, and decide compact/niche enum tags separately.
   - **Open modules (`R-0734`, Slice 8 before `A2c`):** settle the call boundary for safe Concrete modules before Core freezes; re-entrant or retaining FFI requires separate owner approval.
4. **High-payoff feature landings at their natural slices:**
   - **Slice 3:** `FactTable` carrier + UB-free mid-end optimizer (`R-0730` + `R-0711`) and per-function `concrete verify-opt` (`R-0732`).
   - **Slices 4–5 + `LP0`:** non-vacuous cost-preserving step/stack/alloc bounds (`R-0733`), `concrete inspect --asm` (`R-0742`), and post-`LP0` joint backend solver + LCB validator (`R-0732`).
   - **Slices 6–7 & 13:** private `LayoutPlan` packing, copy elision, and AoS↔SoA (`R-0731`).
   - **Slices 8–11:** `InterfaceSummary` + `QueryDB` (`R-0735`), `concrete diff` (`R-0201`), and safe open-module composition (`R-0734` / `R-0705`).
