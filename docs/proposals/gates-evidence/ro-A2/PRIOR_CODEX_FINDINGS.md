1. **P1 — Coverage guards count generated programs, not compared programs.** `scripts/checks/compiler/spec_diff.sh:266–297` stops comparisons at the deadline and permits success after eight BIR programs. The trap and production guards at lines 247–255 inspect the entire generated corpus, so the judged prefix can omit traps, widening, chains, or other productions. Once `compileCore` is filled, comparing just one compiled spec program also suffices. **Fix:** track outcomes and constructs among fully judged programs; require their coverage and minimum counts independently for each active leg. Return INCOMPLETE when the required comparisons remain unfinished.

2. **P2 — Overflow and off-by-one controls accept arbitrary mismatches as the planted reason.** `scripts/checks/compiler/spec_diff.sh:145–165` prints the expected failure marker whenever `judge` rejects the observation. For example, a mutated executable crashing with status 139 satisfies these checks; the evaluator returning `"incomplete"` also counts as catching off-by-one. The grep checks a marker manufactured after any mismatch, rather than evidence of the specified mutation. **Fix:** first require the unmutated candidate to match, then assert the precise mutated observation: overflow removal must produce its calculated non-trap result; off-by-one must produce exactly the incremented encoded result in both legs. Treat incomplete observations and unrelated failures as control setup failures.

3. **P2 — `SPEC_DIFF_SECS` does not bound the shared run.** `scripts/checks/compiler/spec_diff.sh:199–210` and `:259–264` run controls with fixed 120/300-second budgets regardless of the remaining deadline. Furthermore, `bounded` retries with twice its supplied budget, so even the build and generation calls given the remaining time can consume approximately three times that remainder. **Fix:** enforce one absolute deadline around the whole gate, including retries and controls, and report INCOMPLETE when it expires.

4. **P2 — Failing seeds are printed but never saved as regressions.** `scripts/checks/compiler/spec_diff.sh:80–100` emits instructions for manually adding a regression. The shared EXIT trap deletes all generated artifacts, and the new CI job has no failure-artifact upload. This does not implement the approved requirement that failing seeds be saved as regression tests. **Fix:** persist a regression bundle containing the seed, index, leg, generated program, expectations, and observations outside temporary cleanup; upload it on CI failure and provide a durable regression replay mechanism.

5. **P2 — The spec production table mislabels generated syntax.** `Concrete/SpecDiffSpecGen.lean:49–59` handles `.letLiteral` through the fallback that emits an addition. It nevertheless records that production as `let_literal`. Return-production weights at lines 27–29 are also unused: return selection comes from the statement-count draw at lines 64–73.
