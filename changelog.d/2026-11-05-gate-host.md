### Landing: impact gates on the gate host

`train.sh check` runs its impact leg on the gate host (`LAND_GATES_HOST` or `git config
land.gatesHost`, normally concrete-ci-2) through `scripts/land/gates_remote.sh`. It bundles
base..head and runs `run-at-ref.sh` over ssh. The result counts only when the host's log names the
train head's SHA. A run at another SHA, an unreachable host or a lost log is INCOMPLETE and blocks.
Running locally requires the explicit `check --local-gates`. A pass is attested in the train
worktree's git directory. The pre-push hook reuses it at the `ci` push only for that exact commit,
pushed refs, committed gate definitions, selection, changed files, seed and `CONCRETE_*`
environment. In any other case the hook runs the gates itself. Tests are in
`check_landing_script.sh`.
