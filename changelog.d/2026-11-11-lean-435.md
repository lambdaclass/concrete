### Lean 4.35.0 and external checker toolchains

Concrete now uses Lean 4.35.0 throughout its active build, Nix release archives and CI.
The pinned lean-compiler-backend sources build unchanged as a dependency under 4.35.0;
that upstream revision's standalone declaration remains 4.34.1. No proof or definition
changed. The axiom inventory gained twelve compiler-generated Boolean-reflection helpers
for existing Surface0 decidability instances, each with an empty axiom set.

External Lean tools are checked against their revision's declared toolchain on every run,
including cache hits, and built with explicit elan dispatch. The exporter is pinned to
upstream v4.35.0 and must match Concrete. Elan installations are isolated under the
external cache only for pinned tool builds, so Nix's Linux patching cannot modify shared
user toolchains. Project builds and queries retain the caller’s ELAN_HOME.
Ambient ELAN_TOOLCHAIN and LEAN_PATH are cleared. The opt-in extcheck
shell provides Rust and an explicit elan path without Lean/Lake proxy shims on PATH.
CI keys the tools cache on both flake files as well as pins, builder and toolchain.
The required root regression gate runs the production driver with local sources and executable stubs, checking cache reuse,
cache corruption, pin mismatches, ambient Lake isolation, cleared overrides and
elan-home isolation. It checks the actual extcheck PATH and rejects simulated proxy leaks,
global home redirection and unscoped tool builds. Incomplete bounded runs report through
the bounded-gate status path.

External cache homes and Lake tool trees distinguish resolved elan path/version; nanoda
trees distinguish resolved cargo/rustc paths and `rustc -vV`. All tool trees also include the complete recipe hash, including the nanoda stack patch. The
regression fixture exercises population and exporter calls after unlocking, and rejects
a late home export and locking before project preparation.

ISS-0057 and ISS-0058 are closed: the distinct con-leche fixture refuses all three
project-toolchain dispatch substitutions, Rust cache controls cover each identity component,
and runner documentation matches the keys. Repository-making recipes call the sandbox
helper themselves; every call clears inherited Git variables and refuses a conflicting configuration.

The external-tool cache also retains per-revision `source-nanoda-<rev>` checkouts and
builder-keyed `registry-<identity>` Cargo downloads. Completed nanoda cache hits work
offline. Cargo uses an allowlisted environment and private Cargo home, ignoring caller
wrappers and profile/target overrides; `--locked` enforces Cargo.lock. Builds run outside
HOME and refuse ancestor Cargo configuration. See the isolation contract in
[`scripts/proofs/external.sh`](scripts/proofs/external.sh).
