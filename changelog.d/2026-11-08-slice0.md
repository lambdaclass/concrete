### Slice 0: the proof spine through two native backends (2026-11-08)

`Concrete/` holds the slice-0 compiler (PROVISIONAL, ROADMAP B0; `Concrete/README.md` is its
design and gate list). The hand-written BIR examples run through the LLVM path and the LCB path
(`Concrete/Backend/`), and each executable's observation is compared with the BIR semantics on
x86-64 Linux and AArch64 macOS (`.github/workflows/slice0.yml`). The BIR → LCB-IR adapter is
proved against LCB's own semantics, and the backend contract is complete: `LCB.emit`
represents adaptation failure, `Proof.emit_correct`, `Proof.artifact_of_emit_error` and
`Proof.artifact_correct` state that a refusal produces no artifact and every artifact comes from a
correct `emit`, so `P_adapter` is retired. The premises live in one registry
(`Concrete/Premises.lean`); the trusted-base gate compares it, the headline theorems' axioms, the
toolchain and the Lake pins with `tests/golden/slice0_trusted_base.txt`, on both platforms.
The artifact gates add ASan (UBSan dropped by the owner: on IR input it checks nothing),
report-only binary size and compile time, and a stack bound derived from the linked executable's
disassembly, fail closed (`scripts/checks/lib/stack_bound.py`), checked by single-stepping a run
under gdb (x86-64 Linux) or LLDB (aarch64-macos). The run check counts every stack byte a stepped
instruction addresses, not only the stack pointer, so red-zone use is measured; the analysis
refuses an access deeper than the target's red zone (128 bytes on x86-64 System V and Apple
arm64, none under AAPCS64 on Linux), and a linked control that stores at the red zone's edge must
be measured at 128 bytes. Reproducibility is checked across build directories and machines. Every
gate run is bounded by `bounded_run`; a twice-timed-out run is INCOMPLETE, never a pass.
